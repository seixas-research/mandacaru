# A first calculation

This page runs one small molecule with the ASE calculator and then with the
command line. It needs only the installation ([Installation](../installation.md));
the `HAO` basis used here is generated by the program and reads no data files.

## With ASE

`Mandacaru` is an ASE calculator. Attach it to an `Atoms` object and ask for the
energy:

```python
from ase import Atoms
from mandacaru import Mandacaru

atoms = Atoms("H2", positions=[[2.5, 2.5, 2.13], [2.5, 2.5, 2.87]], cell=[5, 5, 5])
atoms.calc = Mandacaru(method="rhf", basis="HAO", grid_spacing=0.35)

energy = atoms.get_potential_energy()      # eV, including nuclear repulsion
print(f"E = {energy:.4f} eV")
print(atoms.calc.result.success)           # did the SCF converge?
atoms.calc.close()
```

What happens when you ask for the energy:

1. The molecule is sampled on a uniform real-space grid whose spacing is
   `grid_spacing` (Å). The grid is built from the geometry and the cell, so give
   the molecule a cell with vacuum around it, enough for the tails of its orbitals.
2. The basis functions, integrals and the self-consistent field run in the Rust
   engine, in Hartree atomic units. Python converts at the edge: ASE energies are
   in eV, forces in eV/Å.
3. If the SCF does not converge the calculator raises `RuntimeError`; nothing is
   silently substituted.

`method` selects the calculation: `"rhf"`, `"uhf"`, `"ghf"`, `"dft"` (with
`xc="lda"`, `"pbe"`, …), or a quantum algorithm such as `"vqe"` and
`"adapt-vqe"`. The default is `"adapt-vqe"`, so a bare `Mandacaru()` runs a
variational quantum simulation, not Hartree–Fock. The [methods
table](#methods-table) lists every method and what each supports, and the
[options reference](#options-reference) lists every keyword.

## The result object

`calc.run(atoms)` returns the result directly, and `calc.result` keeps the last
one. A context manager closes the calculator, which releases its native memory
and scratch directory:

```python
with Mandacaru(method="dft", xc="pbe", basis="HAO", grid_spacing=0.35,
               resources={"threads": 2, "memory_limit_bytes": 512 * 1024**2}) as calc:
    result = calc.run(atoms)
    print(result.in_units("Ha"), result.in_units("eV"), result.success)
    print(result.num_particles)            # (n_alpha, n_beta)
```

The memory limit covers the native buffers of the calculation; exceeding it
raises `MemoryError` ([Native calculations](../guide/native_engine.md)). Forces and
geometry optimization are in [Forces and relaxation](../guide/forces_relaxation.md);
use a PAW-LCAO basis for those.

## From the command line

The `mandacaru` script runs one calculation on a geometry file and prints a
JSON report. Write a file first (any format ASE reads works; keep the cell in
it, because the grid is built from the cell):

```python
from ase.io import write

write("h2.extxyz", atoms)
```

```console
$ mandacaru h2.extxyz --method rhf --basis HAO --grid-spacing 0.35
```

The report has the keys `energy_ev`, `converged` and `method`, plus
`forces_ev_per_angstrom` with `--forces`. `--output FILE` also writes the report
to a file. The other options are `--xc`, `--threads`, `--memory-mb` and the
`--load-hamiltonian`, `--save-hamiltonian` and `--load-crystal` file options;
`mandacaru --help` lists them. The command takes a geometry file or a JSON
geometry, not a molecule name, and it has no dry-run flag; to count qubits
without computing anything use [`estimate_qubits`](../guide/dry_run.md).
