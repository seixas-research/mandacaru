# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Mandacaru** is a framework for fermionic quantum simulation based on variational quantum algorithms (VQAs), targeting real NISQ-era quantum hardware (IBM Quantum via Qiskit). The intended end-to-end pipeline is: fermionic system → second-quantized Hamiltonian → qubit (Pauli) Hamiltonian → parameterized ansatz → VQA optimization → QPU/simulator execution → error mitigation. The flagship algorithm is **ADAPT-VQE** with pluggable operator pools (fermionic / qubit / QEB / CEO), plus its **excited-state** extensions (deflation / subspace-search).

**Important:** the project is mid-build. Implemented end-to-end: localized bases (FAO / NAO / NAO-AE / STO-nG / Pople / named Gaussian families), **a periodic plane-wave basis** and the **pseudopotential families NCPP / ONCVPSP / PAW / UPAW** (selected as a basis *name*, `basis="PAW"`; package `mandacaru.pseudopotentials`, stable since 2026-09-15) → real-space (reciprocal-space for PW) integral engine → second-quantized `Fermion` Hamiltonian → fermion-to-qubit mappings → **UCCSD → VQE** and **ADAPT-VQE** (both exact state-vector solvers, validated on H₂), with **RHF/UHF** for the molecular-orbital basis. Also: **excited states** (`energy_levels` by deflation, `SubspaceVQE`/`SubspaceADAPTVQE` by subspace search), the periodic **`BlochCalculator`** (bands + BvK total energy), **QPE**, **checkpoints**, **forces and relaxation**, and **volumetric output**. All solvers share the **`VariationalDriver`** base (`algorithms/base.py`), with the excited-state methods as composable mixins. **Not written at all: error mitigation** — there is no `backends/mitigation.py` and no `plan/` directory (both were named here for a long time; neither exists). Before building on a module, check that it exists and has code (`wc -l`). `pyproject.toml` is the source of truth for the build (Python ≥ 3.14).

**The single user-facing entry point is `Mandacaru(method=..., ...)`** (`algorithms/calculator.py`; also `from mandacaru import Mandacaru`) — an ASE calculator selecting the solver by the `method` string. `"adapt-vqe"` is **the default everywhere**, including `BlochCalculator`; `STABLE_METHODS` = `"vqe"`, `"adapt-vqe"`, `"subspace-vqe"`, `"subspace-adapt-vqe"`, and anything else must be added with `register_method(name, cls)` — the `mandacaru.experimental` package registers its own solvers when *explicitly* imported, and the stable code, docs, README, examples and website never name them (a sweep under `test/experimental/` enforces it). It forwards every solver option and exposes the result uniformly on `.result` (plus `.solver`/`.hamiltonian`/`.n_qubits`/`.num_particles`, direct-mode `run()`, `energy_levels()`). **The algorithms are called solely through `Mandacaru` — no exceptions (user mandate, re-issued 2026-09-19).** `VQE`, `ADAPTVQE`, `SubspaceVQE`, `SubspaceADAPTVQE` are the internal layer: **not exported** from `mandacaru.algorithms`, and no test, example or doc page may import or construct one — `test/test_single_entry_point.py` sweeps the repository and fails if one does. Direct (no-geometry) problems go through the calculator too: `Mandacaru(method="adapt-vqe", hamiltonian=H, pool=..., num_particles=..., n_spatial_orbitals=...).run()`. To make that a complete replacement, `Mandacaru` **validates its options in the constructor** (building the solver once with its dry-run switch on, which runs every constructor check and configures nothing — plus `_check_shots_for_hardware`, the one check a dry run waives) and builds the real solver **on first use** (`calc.solver` is a lazy property; every geometry evaluation replaces it). So an invalid *option* is refused by the constructor and an invalid *problem* (non-Hermitian operator, qubit-count mismatch) where the problem is built. It **delegates unknown attributes to the solver** (`calc.pool`, `calc.ansatz`, `calc.kpoints`, `calc.energy_at`…); writes and monkeypatches that must land on the solver use `calc.solver`. `method` is spelling-insensitive (`_method_key`: `"adapt-vqe"` = `"adaptvqe"` = `"ADAPT_VQE"`), and `resolve_method` is the one place the solver classes are imported from. **Never reach for a solver class in a test or example — if `Mandacaru` cannot express what is needed, extend `Mandacaru`.**

## Current state of the code

Implemented:
- `src/mandacaru/basis/` — localized basis functions (`BasisFunction` ABC) and three families: `FullAtomicOrbital` (analytic, Slater charges), `NumericalAtomicOrbital` (confined Sankey/SIESTA-type, `nao.py`), `GaussianOrbital` (contracted GTOs, `gaussian.py`). **All generated natively from scratch — no tabulated/external basis-set data.** The `BasisSet` factory builds `"FAO"` (one analytic orbital per occupied subshell carrying the **actual Z** — the bare hydrogenic orbital, no Slater screening; `{"name": "FAO", "virtual_orbitals": k}` appends the `k` lowest *unoccupied* subshells), `"STO-3G"`, `"NAO"`, `"GTO"`, `"6-31G"`/`"6-31G(d)"`. GTO is a minimal **STO-nG** basis (`sto_ng.py`): least-squares fit of `n_gaussians` primitives to each occupied subshell's Slater orbital (Slater's rules ζ = (Z−S)/n\*), the reference fit done once at ζ=1 (cached, `_fit_reference`) and rescaled by ζ²; it reproduces published STO-nG exponents closely (H 1s → 2.22766/0.40577/0.10982). The **Pople split-valence** family (`pople.py`) reuses that fit for 6-31G(d). Aufbau config in `_config.py`, angular helpers in `_angular.py`. **`_config.valence_subshells` returns the highest-`n` occupied subshells plus the semicore `(n-1)d` / `(n-2)f`** when occupied, so Fe is `3d⁶4s²` (8 valence electrons), not a 2-electron `4s²` atom — this feeds both the basis and pseudopotential generation.
- `src/mandacaru/basis/gaussian_families.py` — **named Gaussian families** (`BasisSet.build("cc-pVTZ" | "6-311+G(2df,2p)" | "def2-TZVP" | "STO-4G" …)`): `parse_basis_name` → a `GaussianRecipe` (contraction *patterns*, polarization `(l,count)`, diffuse lists, tight functions, `polarization_min_z`=11 for `3-21G*`), and `gaussian_shells(Z, recipe)` generates `(l, exps, coeffs)` natively — each `(n,l)` shell is one `_fit_reference` fit of `sum(pattern)` Gaussians partitioned tightest-first (`(3,1)` = 6-31G, `(3,1,1)` = 6-311G), polarization `f_l·ζ_val²` (`6-31G*` reproduces `pople_631g_shells` exactly), diffuse = most diffuse exponent of that `l` / `DIFFUSE_RATIO` 3.5, tight = tightest valence × 3. Function counts match the published shell notation (`cc-pVTZ` C `[4s3p2d1f]`, spherical); the exponents are Mandacaru's own. **`MAX_CONTRACTION = 10`**: the fit is numerically singular past ~10 primitives, so `_projected_overlap` rejects ill-conditioned trials (cond > 1e12, overlap > 1) and `_fit_reference` raises instead of returning garbage. `NAMED_BASIS_SETS` lists the 40 validated names (`test/test_gaussian_families.py`); `6-31G`/`6-31G(d)`/`6-31G*`/`STO-nG` still route to `Pople631GBasisSet`/`GTOBasisSet`.
- `src/mandacaru/basis/multizeta.py` — **multiple-zeta and polarized NAOs** (`BasisSet.build("NAO", size=…)` or the basis dict, through which every `NAOBasisSet` option passes). `ZETA_NAMES` covers `SZ`…`QZ2P` (or an explicit `(n_zeta, n_polarization)`); **`DEFAULT_NAO_SIZE = "DZP"`** — `size="SZ"` is opt-in and keeps the original `NumericalAtomicOrbital` path byte-for-byte. Extra zetas are split-valence (`split_radius`/`split_valence_tail`; GPAW vs SIESTA schemes in the 2026-09-20 section), each strictly shorter-ranged than the last (H 1s: 3.99 → 2.09 → 1.22 → 0.81 a₀); polarization adds a whole `l_max+1` shell in the same confining sphere. All become `TabulatedOrbital` (`R(r)·Y_lm` off a spline), so the engine sees them identically. **Caveat:** high zetas are short-ranged and the grid must resolve them — the 3rd H zeta spans 0.65 Å ≈ 3 points at `h=0.20` and contributes ~1e-6 Ha. DZP is the sweet spot.
- `src/mandacaru/integrals/` — real-space one-/two-body integral engine, grid, FFT Poisson solver, C backend binding.
- `src/mandacaru/core/` — the second-quantized layer. `mapping.py`: `Fermion` (ladder operators with full algebra and `from_integrals` for `H = Σ h_pq a†_p a_q + ½ Σ ⟨pq|rs⟩ a†_p a†_q a_s a_r`), `PauliSum` (the qubit output type, `to_sparse_pauli_op`), and the four mappings — **Jordan-Wigner** (default), **parity**, **parity-reduced**, **Bravyi-Kitaev** — from a shared encoding-matrix construction (`map_to_qubits(method=…)`). `hamiltonian.py`: `MolecularIntegrals`. `planewave.py`: `PlaneWaveIntegrals`, a **periodic plane-wave basis** (`{"name":"PW","energy_cutoff":300}` eV) with PBC reciprocal-space integrals (diagonal kinetic `½|G|²`, structure-factor external potential, momentum-conserving `4π/Ω/|G_p−G_r|²` repulsion, G=0 removed by jellium), mirroring the `MolecularIntegrals` interface. It guards an intractable O(N⁴) tensor with `max_plane_waves` (default 60) — a realistic cutoff on a molecule-sized cell gives far too many plane waves for exact state-vector VQE.
- `src/mandacaru/circuits/` — `base.py` (the **`Ansatz` protocol**: `num_parameters`/`n_qubits`/`reference_state`/`state(θ)`/`evolve(θ, references)`, satisfied structurally so a new ansatz drops in with no driver change; plus the optional `SerializableAnsatz`), `gates.py` (anti-Hermitian excitation generators), `ansatz.py` (`UCCSD`; the default is the exact UCC exponential, `trotter=True` the circuit-faithful product), `adapt_ansatz.py` (the growable `AdaptAnsatz`, `append`/`remove`), `pools.py` (the pools behind a common `PoolBase`/`PoolOperator` interface and a `build_pool` registry) and `profiling.py` (`CircuitMetrics`/`profile_ansatz` — compile to a native `{cx,u}` set for CNOT/depth). Imported from `mandacaru.circuits`, their canonical home — not re-exported through `mandacaru.algorithms`.
- `src/mandacaru/optimizers/optim.py` — `Optimizer`, a classical-optimizer wrapper with cost-history tracking and a **step count** (`OptimizeResult.nit`, see the optimizer section). Nine named methods (`NAMED_OPTIMIZERS`): **SPSA**, **COBYLA**, **Nelder-Mead**, **SLSQP** (`DEFAULT_OPTIMIZER`), **Adam**, **L-BFGS-B**, **BFGS**, **L-BFGS**, **NLCG-PR**. Seven dispatch to `scipy.optimize.minimize`; **SPSA** and **Adam** are native (SPSA = two-eval Spall stochastic gradient plus one to keep the best iterate, `options={"track_best": False}` for the strict form, convergence claimed only after `patience` = 5 consecutive steps under `tol`; Adam = finite-difference-gradient adaptive moments).
- `src/mandacaru/algorithms/base.py` — **`VariationalDriver`**, the shared ASE-`Calculator` base. It owns the **problem-setup surface** (`basis`/`grid`/`h`/`kpts`/`spin`/`initial_state`/`charge`/`n_electrons`/`frozen_core`/`frozen_orbitals`/`hamiltonian_builder`/`optimizer`/`device`/`run_options`/`sparse`), the ASE `calculate()` hook (geometry→Hamiltonian per call; reused in direct mode), the **state-vector backend** (`_materialize_hamiltonian`, `_as_pauli_sum`, `_resolve_sparse`, and the canonical **`energy(psi)`**), the Γ-point k-guard, the timings/banner scaffolding and `format_pauli_sum`. Subclasses implement only `_configure(hamiltonian, num_particles, n_orbitals)` and `run()`. Excited-state **methods are mixins**: **`DeflationMixin`** supplies `energy_levels(...)` once (with a per-driver `_deflated_ground` hook), **`SubspaceMixin`** the SSVQE `run()` scaffolding (`_reference_occupied`/`_subspace_optimize`/`_make_subspace_result`; the result always lands on `.result`). So `VQE(DeflationMixin, VariationalDriver)`, `ADAPTVQE(DeflationMixin, VariationalDriver)`, `SubspaceVQE(SubspaceMixin, VQE)`, `SubspaceADAPTVQE(SubspaceMixin, ADAPTVQE)` — a new method plugs in without re-implementing setup. (`VQE.energy_at(θ)` is the parameter-space cost; `energy(psi)` the state-vector expectation.)
- `src/mandacaru/algorithms/vqe.py` — `VQE`, an exact state-vector eigensolver; validated on H₂ against exact diagonalization to ~1e-9 Ha. `VQE`/`VQEResult` mirror `ADAPTVQE`/`ADAPTVQEResult` (`optimizer` takes a name or an `Optimizer`; `VQEResult` exposes `num_parameters`/`energy_history`/`correlation_energy`). Both drivers have **`energy_levels(num_states=2, ...)`** — **excited states** by variational quantum deflation: each level minimizes `⟨H⟩ + β·Σⱼ|⟨ψⱼ|ψ⟩|²` over the levels already found (auto `β` from the Hamiltonian's 1-norm; `DeflationMixin`/`EnergyLevels` in `algorithms/deflation.py`), returning an `EnergyLevels` (ascending Hartree energies, `excitation_energies`, `in_units("eV")`, stored states; ADAPT re-grows a fresh deflated ansatz per level). Reported energies are the bare `⟨H⟩` (the penalty vanishes at the eigenstate), so every level is a true eigenvalue of H — limited to the sector the ansatz reaches from its HF reference (**ADAPT's greedy screening hits Brillouin's zero-gradient wall for singles**, so on H₂ it reaches the seniority-zero partner while UCCSD-VQE also reaches a singly-excited level). `algorithms/subspace.py` adds **`SubspaceVQE`** / **`SubspaceADAPTVQE`** (`SubspaceMixin` over each) — **SSVQE**: `num_states` orthogonal reference determinants (`subspace_determinants`/`reference_matrix`) through one shared `U(θ)`, minimizing `Σⱼ wⱼ⟨φⱼ|U†HU|φⱼ⟩` (strictly decreasing `weights`, default `(k,…,1)`; `SubspaceADAPTVQE` screens on the weighted per-reference sum). This is why the ansatz protocol has **`evolve(θ, references)`** (a `(2ⁿ,k)` stack). Results carry ascending `energies`, orthonormal `states`, `weights`, `optimal_energy`=ground, `excitation_energies`, `.levels`; spectrum on `.result`, ASE energy = ground. Levels are variational **upper bounds** (Hylleraas–Undheim `Eᵢ ≥ λᵢ`): the ground is exact from the HF start, excited-state tightness tracks expressivity. The geometry→Hamiltonian build is shared by both drivers in `algorithms/_hamiltonian_from_atoms.py`; `resolve_optimizer` lives in `optimizers/optim.py`.
- **Profiling** (`utils/profiling.py`) — `Timings` accumulates named stage wall-times plus the OpenMP core count and peak RSS (`peak_memory_mb` via `resource.getrusage`, `cpu_count()`, `current_memory_mb()`). The C backend reports its threads through `mandacaru_num_threads()` → `_backend.num_threads()`. `IntegralEngine` times its one-/two-body stages (`integration_profile()`); the drivers time optimization / screening / profiling, print a "Timings / Resources" block in the verbose summary and expose `result.timings` / `result.integration_profile`.
- `src/mandacaru/algorithms/adapt_vqe.py` — `ADAPTVQE`, the adaptive grow-then-reoptimize loop (gradient `⟨ψ|[H,A_i]|ψ⟩` over a pool, warm-started inner VQE) on the state-vector backend, using `AdaptAnsatz` (dense eigendecomposition, or a **sparse closed-form** backend for large active spaces) and Qiskit circuit profiling. All pools reach FCI on H₂. Examples 01-06. Operator selection is the pluggable hook **`_select_operator(grads, iteration)`** (default `argmax|g|`), used by `run()`, `_grow_deflated` and the subspace grow, so a subclass changes *which* operator grows the ansatz without touching convergence (`max|g| < tol`, computed independently of the selection). What is appended goes through **`_grow(ansatz, selected, op, gradient)`** → `pool.grown_operators(...)`, which is one operator for every pool but `ceo`.
- `src/mandacaru/algorithms/hartree_fock.py` — `RHF` (closed-shell SCF; supplies the **molecular-orbital basis**, so ADAPT's HF reference is stationary and singles have zero gradient) and `UHF` (`run()` → energy for isolated-atom references; `solve()` → `UHFResult` with both spin-orbital sets, the **natural orbitals** of `D_α+D_β` (occupation-ordered), `h_mo`/`eri_mo` in that basis, `reference_energy` and `spin_contamination`). **Open shells (2026-09-09):** `molecular_hamiltonian(mo_basis=True, n_electrons, num_particles=(nα,nβ), open_shell=None)` uses RHF for even counts and the **UHF natural-orbital basis** for odd ones (or `open_shell=True`) — one spatial basis for both spins, so the α/β-block form and everything downstream (pools, ansätze, mappings, frozen core, dry run) is unchanged; the NO reference is not stationary, so ADAPT also selects singles (fine). `resolve_num_unpaired` makes an odd count a doublet by default (`spin` is only a compatibility flag; magmoms select quartets), `_num_particles` checks parity instead of refusing odd counts, `resolve_frozen_core(..., n_doubly=n_beta)` freezes only doubly occupied NOs; **PW still refuses odd counts** (RHF-only). `adapt_vqe._max_abs` treats an **empty pool** (H atom: 1 electron, 1 orbital) as converged instead of crashing on `max([])`. `test/test_open_shell.py` (H, H₃ doublet/quartet, Li frozen core, H₂⁺, OH dry run; ADAPT/VQE reach the sector FCI from `_sector_ground_state`).
- `src/mandacaru/algorithms/bloch.py` — the **general (1-/2-/3-D) periodic driver `BlochCalculator`**, its solver selected by `method="adapt-vqe"` (default) / `"vqe"` like `Mandacaru`. Takes an ASE *primitive cell* (`atoms.cell`/`atoms.pbc` define the lattice and the periodic directions). `bands(kpts)`/`band_structure(path)` solve the single-particle **Bloch problem** `H(k)c = ε(k)S(k)c`: the cell-to-cell blocks `S^{(R)}`, `h^{(R)}` come from the FAO real-space integrals over a lattice window and the phase is the dimension-general `exp(2πi k·n)`, so **the bands are identical across methods**. `total_energy(kmesh, **solver_kwargs)` gives the energy per cell using all k-points via the **Born–von Kármán equivalence** (an `(n1,n2,n3)` mesh ≡ Γ-point on that supercell): `atoms.repeat`, run through a molecular `Mandacaru(method=self.method, …)`, returning `(E(supercell)/n_cells, result)` — a finite-supercell estimate, exact in the infinite-mesh limit. `band_structure` returns `BandStructure`. Examples 07 and 11.
- `src/mandacaru/algorithms/expressivity.py` — PQC **expressibility** (Sim *et al.* 2019): random-parameter fidelities against the Haar distribution scored by KL divergence. The Haar reference dimension is the *number-conserving sector* `d = C(M,nα)·C(M,nβ)` (`active_space_dimension`), **not `2^N`** — the fermionic ansätze never leave their symmetry sector. `ADAPTExpressivityTracker` / `track_adapt_expressivity` hook `ADAPTVQE.run(callback=…)`.
`backends/hardware.py` is the device registry (`AER_simulator`, IBM Quantum via Qiskit Runtime, Amazon Braket) and `utils/logging.py` is the ADAPT `output.txt` protocol (`AdaptOutputLogger`/`parse_output`). ADAPT-VQE is driven as `atoms.calc = Mandacaru(method="adapt-vqe", pool=..., basis="FAO", mapping=..., optimizer=..., gradient=..., device=...)`; `atoms.get_total_energy()` builds the Hamiltonian from the geometry and runs the loop, returning eV with the result on `atoms.calc.result`. `optimizer` takes a method name or an `Optimizer`; `gradient` is `"analytic"` (default) / `"finite_difference"` / `"parameter_shift"`. `run()` takes no required arguments (`max_iterations` / `gradient_tolerance` / `output` default to the constructor values) and prints the qubit Hamiltonian's **term count only**, then the iteration table (see the run-log section); neither the pool nor the selected operator's Pauli expansion is printed — they live on `result.operators` and, with `verbose_operators=True`, in `pool.json`. The class is `ADAPTVQE` and its result dataclass `ADAPTVQEResult` (no `AdaptVQE`/`AdaptVQEResult` aliases).

Both drivers also accept `kpts` (Monkhorst-Pack mesh via ASE — a `(n1,n2,n3)` triple or the ASE dict; the engine is Gamma-point/molecular, so a denser mesh is generated and exposed on `.kpoints` but rejected at run with `NotImplementedError`), `spin` (bool, default False — high-spin reference), `initial_state` (default `"hartree-fock"`, validated), and the **frozen-core approximation** `frozen_core`/`frozen_orbitals` (`True`/`"auto"` freezes the chemical noble-gas core, an int freezes that many lowest MOs, or `frozen_orbitals=[...]` names exact spatial-MO indices; core orbitals leave the active space via `core.hamiltonian.freeze_core_integrals` — a constant core energy plus an effective one-body potential — so the ansatz/pool/qubit count shrink; `core_electrons`/`resolve_frozen_core` resolve it, PW rejects it). The **initial spin state** is read primarily from the geometry's initial magnetic moments (`Atoms(..., magmoms=[1,1])` -> a triplet, via `resolve_num_unpaired`); the `spin` bool is the fallback. ADAPTVQE also takes **`sparse`** (default `"auto"` -> sparse pool for `n_qubits >= 12`): the Hamiltonian and pool generators stay scipy-sparse, screening uses the exact analytic gradient, and `AdaptAnsatz` applies `exp(theta A)` through the closed form `I + sin(theta) A + (1-cos(theta)) A^2` (valid because the excitation generators satisfy `A^3 = -A`; `expm_multiply` otherwise), so only the *selected* operators are ever densified and 12+-qubit active spaces stay tractable.

The ASE-calculator path **softens the -Z/r cusp to half a grid step** (`MolecularIntegrals(..., softening=)`) so a nucleus landing on a grid node no longer produces a garbage core integral (needed since FAO uses the bare Z), and centers the grid on the molecule (minimum-image via ASE `find_mic`), so placement in the cell is irrelevant. `run()` writes the start-up banner once per process (`utils/banner.py` — `lines()` renders it, `show()` writes those lines to stdout) *before* anything is written to `output.txt`, and the same `lines()` go once into the top of the log. `MolecularIntegrals.hartree_fock_hamiltonian(n_electrons)` reduces the full Hamiltonian to the mean-field (diagonal orbital-energy) HF `Fermion` whose ground state is the HF determinant at the RHF total energy. The `basis` argument accepts a name **or** a `{"name": ..., <options>}` dict (`resolve_basis` in `_hamiltonian_from_atoms.py`) — `{"name":"NAO","energy_shift":0.03}`, `{"name":"GTO","n_gaussians":3}`, or the periodic `{"name":"PW","energy_cutoff":300}` (routes to `PlaneWaveIntegrals`; requires `atoms.cell`).

Also implemented on the shared `VariationalDriver` (so VQE / ADAPTVQE and their subspace variants all accept them):

- **Multi-backend circuit providers** (`backends/providers.py` — `CircuitProvider` + `QiskitProvider`/`BraketProvider`/`CirqProvider`, `build_provider`/`normalize_provider`/`provider_available`). `backend_provider="qiskit"|"braket"|"cirq"` (default follows `device`) selects the SDK; `execute_circuits` (default `True` for braket/cirq, `False` for qiskit) makes state preparation *run a real circuit* on that SDK's local simulator instead of the internal backend. Each anti-Hermitian generator `A = Σ i c_j P_j` has mutually commuting terms, so `exp(θA) = Π exp(iθc_j P_j)` factorizes **exactly** (`pauli_rotations` verifies the commutation and refuses otherwise); each factor is a basis change + CNOT ladder + `Rz(-2θc_j)` + uncompute (`CircuitProvider._emit`, gate set `{x,h,s,sdg,cx,rz}`). Qiskit is little-endian, so Mandacaru qubit `k` sits on wire `n-1-k`; Braket and Cirq are big-endian like Mandacaru. Wired into `AdaptAnsatz(provider=...)` and `UCCSD(provider=..., trotter=True)` (a circuit realizes the Trotter product, so UCCSD raises without it); `profile_ansatz(..., provider=)` counts gates/depth per SDK. Circuit execution handles only computational-basis references (HF, the SSVQE ones) and raises otherwise. `examples/12_ADAPTVQE_LiH_backends.py` (LiH across all three, agreeing to ~5e-8 Ha).
- **Amazon Braket / real QPUs.** `BraketProvider(device=..., shots=...)` targets the local simulator or the **AWS service** by ARN. Verified constraint: Braket rejects the `StateVector` result type whenever `shots > 0`, and every QPU requires `shots > 0` — **the exact path is simulator-only**. The QPU path is shot-based: `backends/measurement.py` partitions H into **qubit-wise-commuting groups**, one measurement circuit per group, ⟨H⟩ from bit-string counts; error falls as 1/√shots. `hardware.py` holds the `Device` registry (`braket-local`, `braket-sv1`/`dm1`/`tn1`, `braket-ionq-aria`/`forte`, `braket-iqm-garnet`, `braket-rigetti-ankaa`, or a raw ARN); a QPU named without `shots` is refused in the constructor. **Limitation:** only the energy evaluation is hardware-native — ADAPT's pool screening is classical, so a fixed-ansatz `VQE` is the fully hardware-native driver today. `examples/13_braket_aws_compatibility.py`.
- **IBM Quantum hardware (2026-09-11), Estimator-based.** `QiskitProvider(device="statevector"|"fake_<name>"|"ibm-quantum"|"ibm_<name>"|"ibm_a,ibm_b,…", shots=, instance=, token=, channel=, optimization_level=3, estimator_options=, physical_qubits=, seed=)`: with `shots > 0` the energy is the **Estimator** expectation of the Hamiltonian as a `SparsePauliOp` (`observable()` = `to_sparse_pauli_op()` — labels coincide with Qiskit's because qubit `k` is on wire `n-1-k`; `pub()` = `transpile(qc, backend)` + `observable.apply_layout(isa.layout)`). Targets: `"statevector"` -> `StatevectorEstimator(default_precision=1/sqrt(shots), seed=)`; `fake_*` -> `Fake<Name>V2` under `BackendEstimatorV2`; `"ibm-quantum"` -> `least_busy(...)`, `ibm_x` -> `service.backend`, a comma list -> the least busy of those (`_ibm_backend`), then `Estimator(mode=backend, options=estimator_options)`. `energies(problems)` submits **one job with one PUB per problem**. **`seed=`** makes the *local* estimator reproducible — hardware and fake backends ignore it; without it a shot-based comparison against an exact run is a ~2σ coin flip. **Both local primitives are driven through their synchronous `_run([EstimatorPub.coerce(pub, precision)])`, never `run()`:** `run()` uses a one-off thread, and Qiskit circuit data allocated on another thread makes a later GC spin forever in Qiskit's Rust mimalloc (macOS / Python 3.14 / qiskit 2.5). Driver plumbing: `shots > 0` is allowed for `"qiskit"` (cirq refused); `_provider_options` passes `device`/`shots` only when shots or an IBM/fake device are involved; **`ansatz_provider()` is `None` whenever `shots > 0`** (the ansatz prepares states internally for screening while energies go through `ansatz_energy` -> `provider.energy`; `VQE` uses `trotter=True` then); a dry run may name hardware without shots. **Optimize locally, measure once:** `ansatz_problem(theta=None)`, `measured_energy(provider)` and `measure_energies(drivers, provider)` put a whole curve in **one** job. The IBM open plan has 10 min/month (`service.usage()`): **never run optimizations on hardware**; rehearse on `fake_kingston`/`fake_fez`/`fake_marrakesh` (needs `qiskit-aer`) and submit only the final job. **Two lessons, paid for:** unmitigated 12-qubit LiH circuits (92 CZ, depth ~300) landed 0.5-0.8 Ha above exact; and an H2 curve on a drifted readout qubit came out *below* the exact ground state, the Estimator's readout mitigation having divided by a 35 % assignment error whose calibration record claimed 0.7 %. So `physical_qubits=[...]` pins the layout (qubit k -> `physical_qubits[k]`, on the reversed wires): rank pairs by `backend.properties()` readout + CZ error and prefer a live readout check over the record — on a pinned good pair the 2-qubit H2 curve landed within ~0.015 Ha of exact and *above* it everywhere. Rule of thumb: a few tens of two-qubit gates. Data in `examples/data/h2_dissociation_ibm*.{csv,json}` and `lih_dissociation_ibm.{csv,json}`; plots `plot_h2_ibm.py` / `plot_lih_ibm.py`; pinned by `test/test_ibm_quantum.py`; examples 24 and 25.
- **Parity-reduced mapping.** `mapping="parity_reduced"` tapers the two parity qubits fixed by the particle numbers consistently across the Hamiltonian, pool, ansatz, sector, checkpoints, cached Hamiltonians, forces and dry-run estimates. The mapping name is the sole source of the register representation. `FermionicPool`, `QEBPool` and `CEOPool` support it; `QubitPool` and the subspace solvers refuse it (their operators or reference determinants are not tapered). H₂/FAO uses 2 qubits instead of 4 at the same energy.
- **Dynamic parametrization** `quenching` (default `True`). `True` re-optimizes **all** parameters each iteration (standard ADAPT-VQE — this is what reaches FCI). `False` optimizes only the newly appended parameters and freezes the earlier ones (a cheap line search per growth step, variationally weaker). Implemented once on the base as `_optimize_grown` (`ADAPTVQE.run`, `_grow_deflated`, `SubspaceADAPTVQE._subspace_optimize`) and `_optimize_all` (`VQE.run`/`_deflated_ground`/`SubspaceVQE`, where `quenching=False` sweeps one parameter at a time).

**Pseudopotentials — part of the main API (graduated 2026-09-15).** The whole feature lives in `src/mandacaru/pseudopotentials/` (`generation.py`, `io.py`, `orbitals.py`, `families.py`, `oncv.py`, `paw.py`, `link_library.py`, the library in `library/ncpp/` plus the git-ignored `library/oncvpsp` and `library/paw` **symlinks**, re-created with `python -m mandacaru.pseudopotentials.link_library --oncvpsp DIR --paw DIR`; `io.library_root()` is the parent (env `MANDACARU_PSEUDO_PATH`), `default_library_path()` = `ncpp/`). Tests are `test/test_{pseudo_io,pseudopotential,pseudopotential_engine,ncpp_family,oncvpsp,paw,link_library}.py` (together ~340 tests / 50 s / 2.4 GB; the project-wide `test/conftest.py` times every test and reads its peak RSS into `test/.resource_report.txt` — budget: test < 3 min, suite < 10 min, RSS < 8 GB), examples `26_pseudopotential_generation.py` / `27_pseudopotential_calculations.py`, guide `docs/source/guide/pseudopotentials.md`. `mandacaru.experimental` holds only VASQE.

**The selector is the `basis` argument — there is no `pseudopotentials=` argument anywhere:** `basis="NCPP"` (aliases `"TM"`, `"NCPP-TM"`), `"ONCVPSP"` (alias `"ONCV"`), `"PAW"`, `"UPAW"`, or the dict form with the size hierarchy `{"name": "PAW", "size": "DZP", "split_norm": ..., "directory": ...}` (every family also takes `tail_norm`; PAW/UPAW also take `projector_basis`, `energy_shift`, `confinement`, `polarization`, and default `filter` to on), exactly like `"FAO"`/`"NAO"`/`"cc-pVTZ"`; the per-element form `{"O": {"name": "PAW", "size": "DZP"}, "H": "PAW"}` works with sizes per element within ONE family (mixing a pseudo family with an all-electron family, or two pseudo families, raises a clear `ValueError`). Plumbing: `_hamiltonian_from_atoms.pseudopotential_family(name)` -> `FamilySpec | None` via `families.lookup_family` (the registry is the single source of truth, so `register_family` makes a new family a basis name with no driver edit); `resolve_pseudo_basis(name, options, symbols)` handles the per-element case; `build_basis_hamiltonian(atoms, basis, grid, h, charge, n_electrons, spin, frozen_core, frozen_orbitals, kinetic)` dispatches to `_pseudopotential_hamiltonian(..., family, options, kinetic)`, which validates the option keys against `FamilySpec.options` (default `COMMON_OPTIONS` = size/split_norm/directory) — an unknown key raises at driver construction (`VariationalDriver._check_pseudo_basis`), as does `frozen_core` with a pseudo basis. `dry_run.count_basis_functions(atoms, basis)` / `estimate_qubits(..., basis=)` count the pseudo basis (label `"PAW (DZP, pseudopotentials)"`). The old `"PP"`/`"PSEUDO"` basis names are a **deprecation error** (`RETIRED_PSEUDO_BASIS_NAMES`, `_check_retired_basis_name`) pointing at the new spelling — no silent aliasing.

**The family registry** is `families.PSEUDO_FAMILIES`: `FamilySpec(name, description, generate, get, build, norm_conserving, aliases, options)` with `register_family`/`unregister_family`/`resolve_family`/`lookup_family`/`canonical_family_name`/`family_names`/`family_listing`; unknown names raise a `ValueError` listing the registry. `_pseudopotential_hamiltonian` is a thin dispatcher — `family.build(atoms, grid, h, charge, spin, options, kinetic)` returns the usual 5-tuple. `PseudoPotential.family` is written and read by `io.py` (`FORMAT_VERSION` 2; a v1 file without the field loads as `LEGACY_FAMILY`), and the canonical Troullier-Martins key is **`"ncpp"`** (aliases `("tm", "ncpp-tm")`, `FamilySpec.label` = `"NCPP"`) — the shipped library files still say `"tm"` and are canonicalized on load.

**NCPP (Troullier-Martins).** Norm-conserving TM pseudopotentials with **Kleinman-Bylander** projectors, generated from scratch by an LDA radial atomic solver (`basis/atomic_solver.py`). The nonlocal term is the general separable form `H_NL = C D C+`: `C = projections()` (M x P, cached, C kernel `kb_projections`, fills `kb_resolution_ratios`), `D = nonlocal_coupling_matrix()` block-diagonal over `(atom_index, l, m)` from `nonlocal_coupling` (`core.hamiltonian.projector_blocks`/`assemble_block_matrix`; `None` -> the projectors' `kb_energy` diagonal). `MolecularIntegrals.kb_nonlocal()` (alias `nonlocal_matrix`) evaluates it; `KBProjector` carries `atom_index`, `channel=(l,m)`, `index` (radial projector within the channel, 0 for KB), `block_key`, and accepts `radial=`/`kb_energy=` overrides, with `orbitals.kb_coupling_blocks(projectors)` giving the TM `[[E_KB]]` blocks. **Overlap hook:** `nonlocal_overlap` (PAW's `q_ij`; TM passes `None`) makes `overlap()` = `bare_overlap() + C Q C+`, which feeds `_lowdin_x` and hence every orthonormalized integral / RHF / UHF-NO path (`Q = 0` reproduces the plain Hamiltonian exactly). Pinned by `test/test_ncpp_family.py`: H2 RHF -1.061096 / FCI -1.075333 Ha, LiH RHF -0.729555 / FCI -0.740839 Ha (re-pinned by ~1e-8 Ha when the FFT self-energy became exact; the old values stay under `before_exact_self_energy`). H and Li have one (local) channel, so H2/LiH carry no TM projectors.

**ONCVPSP** (`oncv.py`, Hamann PRB 88, 085117; family `"oncvpsp"`, alias `"oncv"`). `bound_state` (Numerov shooting; `generation_points(Z)` = max(6000, 1500 Z); `_origin_seed` is a **six-term power series** -- the two-term one admixes the irregular solution) and `scattering_wave` at `eps_1 + energy_offset` -> `optimize_pseudo_waves` (8 spherical Bessel functions at the **interleaved zeros of j_l and j_l'** -- the RRKJ log-derivative roots make the third-derivative row linearly dependent -- value + 3 derivatives from the AE radial equation plus generalized norm conservation, residual kinetic energy beyond `q_cut` = 5 Bohr^-1 minimized **exactly** by null-space elimination and a 1-D Lagrange root) -> `polynomial_local_potential` -> `assemble_channel` (`B_ij` asserted symmetric to `B_ASYMMETRY_TOLERANCE` 1e-6 -- needs cubic-spline resampling and the ODE-based targets -- `D = B^-1`) -> unscreen. Records `ONCVPseudoPotential`/`ONCVChannel` (two projectors and a 2x2 coupling block per l). Library `library/oncvpsp/` (`build_oncv_library`, `get_oncv`; `DEFAULT_CUTOFFS` H 1.30 / Li 2.60 / C 1.50 / N 1.45 / O 1.45 / F 1.40 Bohr -- Li at 2.2 or 3.3 grows a ghost, 3.0 shifts LiH by 0.15 Ha). Diagnostics: `check_oncv_channel`, `radial_spectrum` (3-point Laplacian + Richardson -- a 5-point stencil breaks the Dirichlet origin for l=0), `log_derivative_ae`/`log_derivative_ps`, `report_oncv`. Validation (`test/test_oncvpsp.py`): eigenvalues <= 1e-7 Ha, log derivatives <= 1.7e-4; **H2 (h=0.25) RHF -1.044179 / ADAPT -1.058561, LiH (h=0.30) RHF -0.774343 / ADAPT -0.782341 Ha**. Known limits: no NLCC, no relativity, no projectors above the valence l, |D| up to ~300 Ha (harmless to first order). ONCVPSP still **grid-samples its projectors** -- the exact on-site quadrature exists only in `PAWIntegrals` -- making its O/C curves erratic at the +-3 eV level; prefer PAW there.

**PAW** (`paw.py`, Bloechl PRB 50, 17953; family `"paw"`, `norm_conserving=False`, extra option `projector_basis="raw"|"dual"`). Frozen-core, one-center-expansion form with the one-center terms **linearized** at the LDA reference (fixed `D^ion` plus the constant `one_center_energy`). `generate_paw` -> `PAWDataset`/`PAWChannel`: the ONCV Numerov pair (`DEFAULT_ENERGY_OFFSETS` H/Li 0.5 Ha, else 1) -> `smooth_partial_waves` = `oncv.optimize_pseudo_waves(..., norm_factor=1-s)`, so `q = s <phi_i|phi_j>_rc` is **positive definite by construction** (`DEFAULT_NORM_DEFICITS` H 0.05 / Li 0.02 / C 0.10 / N,O,F 0.15; free waves gave an *indefinite* q and a singular `1 + sum |p~>q<p~|`, refused via `OVERLAP_MINIMUM`) -> `polynomial_local_potential` with **`DEFAULT_LOCAL_SHIFTS`** C 12 / N 10 / O 6 / F 8 Ha (without them the continued potential binds a 1s-like ghost 0.6-1 Ha below eps_2s in the first-row s channel) -> `chi_i = (eps_i - T - v~) phi~_i`, `B_ij = <phi~_i|chi_j>`, dual projectors `p~_i = sum_k (B^-1)_ki chi_k` (duality asserted to 1e-8, achieved 1e-14), `q`, `dT`, `dV`, `D^scr = B + eps_j q_ij` -> monopole compensation charge (`(1-r^2/r_g^2)^3`, `r_g = min r_c`) -> unscreen -> `D^ion` and `one_center_energy`. Molecular path `build_paw` -> **`PAWIntegrals(MolecularIntegrals)`**: `paw_projectors`, `paw_coupling_blocks` / `paw_overlap_blocks` (via `PAWDataset.projector_set(l, basis)` -- `"raw"` vs `"dual"` give identical energies, only the resolution ratio differs), **exact on-site projections** (radial quadrature; grid sampling gave 0.7-3x the exact value and collapsed LiH by 0.2-0.6 Ha), the **augmented two-body tensor** (`two_body_augmentation`, `compensation_moments`, `compensation_potentials` W, `compensation_coulomb` U) and `one_body_augmentation`. Two hooks added to `MolecularIntegrals` for this and inert elsewhere: `two_body_augmentation()` (None by default) and `constant_energy` (0). Diagnostics: `check_paw_channel`, `paw_spectrum`, `paw_eigenstate`, `reconstruct_ae`, `log_derivative_paw`, `report_paw`. Library `library/paw/` (`build_paw_library`, `get_paw`, `paw_library_path`; 9.6 s to regenerate). Validation (`test/test_paw.py`): duality <= 1e-14, eps_1 to <= 1.2e-7 Ha with no ghost, AE reconstruction <= 6.5e-5, `q_11` H 0.0212 / Li 0.0045 / O 0.114; the pinned molecular energies are in the 2026-09-20 sections below. Omitted vs Bloechl: self-consistent `D_ij[rho]`, NLCC (`smooth_core_density` stored, unused), relativity, GGA, projectors above the valence l.

**Sizes, library coverage and storage.** `{"name": "PAW", "size": "DZP", ...}` reaches `pseudo_basis(..., size=)`, which builds the split-valence zetas *from the pseudized orbital* (polarization split off the outermost channel); `size` defaults to `"SZ"`. An all-electron family can never be paired with a pseudopotential — the family *is* the basis. The shipped library covers **every element with Z <= 92** (`LIBRARY_Z_MAX = 92`, regenerable with `build_library()`); the ONCVPSP (110 MB) and PAW (190 MB) libraries live in the sibling repositories `mandacaru-oncvpsp` / `mandacaru-paw` (flat `<Symbol>.parquet`) and are linked in, never committed (`link_library(family, source, root=, files=, force=)`, `status()`, per-file links with `--files`; pinned by `test/test_link_library.py`, whose real-loader test skips when the links are absent). Storage is **Parquet by default** with **JSON** retained (`PSEUDO_FORMATS`); `load_pseudopotential` **auto-detects** the format from the extension, falling back to magic bytes (`PAR1` vs `{`). `save_pseudopotential` is lossless and idempotent (`stride=1`); the `STRIDE=4` decimation applies only at `build_library()` time, where the fine generation grid exists — applying it per-write made load->save compound. **Beware the pandas/pyarrow/qiskit interaction:** pandas 3 defaults `future.infer_string` on, so even a *fastparquet* read builds its column index as a pyarrow string array, and after Qiskit's `transpile` has run in the same process that decode corrupts (`UnicodeDecodeError` / `ArrowException`). Every Parquet read therefore goes through `core.serialization.native_pandas_strings()` — keep new Parquet paths inside it. (Separately, importing pandas *after* qiskit's transpile segfaults at interpreter shutdown; importing it first is fine.)

**PAW / ONCVPSP forces, particle-number sectors, real orbitals (2026-09-15).** `atoms.get_forces()` with a pseudopotential basis goes through `algorithms/pseudo_forces.pseudo_nuclear_gradient`: the energy `E = sum D h^MO + 1/2 sum Gamma g^MO + E_ion + E_1c` with `h^MO = A+ h A`, `A = S^-1/2 V` is differentiated with the spin-summed RDMs (`spatial_rdms`) and the MOs `V` (`MolecularIntegrals.mo_coefficients`, set by `molecular_hamiltonian`) held fixed — exact for an orbital-stationary state, with `details["orbital_gradient"]` measuring the residual. Hellmann-Feynman = operators move (local potential, projectors in `C D C+` and `S = S~ + C q C+`, compensation `W`/`U`, ion-ion); Pulay = basis functions move (`S~`, `T`, `V_loc`, `C`, grid ERI, `W`). Matrix derivatives come from displaced sampling on the frozen grid, contracted as a central-difference directional derivative of `AlgebraicEnergy(S, h, g)` (complex-safe, no energy-weighted density matrices). The calculator refuses a force whose rebuilt energy differs from the solver's by more than `ENERGY_CHECK_TOLERANCE` (1e-6 Ha). Validated analytic vs central difference of the fixed-state energy at **8.6e-5 eV/Angstrom** (H2 PAW-DZP, h = 0.25).

**Three fixes are load-bearing and must stay.** (1) **`PAWIntegrals.projections()` are atom-centered spherical quadratures** (`atom_centered_projections`, 64x24x48 points over each projector sphere; `atom_centered_projection_gradients` gives `G = <dphi/dR|p>`, Pulay `+G`, HF `-G`; `exact_projections = True`) — grid-sampled projections put a 3.9 eV nonlocal egg-box on H2 at h = 0.25 and 2 eV/Angstrom force errors; the remaining egg-box (kinetic/local/Hartree) is 18/13/5 meV at h = 0.25/0.20/0.15. (2) **`PAWDataset.local_potential` is a cubic spline** (C2, `_local_spline`, cached by id) — `np.interp` kinks made derivatives step-dependent at 2e-2 eV/Angstrom. (3) **Conjugation-real MOs** (`core.hamiltonian.conjugation_real_orbitals`, `MolecularIntegrals.conjugation_matrix`/`real_orbitals`, applied in `molecular_hamiltonian` for RHF and UHF-NO, rotating only within the occupied/virtual blocks): complex `Y_lm` orbitals leave the SCF with arbitrary phases and mixed degenerate pairs, the MO ERIs pick up imaginary parts (5.7e-2 Ha on H2 DZP), and every real pool then **stalls** (ADAPT 62 meV above FCI with every optimizer, 0.05 eV/Angstrom force error); with real MOs ADAPT reaches the sector FCI to 1e-9 eV. This affected every l > 0 basis, not just PAW.

**Particle-number sector** (`core/sector.py`): `ParticleSector(n_qubits, (n_alpha, n_beta), mapping)` with `restrict`, `positions`, `basis_vector`, `embed`, `project`. `restrict(PauliSum, max_entries=None)` builds the CSR on the sector by bit masks, **folded in batches of `RESTRICT_BATCH_ENTRIES = 8_000_000` staged entries**: every Pauli term contributes one entry per sector state, so holding them all before de-duplicating costs `len(terms) x dim` (OH in PAW-DZ staged 3.7e8 entries, ~12 GB, and died). Folding batch by batch is exact (the sum is linear in the terms; pinned bit-identical down to `max_entries=1`) and brings that case to 33.5 s / 2.74 GB peak. **`restrict` groups terms by flip mask (2026-09-21).** A Pauli string sends `|x>` to a phase times `|x ^ f>`, so every term with the same `f` sends column `j` to the **same row** — and the `searchsorted` that finds those rows, which dominated the cost, is paid once per *group* instead of once per term. Structural, not lucky: **X and Y both set a flip bit**, so all eight Pauli strings of a JW double excitation share one mask, the two of a single share one, and every Z-only term lands in `f = 0`. A molecular Hamiltonian has **~9x fewer masks than terms, flat in the basis size** (M = 4/6/8/10 -> 10.0/9.8/9.4/9.2). The group's terms are then summed into **one** value array before any COO entry is emitted, so the staged entries shrink by the same factor. `flip_groups(operator)` is the public helper; `inside.all()` is a fast path that skips compaction for a number-conserving operator. **Measured** (synthetic molecular Hamiltonians, JW): 12 qubits 0.088 -> 0.019 s (**4.6x**), 16 qubits 1.9 -> 0.3 s (**~6x**), **20 qubits 59.3 -> 7.0 s (8.6x)**, agreeing with the old result to 1.6e-14 (summation order only) at identical `nnz`; transient allocation during the restriction ~2.8x lower (556 -> 197 MB at 20 qubits), though total memory is dominated by the *result* matrix, which is unchanged. Pinned by `test_sector.TestFlipMaskGrouping` (the ratio, the group accounting, the one-mask-per-double property, and agreement with the dense restriction for both a conserving and a leaking operator). **Benchmark trap:** `ru_maxrss` is a high-water mark, so a delta is meaningless if anything ran before the baseline was sampled — measure absolute peaks in a fresh subprocess.

`ADAPTVQE(sector="auto")` materializes H and the pool on the sector for `n_qubits >= SECTOR_AUTO_QUBITS = 16` (no circuit provider, not the subspace solvers); `AdaptAnsatz(sector=)` and `rdm.one_rdm/two_rdm(..., sector=)` follow (not with `mapping="parity_reduced"`). Also: **`Fermion.map_to_qubits` accumulates in place** — `result = result + op` copied the whole sum per term and took 22 s of a 24 s H2 DZP run.

**Two radial on-node bugs, both fixed and both still load-bearing.** (1) `multizeta.TabulatedOrbital.radial` and `nao.NumericalAtomicOrbital.radial` evaluated their `CubicSpline(extrapolate=False)` below the first table point, got NaN and returned 0, so every s function vanished within ~0.005 Bohr of its center and a nucleus **exactly on a grid node** (a symmetric molecule centered in its cell) lost the orbital's peak sample: LiH PAW-DZP -18.31 instead of -21.28 eV. Both now continue as `R(r0)(r/r0)^l` below `r0`. (2) `pseudo_basis` built the polarization shell from the outermost channel's radial function *itself*, so `R_p(0) != 0` and the p function was discontinuous at its own nucleus; its displaced-sampling derivative exploded on-node (analytic -8.12 vs finite-difference -5.11 eV/Angstrom). The shell is now `r^k R_outer(r)` normalized (k = 1 for the first polarization shell) — same range, vanishing as `r^l`. Both changed every pseudo-family DZP/TZP energy.

**File-size and log-detail limits** (user directives, 2026-09-15). `core.serialization.MAX_FILE_QUBITS = 50`: `save_hamiltonian` raises above it, and `VariationalDriver._maybe_save_hamiltonian` calls `file_qubits_allowed(n_qubits, what)` first, skipping the cache with a `RuntimeWarning` while the simulation continues. **Measured forces and the tapered register (2026-09-15).** `Mandacaru(measurement_provider=QiskitProvider(...))` optimizes on the local state vector (**never on hardware**), then measures the optimized state's Pauli expectation values in **one PUB / one job per geometry** (`QiskitProvider.expectation_values(...)` → `({label: <P>}, {label: std})`) and takes the ASE energy **and** the forces from them: `Mandacaru._measure` collects every label of the qubit Hamiltonian and of `rdm.rdm_qubit_operators(n_modes, mapping, num_particles)` (`MAX_PAULI_RDM_MODES`, 25; only the *forces* path reaches it now), assembles γ/Γ with `rdms_from_expectations`, and `_forces(solver, rdms=, reference_energy=)` checks the RDM-rebuilt energy against the *measured* one — an algebraic identity, so it validates the wiring on hardware too. The last measurement is on `calc.measurement`. ## Measuring on hardware: what a job costs, and the six things that shrink it (2026-09-21)

Prompted by a real failure — LiH 1.60 Å, PAW-TZP, 24 qubits, `ibm_fez`, `resilience_level=2`: **`Error code 1336; Program runtime ran out of memory`** after 37 min of queue, discarding a converged 75-operator run. Full tables and reasoning in `docs/source/guide/measurement_cost.md`; pinned by `test/test_measurement_scaling.py` (36 tests, 7 s).

**Measured scaling** (LiH/PAW, h=0.25, `ceo-ovp`, JW) at 4/8/20/24 qubits: H has 46/360/5,866/12,736 Pauli strings, the old submission 50/980/46,170/**97,980** labels, QWC 23/93/1,600/3,290 bases, the circuit 18/150/881/2,223 2q gates. **QWC bases ≈ 0.2·M³**, so every constant-factor fix below buys about *one basis-size step*. Three walls: memory (fixed here), **shots** (1-norm bound: LiH-DZ ≈ 1e9 shots for 1.6 mHa against the Open plan's 10 min/28 days), **fidelity** ((1−3e-3)^n2q = 0.64/0.07/0.001 at DZ/DZP/TZP — DZP is already past it). **Fixing the memory does not make 24 qubits meaningful; it makes 4–8 possible.**

1. **RDMs only when forces ask** (`Mandacaru._measure(solver, rdms=want_forces)`). An energy-only run used to submit H ∪ every 1-/2-RDM operator and discard it (97,980 labels vs 12,736, plus 34 s building 117,792 operators). The energy now goes as **one weighted `SparsePauliOp`** via `provider.energy` (`pub()` always did; only `expectation_values` was one-per-label), which also removes the per-observable ZNE arrays.
2. **Pre-flight `[MEASUREMENT PLAN]`** (`backends/measurement.py`: `MeasurementPlan`, `measurement_plan`, `resolve_measurement_budget`, `MeasurementBudgetError`, `DEFAULT_MEASUREMENT_BUDGET` = observables 50k / bases 10k / circuit_instances 2M). All local; `_resilience_multipliers` shows `resilience_level=2` is a **96×** circuit multiplier before a shot is counted. `Mandacaru(measurement_budget=…)` refuses oversized jobs *before* queueing; `plan.warnings()` fires below `FIDELITY_WARNING = 0.1`.
3. **`MeasurementFailed` keeps the state** (`_measurement_failure`): the exception names the observable/basis/shot counts, `calc.solver` and `calc.measurement_plan` survive, and **`calc.remeasure(provider=, rdms=, **overrides)`** resubmits the same ansatz — no re-optimization.
4. **Chunking** (`QiskitProvider(max_bases_per_job=)`, `chunk_labels_by_basis`, `planned_jobs`): jobs of bounded QWC-basis count, never splitting a basis, one shared transpilation, `provider.jobs`; **`qpu_usage` now sums over every job** (it reported `qpu_jobs = 1` and the last job's seconds). Forces identical to the unsplit submission (0.0).
5. **Odd-Y strings are exactly zero.** A string with an odd number of `Y` is `i^odd` times a real *antisymmetric* matrix, so `<psi|P|psi> = 0` identically for real `psi`. `_is_real_operator` holds the parity rule — **even Y needs a real coefficient, odd Y an imaginary one** (written inverted first, which silently disabled the optimization: the generators are all-odd-Y with imaginary coefficients) — and `_real_problem` checks H *and* every `ansatz.pauli_generators`. LiH/PAW-DZ: 472 of 981 labels dropped, energy/RDMs/forces bit-identical.
6. **Double factorization**, `measurement_scheme="double-factorized"` (`backends/factorization.py`; Motta npj QI 7, 83 (2021), Huggins npj QI 7, 23 (2021)) — **the only item that changes the exponent**. `H = E0 + Σ h̃_pq a†_p a_q + ½ Σ_l λ_l (Σ_k g_lk ñ^(l)_k)²`: reshape `g_prqs = <pq|rs>` to `W_{(pr),(qs)}`, `eigh` for the leaves, `eigh` each leaf for its rotation; the `-½ Σ_q <pq|qs>` remainder folds into `h̃`. `to_fermion().map_to_qubits()` equals the original to **0.0**. Each `U_l` is realized by **`givens_decomposition`** — any real orthogonal M×M matrix is ≤ M(M-1)/2 rotations on *adjacent* modes, each a 2-qubit gate under JW (Clements Optica 3, 1460 (2016); Kivlichan PRL 120, 110501 (2018)) — after which every occupation is diagonal, so a leaf is **one diagonal `I`/`Z` observable**: `L+1` PUBs, one job. **Measured energy = the state vector's to 4e-13 eV.** `Mandacaru.factorization()` supplies the driver's scalar offset; JW and integrals only, both refused by name. **The trade, measured** (LiH/PAW, bases → / λ ratio / total shots): 4 orb 5.2×/5.8×/**×6.5 worse**, 8 orb 8.5×/2.9×/×1.0, 20 orb 29×/1.7×/**×0.10**, 24 orb 45×/1.5×/**×0.05**. **Crossover ≈ 8 qubits** — below it the QWC path is cheaper, and the plan reports the *factorized* 1-norm (larger) so the shot cost is not understated. **Two traps:** `energy()`'s einsum is `"pqrs->prqs"` on Γ (`"pqsr->prqs"` first, caught by the operator identity staying exact); and `basis_rotation` emits the elimination order **unreversed**, since a circuit applies `generators[0]` first and so realizes the reversed product — one reversal too many cost 0.15 Ha with every piece looking right, so a test extracts the single-particle matrix the circuit *actually* induces.

**Checkpoints** (`core/checkpoint.py`, exported from `mandacaru.core`): `WavefunctionCheckpoint(n_qubits, reference_qubits, generators, parameters, labels, kinds, mapping, num_particles, n_spatial_orbitals, occupied_orbitals, energy [Ha], hamiltonian, method, status, metadata)` is the algorithm-agnostic on-disk form of `|Ψ> = Π_k exp(θ_k A_k)|ref>` — the *register-level* description, which is exactly the `(n_qubits, occupied, generators, theta, hamiltonian)` tuple every circuit provider consumes (`problem()`). `state_vector()` prepares the amplitudes with no driver (Rodrigues closed form when `A³ = −A`, `expm_multiply` otherwise), `circuit(provider)` is `provider.build(...)`, `expectation()` uses the stored Hamiltonian. ## PAW and p-valence binding: the compensation-charge fix (2026-09-17)

**Symptom.** PAW had no bound minimum for O/C-containing molecules: exact sector ground states of OH, CH and H2O went monotonically downhill to dissociation in every `size` and `h` (OH/SZ +7.50 eV above dissociation at r_e), while s-valence systems were fine (LiH was the positive control). The relaxations still *converged*, cleanly, to the wrong answer: **a converged relaxation is not evidence that the model binds — check with an energy scan.**

**Root cause.** `_compute_one_body` builds `T + V + C D C+`, where `V` is the grid integral of `v^ion` against the **smooth pair density**. PAW's compensation charge is an *extra* density the grid integral could not see, while `two_body_augmentation` gave it its full Hartree repulsion: it repelled every electron and was attracted to no nucleus. It scales with the augmentation charge (O 0.64 e against Li 0.009, H 0.021): **+102 eV for OH** against +0.55 for LiH, growing by **+8.7 eV** between 4.0 and 0.97 Angstrom — exactly the binding deficit.

**The fix.** The hook `MolecularIntegrals.one_body_augmentation()` (`None` by default), added to `one` in `_compute_one_body` and to the force's energy rebuild. `PAWIntegrals.one_body_augmentation` returns `sum_{A,LM} Q^{A,LM}_pr V^{A,LM}` with `V^{A,LM} = integral g^_{A,LM} sum_{B != A} v^ion_B` from `compensation_ionic_at(centers)` — an **atom-centered spherical quadrature** (the shape spans ~4 grid points at h = 0.20; a grid sum would inject an egg-box), converged to 1e-9. The on-site `B = A` term is excluded (already inside the dataset). Taking `centers` as an argument lets the force difference it (`pseudo_forces._ionic_shift`).

**Results** (exact sector ground states, PAW-SZ, h = 0.20, 12 Angstrom cell): OH -> **bound, 1.05 Angstrom, 3.46 eV** (exp. 0.9697, 4.6); CH -> **1.25 Angstrom, 1.77 eV** (1.1199, 3.47); LiH 1.69 Angstrom, 1.44 -> 1.65 eV. PAW-DZ moves OH to ~0.90 Angstrom, bracketing experiment.

**Pins moved with it — do not restore the old ones.** Every PAW energy dropped in proportion to the augmentation charge (the old table is `PAW_BEFORE_COMPENSATION_ATTRACTION`). **H2 PAW-DZP `d_eq` moved 0.807 -> 0.712 Angstrom** (h = 0.25; exp. 0.741, VASP-PBE 0.750), so in `test_paw_forces` 0.75 Angstrom is now *outside* the minimum (`bond_force > 1.0`) and `test_h2_force_curve_follows_vasp` compares only *signs* where |VASP force| > 2 eV/Angstrom. **Y_LM convention:** `compensation_moments()` / `compensation_coulomb()` are keyed by `(atom, L, M)`; the monopole carries `1/sqrt(4 pi)` and the Coulomb matrix `4 pi`.

**Two hypotheses built, measured and REFUTED** — correct machinery, not the cause; do not "re-fix" them. (1) **Multipole compensation** (`pseudopotentials/multipoles.py`: `shape_function`/`shape_potential` for any L, `gaunt` by quadrature, `radial_moments`, `multipole_coulomb_matrix`, `paw_multipole_blocks` + `PAWDataset.multipole_moments`; `L = 0` reduces to the monopole to 3e-16 using the *stored* `q_ij`). Effect on OH binding: 0.5 eV. Kept, because the fix sums over the same channels. (2) **One-center two-body term** (`pseudopotentials/onecenter.py`) — `1/2 (D-D0)^2 dW`, **measured at 0.08-0.33 eV for oxygen**, ~0 for Li/H, **not wired into the Hamiltonian** (`test/test_onecenter.py`).

**Cost note.** OH/PAW-SZP is 26 qubits, **127,948 Pauli terms**, sector dim **204,490**: memory is fine (~2.1 GB, batched `restrict`) but one Hamiltonian takes **~40 min** — `ParticleSector.restrict`'s per-term Python loop is what to optimize. **DZ beats SZP in practice.**

## The compensation potentials are not Hermitian (2026-09-17)

**Root cause of the p-valence *force* error.** `PAWIntegrals.compensation_potentials()` returns `W^{A,LM}_qs = integral phi~*_q phi~_s v_L(r_A) Y_LM(r^_A)`. **The weight is complex whenever M != 0**, so `W` is Hermitian only for M = 0 (on water `|W - W^H|` is 1e-16 for `(A,L,0)` and *as large as `|W|`* otherwise). The Pulay branch wrote `dW = cross_w + cross_w.conj().T`, and `cross^H` puts **`conj(v)`** in the second half. Both halves are now written out explicitly. One line.

**Why it hid.** An s-valence atom has only the `(A,0,0)` channel, so **H and Li never exercise it** (H2 4.4e-5, LiH 1.6e-4 against OH 4.2e-2) and all 76 `test_paw*.py` tests passed before and after. On C2v water z rides the real `M = 0` harmonic and y the complex `M = +-1` pair: the oxygen force came out **2.2496 along y against 2.7841 along z**.

**How it was found** (repeat this next time): monkeypatch `AlgebraicEnergy.directional` to capture every `(dS, dh, dg)`, rebuild the integrals at displaced geometries **on the same frozen grid**, and compare each matrix derivative with its own central difference: `dS` 2e-6, `dh` 6e-6, **`dg` 1.4e-1**, only for oxygen — leaving `dW`. **Units trap: the analytic derivatives are per Bohr, an ASE displacement is in Angstrom — a factor 0.5292 that looks exactly like a physics bug.**

**Results** (water, PAW-SZ, h = 0.20): analytic vs finite difference **0.575 -> 0.0032 eV/Angstrom**, C2v restored (O: 2.82747 vs 2.82755). The net force got *larger*, 0.869 -> 1.158, **and that is correct** (rigid-translation finite difference -0.8162 per axis against -0.8188; the old cancellation was accidental). What remained was a real egg-box, net/largest force **1.85 / 0.86 / 0.41 / 0.099 / 0.025 at h = 0.30 / 0.25 / 0.20 / 0.16 / 0.13** — before the filter and exact-local defaults; oxygen needed **h <= 0.16 for geometry**.

**H2O in PAW-SZ binds** (the older "no bound minimum" note was the **all-electron FAO** path). Symmetric O-H scan, h = 0.16, 104.5 degrees: minimum **-482.291 eV at 1.00 Angstrom**, monotonic to -474.657 at 3.20, so **7.63 eV for the two bonds** (exp. 4.8 each). A relaxation from 90 degrees / 1.0 Angstrom reaches 0.9921 Angstrom / 117.29 degrees in 3 BFGS steps: the angle error is the minimal s+p shell, not the gradient (PAW-DZ water would be 24 qubits / sector dim 245,025).

Pinned by `test/test_paw_forces.py`: `test_compensation_potentials_are_hermitian_only_for_m_zero`, `test_forces_respect_the_c2v_symmetry`, `test_p_valence_force_is_the_derivative_of_the_energy` (both **verified to fail pre-fix**), `test_translation_projection_zeroes_the_net_force`.

## The orbital-response warning: what it means, and the pool fix (2026-09-18)

`atoms.get_forces()` on H2O/PAW-SZ warns `the state is not stationary with respect to orbital rotations (max |dE/dkappa| = 8.5e-03 Ha)`; **the message's original advice was wrong** and was rewritten.

**What the residual is.** `AlgebraicEnergy.orbital_gradient` is `max |dE/dkappa|` over orbital rotations with the RDMs frozen. It vanishes at *both* ends of the correlation range — RHF is orbital-stationary, and a full CI in an orbital space is invariant under rotating those orbitals, so the frozen-orbital gradient is the *whole* derivative there. Measured at the relaxed water geometry (h = 0.25, 6 orbitals, sector dim 225): **HF determinant 1.2e-9 Ha, exact sector FCI 1.8e-9 Ha, ADAPT (30 `ceo` operators, 5.4e-4 Ha above FCI) 1.0e-2 Ha.** So a nonzero residual does **not** report an unconverged optimizer — it reports an ansatz that stopped short of its space's FCI.

**Why tightening the tolerance does nothing.** The energy is *second* order in the state error, this residual *first* order: `gradient_tolerance` 1e-3 -> 1e-4 with `max_iterations` 50 -> 100 grew 30 -> 41 operators and moved the screening gradient 1.8e-4 -> 7.6e-5, the energy by **1e-6 eV** and the residual by **0.6 %**. Pinned as a scaling law by `test_all_electron_forces.py::TestOrbitalResponseResidual` (contaminate the exact state by epsilon: residual proportional to epsilon, energy error to epsilon^2; the two zeros are pinned there too). **The test system is a scalene H3+ triangle on purpose:** H2 in a minimal basis has two orbitals of opposite g/u parity, so its energy is *even* in the rotation angle and the residual is identically zero however bad the state is — the test would pass for the wrong reason.

**The lever is the pool.** Same geometry, same h = 0.25, `gradient_tolerance=1e-4`, `max_iterations=100`:

| pool | size | ops | max grad | E-E_FCI (Ha) | dE/dkappa (Ha) | fmax (eV/Ang) | CNOTs |
|---|---|---|---|---|---|---|---|
| `ceo` | 92 | 37 | 9.1e-5 | 5.44e-4 | **1.00e-2** | 2.6257 | 1456 |
| `fermionic` | 92 | 85 | 9.4e-5 | 4.06e-4 | **2.91e-5** | 2.5696 | 8138 |
| `qubit` | 640 | 100 | 1.9e-4 | 4.05e-4 | **6.36e-5** | 2.5698 | 1226 |

`fermionic` and `qubit` cut the residual **~300x** (below `ORBITAL_RESPONSE_TOLERANCE`, so no warning) while improving the energy only 25 % — exactly the first-order/second-order asymmetry. The forces follow the residual, not the energy: the exact-FCI state gives fmax 2.5441, the two low-residual pools land within 0.026 of it, `ceo` is 0.082 off. **`pool="qubit"` is the recommendation for this system** — smallest residual-to-cost ratio and *fewer* CNOTs than `ceo` (1226 vs 1456). (The table predates the CEO correction, when `ceo` was `qeb`.) **Consequence:** the ADAPT-vs-FCI force error is **0.085 eV/Angstrom** there, ~6x the `fmax = 0.0131` the run converged to.

## `project_translation="auto"` is the default (2026-09-18)

`project_translation` can decide for itself, and the argument is a theorem rather than a heuristic: **the exact force of a free molecule sums to zero, so subtracting the mean is the orthogonal projection onto a subspace that *contains* the true answer, and an orthogonal projection can never increase the distance to a point already in the subspace.** The reported force is therefore never made worse by projecting and is usually made better, whatever the grid error happens to be. Pinned by `test_paw_forces.py::test_projection_cannot_increase_the_error_against_a_zero_sum_force`.

**What it gives up** is the identity `forces == -dE/dR` of the *discretized* energy, which genuinely is not translation invariant. That is a property of the approximation, not of the physics — but it is the property most of the force tests exist to check, so the raw array is kept: **`ForceResult.unprojected`** (backed by `details["forces_unprojected"]`, equal to `forces` when nothing was projected), alongside `details["translational_residual"]` (always the *unprojected* residual, since `_check_translational_invariance` runs first and still warns) and `details["translation_removed"]`.

`DEFAULT_PROJECT_TRANSLATION = "auto"`, `PROJECT_TRANSLATION_CHOICES = (True, False, "auto")`. `Mandacaru._projection_applies(result)` is the gate: **at least 2 atoms** (a single atom's grid re-centers on it, so its residual is zero by construction and says nothing) and **not periodic** (the sum over a cell's atoms is not the free-molecule identity; an explicit `project_translation=True` there emits a `RuntimeWarning` saying it is ignored rather than doing nothing silently). Validation is by *type* — `1 in (True, False, "auto")` is `True` in Python, so an int is refused as the typo it is.

**Consequence for recorded numbers:** every force quoted in this file before 2026-09-18 is the *unprojected* one, reproducible with `project_translation=False`. Flipping the default failed 8 tests, every one asserting a property of the raw gradient; all now read `force_result.unprojected` with a comment saying why, so the trade-off is visible at each assertion instead of hidden in a default. Policy tests: `test_fao_forces.TestTranslationProjectionPolicy`.

**When to turn it off:** validating a gradient against a finite difference, comparing against the driver's raw output, or measuring the egg-box itself. For relaxation and dynamics — where the artifact is systematic and integrates into a centre-of-mass drift — leave it on. ASE's plain `BFGS`/`FIRE` use forces only, never the energy, so projection introduces no inconsistency into the optimizer; `BFGSLineSearch`/`QuasiNewton` do use the energy, and there the projected force and the unprojected energy are mildly inconsistent by exactly the residual.

## UPAW: an option, not the default (2026-09-18)

Ivanov *et al.*, arXiv:2408.03159v2 (`~/Dropbox/UPAW.pdf`): **unitary PAW** picks pseudo partial waves with `O_ij = <phi_i|phi_j> - <phi~_i|phi~_j> = 0`, so `T+T = I`. **Mandacaru already had the knob:** `q = s * norms`, so **`norm_deficit=0` *is* UPAW** (H, Li, C, O build cleanly: `|q| <= 3e-14`, overlap minimum exactly 1, no ghosts). **Not the default, for three measured reasons:** (1) **we do not need it** — `_lowdin_x` orthogonalizes `S = S~ + C q C+` before the second-quantized Hamiltonian is built; the paper's problem is specific to plane waves. (2) **It does not remove the augmentation machinery** — the constraint fixes only the **L = 0** moment: water's oxygen `|Q^{L=0}|` 3.2e-2 -> 7.7e-15, but `|Q^{L=2}|` 1.4e-3 -> **2.2e-2 (16x larger)**; `W`, `U`, both augmentations and their force derivatives all remain. (3) **The waves are harder, and it lands on the forces** — water's net force is **5x larger** (0.380 -> 1.918 eV/Angstrom at h = 0.25) and the energy converges ~19 % more slowly in `h`. Physics agrees (LiH d_eq 1.6782 vs 1.6802 Angstrom; binding 3.2389 vs 3.1413 eV) and the LCU one-norm is unchanged (H2 1.3563 -> 1.3579 Ha), so this is a cost judgement.

**Worth taking from the paper instead** (not implemented): **down-sampling** (`E_ds(n+1) = E_ds(n) + E(n+1, n_b) - E(n, n_b)`; maps onto `BlochCalculator.total_energy(kmesh)` and the size hierarchy). `lambda = sum |c_P|` as a cost figure is now the plan's `hamiltonian_one_norm_Ha`, and double factorization is `backends/factorization.py` (see the 09-21 section).

**Shipped as the family `"upaw"`** (`basis="UPAW"`, alias `"unitary-paw"`, a registered `FamilySpec`). In `paw.py`: `UPAW_FAMILY`/`UPAW_LIBRARY_SUBDIR`, `generate_upaw(symbol, **options)` = `generate_paw(norm_deficit=0.0, ...)` tagged via `dataclasses.replace` (an explicit `norm_deficit=` is a `TypeError`), `upaw_library_path`, `get_upaw`, `build_upaw_library`, `build_upaw`, and `build_paw(..., loader=None)` so the molecular path is shared. **No library is shipped, so `get_upaw` generates on demand** (0.4-2.2 s per element, cached in `_CACHE`, warns once); an *explicit* `directory=` with a missing element raises with the `build_upaw_library` recipe — deliberate asymmetry. **Serialization:** `io.TABLE_FAMILIES` maps **family -> codec** (`"upaw": ".paw"`, not invertible); the writer stores the record's own family, `paw.from_payload` reads `payload["family"]`; a PAW file is refused as UPAW and vice versa. Pinned by `test/test_upaw.py` (17 tests, incl. **the two measurements that keep it from being promoted**); it reads Parquet, so it must not share a process with a Qiskit-transpiling test file.


## PAW egg-box: the Fourier basis filter and the exact local potential (2026-09-20)

Two independent cures for the PAW egg-box (the net force on a free molecule, i.e. the grid's broken translation invariance), **both on by default for `paw` and `upaw`** and each separately switchable. They attack different terms, and the measurement below is why both are defaults: alone the quadrature looks weak and the filter leaves the local potential as the dominant residue; together they compound.

Water, PAW-SZ, 10 Angstrom cell, ADAPT/fermionic, `project_translation=False` — net force in eV/Angstrom (ratio to the largest force):

| | neither | exact local only | filter only | **both (default)** |
|---|---|---|---|---|
| h = 0.25 | 2.3944 (0.862) | 1.7990 (0.651) | 0.1596 (0.055) | **0.0507 (0.017)** |
| h = 0.20 | 1.1579 (0.409) | 0.1511 (0.062) | 0.0450 (0.019) | **0.0021 (0.001)** |

So ~47x at h = 0.25 and ~550x at h = 0.20. Energies for the same four columns: -492.187084 / -492.164040 / -491.376101 / -491.381780 eV (h = 0.25) and -485.987612 / -486.000510 / -485.577732 / -485.578633 eV (h = 0.20). **The filter raises the energy** (+0.8 eV at h = 0.25, +0.4 at h = 0.20): it removes variational freedom the grid could not represent anyway, and most of the "cost" is the unfiltered basis's own aliasing error (a fixed-cutoff series gives 530/422/294/237 meV as h falls). Geometry barely moves: H2 0.0001, LiH 0.0002, OH 0.002 Angstrom (0.037 eV in binding).

**Fourier filter** (`src/mandacaru/basis/filtering.py`). Every radial table of the pseudo basis is transformed per `l` with a spherical-Bessel transform (`TRANSFORM_OVERSAMPLE = 8`), multiplied by a raised-cosine `cutoff_window` (1 below 0.75 k_c, 0 at k_c), transformed back, switched off smoothly in real space out to `SWITCH_MARGIN = 1.5` x the original `support_radius` (`DEFAULT_FILTER_METHOD = "switch"`; `"plain"` and `"mask"` exist in `FILTER_METHODS` — **the mask method measured worse than no filter on long-ranged functions**, do not promote it) and renormalized to the table's own norm (`filter_radial` / `filter_table`). The cutoff is `k_c = FILTER_NYQUIST_FRACTION (1.0) x pi/h` of the **coarsest** grid axis. `band_weight` / `residual_weight` measure what is lost, and above `FILTER_WEIGHT_WARN = 0.05` a `RuntimeWarning` says the grid is too coarse for that function. The basis option is **`filter`**: `True` / `"auto"` (grid Nyquist), a number (cutoff **in eV**), `False` / `None` (off) — `validate_filter`, `filter_cutoff`, `filter_label`. Defaults are per family through the new **`FamilySpec.default_options`** with `FamilySpec.resolved_options(options)` as the *single* merge point (every default key must be in `options`, checked in `__post_init__`): `{"filter": True}` for `paw` / `upaw`, nothing for `ncpp` / `oncvpsp` (their projectors are still grid-sampled, so filtering the basis alone is not the same win — not measured as a default there). The dry-run label always names the filter state, and the builder's `context["filter_cutoff"]` records the cutoff used. ## The CEO pool, corrected to the paper (2026-09-20)

`ceo` was **identical to `qeb`** under JW at every size (verified term for term, 4 to 16 qubits) and, under parity / BK, summed QEB generators sharing a *mapped* support -- an artifact measuring strictly worse than `qeb` on LiH (0.063 eV off FCI against 1.5e-10; 1352 / 666 CNOTs against 238 / 258). Corrected against **Ramoa et al., npj Quantum Inf. 11, 86 (2025)** (PDF under `~/Dropbox/2.Library/`); its Eqs. (11), (12), (25), (26) are reproduced **sign for sign** by `qubit_excitation` (pinned by `TestCEOGrouping.test_the_paper_equations`).

**The construction.** A CEO couples the qubit excitations acting on **one set of spin-orbitals**, which works because every double QE on a 4-set is a uniformly weighted combination of *the same eight Pauli strings*, differing only in signs: coupling costs no extra entangling structure, and a sum or difference collapses to **four** strings where a QE needs eight. Of the three ways to pair four spin-orbitals only the Sz-conserving ones are excitations: **two** for a 2-alpha-2-beta set, **three** for a same-spin set; a same-spin pair carries one single. The pool (Eqs. 23-24) holds all `2*C(k,2)` sums and differences per set -- 2 per opposite-spin set, 6 per same-spin one -- plus every single, trivially its own CEO.

**The load-bearing point: CEO uses GENERALIZED excitations.** The paper's QE pool is generalized too ("generalized excitations instead of restricting the source/target orbitals to be occupied/unoccupied in the reference state", Sec. II A 3) -- which is why its supports carry several QEs. **With the occ/virt restriction each set carries one excitation and CEO degenerates into QEB**; that restriction was the whole bug. `CEOPool.excitations()` enumerates all same-spin pairs and all Sz-conserving pairings of every 4-subset, ignoring occupancy. `QEBPool` keeps its occ/virt restriction (a documented difference from the paper's QE pool). Pool sizes: H2 4 (qeb 3), LiH 24 (8), BeH2 96 (26), **H2O-fc 660 (92)** -- the same measurement cost, the gradients being linear combinations of the same Pauli expectations.

**Growth is the paper's modified step 3** (`PoolBase.grown_operators(selected, gradient)` -> `[selected]`; `CEOPool` overrides): append the selected OVP-CEO as one parameter when only one coupled excitation is live (`GRADIENT_FLOOR = 1e-12`), else append the live excitations with **independent parameters** (the MVP-CEO). They commute **exactly**, so appending them in sequence *is* `exp(sum_i theta_i T_i)` -- no multi-parameter ansatz block was needed. Plumbing: `ADAPTVQE._operator_matrix` / `_operator_gradient` (one operator in the run's dense / sparse / sector representation) and `_grow(ansatz, selected, op, gradient)`, called from `run()`, `_grow_deflated` and `SubspaceADAPTVQE._subspace_optimize`, each with its own gradient (plain, deflated, weighted); `_optimize_grown(cost, previous, n_new=1)` now adds `n_new` zeros. **Consequence:** for `ceo` the parameter count can exceed the iteration count (BeH2: 21 growth steps, 4 of them MVP, 25 parameters). `max_iterations` still counts operators, and the iteration row names the *selected* OVP-CEO while `selected` and the ansatz carry what was appended.

**Measured** (FAO, h = 0.30, L-BFGS-B): same energy and operator count as `qeb`, **roughly half the CNOTs** -- H2 48 -> 24 (JW), LiH 208 -> 112 (JW), 238 -> 134 (parity), the generic `{cx, u}` compilation already benefiting from 4 strings instead of 8. Every generator conserves N and Sz in every encoding and **all are circuit-exportable**; `supports_parity_reduced` stays True.

**`"ceo-ovp"` is the variant that pays off here** (`OVPCEOPool`, the paper's one-parameter variant of Supplementary Sec. I; alias `"ovp-ceo"`, and `"ceo-ovp"` is no longer an alias of `"ceo"`). Same pool; `grown_operators` never expands. **Why:** without the paper's MVP circuit an expanded step compiles as 2-3 separate eight-string excitations and *costs* gates. LiH / STO-3G, 12 qubits, the hardware example's settings: `qeb` 204-208 CNOTs, adaptive `ceo` **248-324**, `ceo-ovp` **104-112** -- all within 1.5e-5 eV. `examples/24_ADAPTVQE_LiH_IBM.py` uses `ceo-ovp` and records `cnot_count` / `circuit_depth`. **Its `examples/data/lih_dissociation_ibm.csv` is a real `ibm_kingston` run (job `daibf41hvn6c73ct0ojg`, 4096 shots) whose measured columns predate the pool change -- never run that example with `HARDWARE = None`, it would overwrite them** (verify in a redirected copy: local energies move < 1.5e-5 eV, circuits halve).

**Not implemented:** the paper's specialized 9-CNOT (OVP) and 13-CNOT (MVP) syntheses of Figs. 5-9. `TestR07CommutingTermsOnly` was rewritten: the `pauli_rotations` commutation guard stays (pinned with a hand-built anticommuting generator), no pool generator trips it now. Pinned by `test/test_pool_encoding.py::TestCEOGrouping` (the paper's equations, the size formula per mapping, the 4-string doubles, commutation, Sz conservation, step 3's OVP/MVP branch).

## Growth strategies: TETRIS and pruning (2026-09-20)

Two literature refinements of *how* the ansatz grows, both **off by default**, independent of each other and of the pool, on `ADAPTVQE` (so `Mandacaru(method="adapt-vqe", tetris=…, prune=…)`; the other methods refuse them through `_check_solver_options`, and a non-bool is refused in the constructor — `prune=1` is the typo it looks like).

**`tetris=True`** — TETRIS-ADAPT-VQE (Anastasiou *et al.*, Phys. Rev. Research **6**, 013254, 2024). `_select_disjoint(grads)` walks the pool in descending |gradient| and appends every operator whose support is disjoint from those already taken this step, stopping when the register is covered or nothing disjoint is left above `GRADIENT_FLOOR`; it falls back to `[argmax]`, so it is never worse than the plain rule. **Free**: the gradients were screened anyway, and the operators act on different qubits, so they occupy one circuit layer.

**`prune=True`** — Pruned-ADAPT-VQE (J. Chem. Theory Comput. **21**, 8720, 2025). `_prune_ansatz` ranks the ansatz by `f_i = exp(-PRUNE_ALPHA x_i) / theta_i^2` (`PRUNE_ALPHA = 10`, `x_i = i/N`) — small amplitude, early position — and removes the top-ranked operator only if `|theta| < PRUNE_FRACTION (0.1) * mean(|theta|)` over the `PRUNE_RECENT = 4` most recent ones; recently added operators legitimately have small parameters, which is why the threshold is measured against *them*. The newest operator is never pruned (it was just selected on the largest gradient) and nothing is pruned below `PRUNE_MIN_OPERATORS = 2`. Parameters are not re-optimized — the removed operator was doing almost nothing — but the energy is re-evaluated. Needs `AdaptAnsatz.remove(index)`, which pops the index-aligned caches rather than rebuilding.

**A stall this required guarding.** The loop counts *operators* (`len(selected) < max_iterations`), and pruning can hand back the operator the next step re-selects — the paper reports exactly that near convergence — which leaves the count unchanged forever. Growth steps therefore carry their own budget, `PRUNE_STEP_BUDGET (3) * max_iterations`, when pruning is on.

**Measured against a *tightly converged* inner optimizer** (see the optimizer section — the original measurements used a loose one and overstated both methods). TETRIS pays in **growth steps**, not gates: H4/qeb depth 463 → 399 in 8 steps instead of 17 at 58 % fewer evaluations; BeH2/qeb the same 9-operator circuit in 7 steps instead of 9. **Pruning has nothing to remove** once every amplitude matters; against a loose `tol=1e-8` it still cuts BeH2 from 15 operators / 412 CNOTs to 10 / 260. `[OPTIMIZATION SETUP]` records `growth:` / `pruning:`, and `ADAPTVQEResult.pruned_operators` lists what was removed. Pinned by `test/test_growth_strategies.py` (17 tests, 19 s), which pins **both** regimes.

**Other papers in `~/Dropbox/2.Library/.../ADAPT-VQE/`, surveyed and not implemented:** operator **pool tiling** (Phys. Rev. Research 6, L012030, 2024 — learn the useful operators on a small instance, tile them for the large one; the obvious answer to CEO's 660-operator screening and a natural fit for `BlochCalculator`), **qubit-encoded pools for periodic systems** (JCTC 21, 5973, 2025, with variance extrapolation), and **double unitary downfolding** (JCTC 21, 8799, 2025 — correlation outside the active space at no extra qubits; the largest accuracy-per-qubit prize and the biggest project). Floquet-ADAPT and the Schwinger-model surrogate are out of scope. The minimal complete pool of Tang *et al.* was implemented as a prototype and **rejected**: its 2n-2 operators are at most 2-local, so every gradient vanishes at |HF> (a 1-qubit flip changes N, a 2-qubit flip is a single excitation, zero by Brillouin in the RHF basis) and ADAPT stops at zero operators reporting `converged=True`; seeded with one 4-local string it fixes H2 but traps on LiH (200 operators, still 0.18 eV off).

## Volumetric output: `.cube` / `.xsf` of the variational state (2026-09-20)

**A many-electron state has 3N coordinates and cannot be put in a volumetric file**; what is written are its exact **one-particle reductions**, built from the 1-RDM, the MO coefficients and the run's *actual* basis functions on the calculation's own grid — the docs say so and new text must not call it "the wavefunction". API, on `Mandacaru` only: `calc.write_cube(path, quantity="density", index=None, state=None, component=, grid=, format=)` -> `VolumetricField` (`integral`, `norm`, `occupation`, `n_electrons`, `augmentation_charge`, `output_path`, `summary()`, `write()`), `calc.volumetric_field(...)` (no file) and `calc.natural_orbitals()` (occupations + coefficients). Quantities: `density`, `alpha_density`, `beta_density`, `spin_density`, `difference_density` (n - n_HF), `natural_orbital`, `molecular_orbital`. `state=` is an index into a subspace result's `states` or an explicit state vector (how `energy_levels().states[i]` is drawn). Direct mode (no basis) is refused. Modules: `algorithms/volumetric.py` (`volumetric_field(integrals, gamma, ...)`, `state_natural_orbitals`, `OrbitalExpansion`, `spin_resolved_rdm`, `reference_occupations` — testable without a solver) and `utils/cube.py` (`write_cube` / `write_xsf` / `write_volumetric` / `detect_format`). It reuses the forces' RDM pipeline: `Mandacaru._state_rdms(psi=None, two_body=True)` gained those two arguments (defaults byte-identical; a density never builds the O(M^4) 2-RDM), so frozen cores, `parity_reduced` registers and sector runs all work (densities agree to 3e-17).

**Do not use `ase.io.cube.write_cube` for this grid**: it derives the voxels from `atoms.cell / n` and writes `atoms.positions`, while Mandacaru's grid is centered on the molecule with `n = round(L/h) + 1` nodes and a 3x3 `step` matrix — every nucleus would land in the wrong place. The writer here takes `origin = node (0,0,0)`, the columns of `grid.step` as voxel vectors (Bohr) and the nuclei from `integrals._potentials.nuclei` (the `coherent_positions` frame the basis functions sit in); `.xsf` does go through ASE (`origin` / `span_vectors`). Alignment is pinned for a molecule **not** centered in its cell and for a skewed grid. Validated: integral of n = 2.0000000000 (H2/FAO), 4.0 (LiH, frozen core refilled), H3 doublet spin density 1.0; H2 natural-orbital occupations (1.9749, 0.0251) at 0.74 Angstrom -> (1.3149, 0.6851) at 2.50, HF exactly (2, 0); cube round trip 4.8e-7. **PAW writes the smooth *pseudo valence* density**, which does not integrate to N: grid 1.943466 + augmentation 0.056534 = 2 for H2-SZ — tests pin that *identity*, not literals. Left out on purpose: all-electron reconstruction inside the spheres (`reconstruct_ae` is radial only), a `--cube` CLI flag. `test/test_volumetric.py` (47 tests, 5 s), guide `docs/source/guide/visualization.md` (VESTA / VMD instructions), `examples/32_wavefunction_cube.py` -> `examples/data/h2_stretched_*.cube` (120 kB each) and `h2_cube_slice.png` (density and n_ADAPT - n_HF of stretched H2: gain on the nuclei, loss in the bond).

## `references.bib`: the run cites itself (2026-09-20)

A run writes the BibTeX of the methods it used, so a paper's bibliography is not assembled from memory. **Two modules, deliberately separate:** `utils/bibliography.py` is the **data table** — one `Reference(key, entry, note, verified, topics)` per method, pool, mapping, basis family, optimizer and code (45 entries), with **abbreviated journal names** (`Nat. Commun.`, `Phys. Rev. B`) and `bibtex(keys, header=)` / `resolve(keys)` (an unknown key **raises**, never drops silently). `utils/citations.py` is the **selector**: `citation_keys(method=, pool=, mapping=, basis=, family=, basis_options=, optimizer=, backend_provider=, shots=, execute_circuits=, profile=, tetris=, prune=, has_geometry=, built_basis=, extras=)` plus `resolve_references_path`, `write_references` (atomic). Adding a paper edits the table; teaching an option to cite it edits the selector.

**It cites what ran, not what was typed.** `_citation_config()` reads the *built* pool object's `name` and the Hamiltonian builder's `context["family"]` / `context["options"]` (family defaults filled in), so `basis={"name": "PAW", "size": "SZ"}` cites Bloechl **and** Anglada-Soler (the default filter) **and** Sankey-Niklewski + Junquera (the default `energy_shift`). `"ceo"` cites Ramoa 2025 *and* Yordanov 2021 (the qubit excitations it couples); `tetris`/`prune` are cited only when on; Qiskit only when circuits went through it. What configuration cannot know is added when it happens: `_cite(*keys)` (`energy_levels` -> Higgott2019, `_expressivity` -> Sim2019) refreshes a file already on disk.

**The option is `references=`** on `VariationalDriver` (so every method, forwarded through `Mandacaru`): **`"auto"` (default)** writes `references.bib` **beside the `txt=` log and nothing when there is no log**, `True` writes it in the cwd, a string names it, `False` is off. A bad value raises at construction (`references_path` is a **property**, resolved on demand), the path joins `_check_output_paths`, a dry run writes nothing, and a write failure is a `RuntimeWarning` — never the end of a calculation. Public: `calc.citation_keys()`, `calc.write_references(path)`, `calc.references_written`; CLI `--references PATH`. Each driver declares `citation_method` (`"adapt-vqe"`, `"vqe"`, ...).

**Provenance is explicit.** The ADAPT-VQE family (Grimsley 2019, Tang 2021, Yordanov 2021, Ramoa 2025, Anastasiou 2024, Vaquero-Sabater 2025) was read from the PDFs in `~/Dropbox/2.Library/.../ADAPT-VQE/`; everything else is `verified=False`, listed in `UNVERIFIED` and rendered with an `[unverified record]` comment. **Verify one before it goes into a manuscript, and flip its flag when you do.** Pinned by `test/test_bibliography.py` (47 tests) — including **registry sweeps** that fail when a new pool / mapping / optimizer / family / method has no paper, and a regex that fails on an unabbreviated journal name. Guide section in `docs/source/guide/run_output.md`.

## Classical optimizers: steps, and the comparison (2026-09-20)

**A step is not an evaluation, and the log now says both.** `OptimizeResult.nit` is the optimizer's **parameter updates**; `nfev` its **cost evaluations** (what a QPU is billed for). They differ by the method — L-BFGS-B spends several per step (finite-difference gradient + line search), Adam `2N + 1`, SPSA 3, COBYLA ~1 — so reporting one flatters one family and slanders the other. Sources: SciPy's `res.nit` where it exists, else a tally from a `callback=` passed to `minimize` — **COBYLA, the default, is exactly the method with no `nit`** (pinned) ; SPSA/Adam return their loop count. `_optimize_grown` forwards it; `_optimize_all`'s `quenching=False` sweep **sums** the per-parameter searches.

Plumbing: `AdaptIteration.optimizer_steps` / `.num_evaluations` (per growth step), `ADAPTVQEResult.optimizer_steps` (total; restored and re-serialized through the checkpoint `status`), the **`steps` column** of `[ITERATIONS]` and of the stdout trace (`_ITERATION_DROP_ORDER` = `dE, 1q, depth, steps, cnot` — steps before cnot because the classical effort is reconstructible from the summary total and `[PERFORMANCE]`), `optimizer_steps:` beside `cost_evaluations:` in `[VARIATIONAL QUANTUM SUMMARY]`, and `parse_output` reading the column back (`"-"` both when a method reports none *and* when an older log has no such column). Pinned by `test/test_optimizer_steps.py` (26 tests, 2 s); `test_adapt_args_gradient.py::test_a_wide_terminal_keeps_every_column` gained the column.

**Three spellings of `optimizer=`, all equivalent** (`resolve_optimizer`): a method **name** (the library's budget and tolerance), a **dict** of `OPTIMIZER_KEYS = ("method", "maxiter", "tol", "options", "seed")` — `optimizer={"method": "SLSQP", "maxiter": 2000, "tol": 1e-12}`, so a script never has to import `Optimizer`; keys left out keep their defaults, an unknown key raises, and the method name goes through the same `_check_method` as the string form — or an **`Optimizer`**, which is what the dict builds. **Every example uses the dict** (user directive 2026-09-20) and none of them imports `Optimizer` any more; the **tests** keep module-level `Optimizer` constants, which is the right tool for a configuration reused across a file. Pinned by `test_optimizer_steps.TestTheDictForm`.

**The defaults are explicit** (user directive 2026-09-20). **`DEFAULT_OPTIMIZER = "SLSQP"`**, `DEFAULT_MAXITER = 1000`, **`DEFAULT_TOL = 1e-12`** (all exported from `mandacaru.optimizers`), used by `Optimizer()`, `resolve_optimizer(..., tol=)` and every driver. **Every example, test and docs snippet writes `Optimizer(method=..., maxiter=..., tol=...)` out** — tests hoist it into a module constant (`LBFGSB`, `COBYLA_OPT`) right after the imports with a comment saying why; `test_named_optimizers_build` deliberately keeps the bare-string path, and `test_an_old_log_still_reads_back`'s fixture keeps its literal `COBYLA`.

**The tolerance is chosen *with* the method and must stay tight.** `tol` means different things per method: for **SLSQP and COBYLA it is a function-value criterion**, so it has to be tighter than a gradient method's to leave an equally small gradient — and **ADAPT's convergence test reads exactly that residual gradient**. At `tol=1e-8` SLSQP reaches the H2/FAO ground state to 1e-10 eV but leaves `max|g| = 4.6e-06` against `gradient_tolerance=1e-6`, so the growth loop never stops and piles up **50 redundant operators**; at `1e-12` the same run converges after **one** operator in 4 steps / 9 evaluations. SciPy's own defaults are worse still (Nelder-Mead `xatol = fatol = 1e-4`), and `tol=None` leaves native SPSA/Adam nothing to certify against.

**What the tighter tolerance broke, and what it revealed.** `test_checkpoint.py`'s ADAPT-resume tests ran on H2/FAO/qeb expecting 2-6 growth steps; with `tol=1e-8` the **first** operator nails the angle and ADAPT converges after **one** — H2 in a minimal basis is exactly one double excitation from its ground state, so the old multi-step behavior was the optimizer being sloppy. They moved to **LiH** (six operators, 0.1 s) via a new `lih()` helper; `TestRecord` keeps its own `h2_run` fixture, whose assertions name the 4-qubit register. The VQE warm-start test compares against a cold run instead of pinning `< 10` evaluations (a tight tolerance still spends a gradient confirming it is at the optimum), and `test_convergence_status` needed `Optimizer(method="SPSA", maxiter=20, tol=None)` — no tolerance is now the *only* way to get an uncertified native run.

**The comparison** (`examples/33_optimizer_comparison.py` with a `SYSTEM` switch, guide `docs/source/guide/optimizers.md`, data `examples/data/{lih,h2o,h2o_qeb}_optimizers.csv`). **LiH** 1.6 Å, FAO, `pool="qubit"`, JW, 6 qubits, `max_iterations=12`, at the shipped defaults; FCI −162.953987 eV — steps / evaluations / operators / E−FCI (eV) / CNOTs / s / converged: SPSA 11377 / 34143 / 12 / 5.4e-5 / 66 / 2.5 / no; COBYLA 4247 / 5470 / 12 / 4.8e-6 / 66 / 2.8 / yes; Nelder-Mead 3270 / 5935 / 10 / 7.2e-7 / 60 / 0.5 / yes; **SLSQP 76 / 632 / 10 / 7.2e-7 / 60 / 0.1 / yes**; Adam 9427 / 118291 / 10 / 7.2e-7 / 60 / 6.4 / yes; L-BFGS-B 85 / 844 / 10 / 7.2e-7 / 60 / 0.2 / yes. **SLSQP wins on every axis.**

**H2O/PAW-SZ, h = 0.25, `pool="qubit"`, 12 qubits / 640 operators, `max_iterations=40` (sector FCI −492.521982 eV) — identical at `tol` 1e-8 and 1e-12, every inner optimization being `maxiter`-limited** — steps / evaluations / E−FCI / CNOTs / s / uncertified: SPSA 77454 / 232402 / 1.38e-2 / 538 / 166.1 / 38; COBYLA 23273 / 34184 / 9.64e-3 / 486 / 54.5 / 10; Nelder-Mead 59751 / 77245 / 9.67e-3 / 488 / 66.1 / 24; **SLSQP 236 / 6244 / 9.64e-3 / 486 / 8.3 / 0**; Adam 15703 / 746747 / 9.64e-3 / 490 / 784.6 / 2; **L-BFGS-B 166 / 5912 / 9.72e-3 / 486 / 10.8 / 0**. Everything but SPSA lands on the same circuit (486-490 CNOTs), so the choice is cost — SLSQP spends a twentieth of a direct search's evaluations. With `pool="qeb"`, which *converges* (ops / CNOTs / s): COBYLA 30 / 1168 / 19.0, Nelder-Mead 31 / 1216 / 33.8, **SLSQP 30 / 1168 / 5.6**, L-BFGS-B 31 / 1172 / 5.1, Adam 30 / 1168 / 215.5, SPSA 60 (cap) / 1288 / 299.5.

**Three more methods (2026-09-21):** `"BFGS"`, `"L-BFGS"`, `"NLCG-PR"` (Polak-Ribiere conjugate gradient). `_SCIPY_ALIASES` maps the last two onto SciPy's `"L-BFGS-B"` and `"CG"` — **`L-BFGS` *is* `L-BFGS-B` without bounds**, which the driver never passes, and SciPy's `CG` is Polak-Ribiere+. Citations `Fletcher1970` / `Liu1989`+`Byrd1995` / `Polak1969`. **`_GRADIENT_NORM_METHODS = ("BFGS", "NLCG-PR")`:** SciPy reads `tol` as `gtol` there, and `1e-12` is below a finite-difference gradient's own ~`1e-8` accuracy — every line search then ends in "precision loss" and `optimizer_failures` fires at *every* growth step while the state sits on the minimum. `minimize` passes `sqrt(tol)` instead (near a minimum `f-f* ~ |g|²/2λ`), unless `options={"gtol": …}` was written. LiH: BFGS 80 steps/1066 evals, L-BFGS 85/844 (= L-BFGS-B), NLCG-PR 137/2339 — all reaching SLSQP's -162.953986 eV and 60-CNOT circuit (76/632), all certified.

**Rule of thumb:** state vector → the `SLSQP` default or any quasi-Newton method (1-2 orders of magnitude fewer steps, the only family that certified every growth step on water) **with `tol` kept tight**; `shots > 0` → `SPSA` / `COBYLA` (no derivative through shot noise); a **stationary starting point** → a direct search, since a gradient method cannot leave one and correctly reports convergence there (ADAPT never hits this — its screening only selects a non-zero gradient — but a hand-built fixed ansatz can, which is why `TestR05CustomAnsatz` names Nelder-Mead); cost-limited → read `cost_evaluations`, not `optimizer_steps`.

**Three things the tighter default revealed, all now pinned.** (1) **H2/FAO/qeb converges in ONE operator** — it is exactly one double excitation from its ground state — so `test_checkpoint.py`'s resume tests moved to LiH (six operators). (2) **BeH2 reaches 9 operators / 256 CNOTs** instead of 15 / 412, so **pruning has nothing left to remove**: it was compensating for an under-converged inner optimizer, not for a redundancy of ADAPT. `test_growth_strategies` now pins both regimes — `test_it_compacts_an_ansatz_a_loose_optimizer_left_behind` (an explicit `LOOSE = tol=1e-8`) and `test_a_tightly_converged_ansatz_has_nothing_to_prune`. TETRIS still pays, in *growth steps* rather than gates: H4 depth 463 → 399 with 8 steps instead of 17 and 58 % fewer evaluations; on BeH2 the same circuit in 7 steps instead of 9. (3) **`tol=1e-12` costs 15x the wall time in the PAW force tests** (255 s against 17 s for one test) for no change in what they measure — they compare an analytic gradient against a finite difference of the *same* state, so `test_{paw_forces,paw_exact_local,fao_forces,all_electron_forces}.py` keep `tol=1e-8` with a comment saying why. **Do not sweep them back to the default.**

## Partial charges and magnetic moments (2026-09-20)

**An atom in a molecule has no boundary**, so every partial charge is a *convention* — a weight `w_A(r)` with `sum_A w_A = 1`, `N_A = int w_A n`, `q_A = Z_A - N_A`. `algorithms/charges.py` implements three (`PARTITION_METHODS`) and the docs make them disagree on purpose (LiH/FAO h=0.20: Li **+0.689 / +0.803 / +0.924** for hirshfeld / voronoi / bader). **What is *not* a convention** and comes out identical from all three: `sum(charges)` = the system charge, and `int (n_a - n_b) = N_a - N_b` — which is why **`get_total_magnetic_moment()` takes no `method`** (pinned by a signature test).

- **`hirshfeld`** (default): stockholder `w_A = n_A^0 / sum_B n_B^0`, the free atoms solved on demand by `basis/atomic_solver.solve_atom` and cached (`free_atom_density`, `_REFERENCE_CACHE`) — nothing tabulated. Where the promolecule underflows (`PROMOLECULE_FLOOR`) the weights fall back to Voronoi rather than 0/0.
- **`voronoi`**: nearest nucleus, **ties split evenly** (`VORONOI_TIE`). Not cosmetic: a symmetric dimer puts a whole node layer on the dividing plane, and giving it to the lower index charges H2 by **0.16 e** at h=0.25 and by nothing at h=0.15.
- **`bader`**: on-grid steepest ascent (Henkelman 2006) — `_ascent` picks the steepest *rise per unit distance* (so a diagonal neighbour is not favored for being farther), then **pointer doubling** `p <- p[p]` resolves every node to its maximum in O(log N) instead of walking paths. Separatrix ties are split the same way (`BADER_TIE`), which halves the artifact (0.157 -> 0.098 e) but cannot remove it — a node *off* the boundary whose path crosses it still goes one way. **H2 artifact by h: 0.30 -> ±1.0 (one basin!), 0.25 -> 0.098, 0.20 -> 0.092, 0.15 -> 0.** Hirshfeld and Voronoi are exactly 0 at every h.
- **`h = 0.30` merges the two protons into one basin and hands an atom zero electrons** — the one silent catastrophe, so `bader_weights` raises a `RuntimeWarning` naming the starved atoms. Bader is the partition that most repays a fine grid.

**Three load-bearing details.** (1) **`integrals._potentials.nuclei` is the Bohr frame**; `integrals.nuclei` is in the integrals' `units` (Angstrom), and using it displaced every nucleus by 1.889 — symmetric H2 came out **±0.32**. The symmetric-dimer test is what caught it and is the regression. (2) A **pseudopotential** run is measured against a **valence** promolecule (`reference_subshells`, detected from `_potentials.pseudopotentials`, not from `Z_val != Z` — they agree for H and He), and the **PAW augmentation is added back per atom** from `C_A q_A C_A^+`, which is block-diagonal over `projector_blocks` so the split is exact; `grid_electrons` then hits N to 1e-8. (3) A **frozen core is refilled** through `spin_resolved_rdm`, so `_spin_moment` takes the **total** `len(integrals.basis)`, not `solver.n_spatial_orbitals` (the active count — passing it raised on LiH frozen-core).

**API.** `Mandacaru.atomic_partition(method)` -> `AtomicPartition` (populations, charges, moments, `reference_charges`, `augmentation`, `notes`, `summary()`) computed once; `get_charges(atoms=None, method=None)`, `get_magnetic_moments(...)`, `get_total_magnetic_moment()` and ASE's own `get_magnetic_moment()` are the views, and each stores into `results` so ASE's accessors work. **`population=` (default `None`, `True` = hirshfeld) fills `charges`/`magmoms`/`magmom` on every `calculate()`** — which is what puts them in a written file: ASE's extxyz writer makes per-atom results **columns** (`charge:R:1` — *singular*, ASE's spelling — and `magmoms:R:1`) and scalars **header** keys (`magmom=` beside `energy=`), and `ase.io.read` recovers all of them. It is off by default because the partition costs a grid pass a relaxation has no use for, and it sets the getters' default method so a Bader run does not quietly report Hirshfeld. A failed analysis warns and keeps the energy. Pinned by `test/test_charges.py` (51 tests, 16 s); guide `docs/source/guide/charges.md`.
