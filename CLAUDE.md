# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Carcará** is a framework for fermionic quantum simulation based on variational quantum algorithms (VQAs), targeting real NISQ-era quantum hardware (IBM Quantum via Qiskit). The intended end-to-end pipeline is: fermionic system → second-quantized Hamiltonian → qubit (Pauli) Hamiltonian → parameterized ansatz → VQA optimization → QPU/simulator execution → error mitigation. See `plan/roadmap.md` for the full phased design and its flagship algorithm, **ADAPT-VQE** with pluggable operator pools (fermionic / qubit / QEB / CEO), plus its **excited-state** extensions (deflation / subspace-search) and the stochastic **VASQE** variant.

**Important:** the project is mid-build. Implemented end-to-end: localized bases (FAO / NAO / STO-nG / 6-31G(d)) **and a periodic plane-wave basis** → real-space (and reciprocal-space, for PW) integral engine → second-quantized `Fermion` Hamiltonian → fermion-to-qubit mappings → **UCCSD ansatz → VQE** and **ADAPT-VQE** (both exact state-vector solvers, validated on H₂), with **RHF/UHF** for the molecular-orbital basis. Also implemented: **excited states** (`energy_levels` via variational deflation, and `SubspaceVQE`/`SubspaceADAPTVQE` subspace-search), the stochastic **VASQE** (softmax operator selection with temperature annealing), and the periodic-system **`BlochCalculator`** (band structure + BvK total energy, `method="vqe"|"adapt-vqe"|"vasqe"`). All solvers share a common **`VariationalDriver`** base (`algorithms/base.py`) with the excited-state methods as composable mixins. **The single user-facing entry point is `QuantumCalculator(method=..., ...)`** (`algorithms/calculator.py`) — an ASE calculator selecting the solver by the `method` string (`"vqe"`, `"adapt-vqe"`, `"vasqe"`, `"subspace-vqe"`, `"subspace-adapt-vqe"`, `"subspace-vasqe"`), forwarding all solver options, and exposing the run result uniformly on `.result` (plus `.solver`/`.hamiltonian`/`.n_qubits`/`.num_particles`, direct-mode `run()`, and `energy_levels()`); the solver classes remain the internal layer. The `backends/hardware.py` device registry is written (`AER_simulator` runnable, `ibm-quantum` reserved); **still an empty stub: error mitigation** (`backends/mitigation.py`). Before building on a module, check whether it actually has code (`wc -l`), because `plan/roadmap.md` mostly describes intended design and its later phases (real-hardware execution, mitigation) are not yet written. `pyproject.toml` is the source of truth for the build (currently Python ≥ 3.11).

## Current state of the code

Implemented:
- `src/carcara/basis/` — localized single-particle basis functions (`BasisFunction` ABC) and three concrete families: `FullAtomicOrbital` (analytic, with Slater charges), `NumericalAtomicOrbital` (confined Sankey/SIESTA-type, `nao.py`), `GaussianOrbital` (contracted GTOs, `gaussian.py`). **All families are generated natively from scratch — no tabulated/external basis-set data.** The `BasisSet` factory (`factory.py`) builds `"FAO"` (Full Atomic Orbitals; one analytic orbital per occupied subshell, carrying the **actual atomic number Z** as the orbital's nuclear charge — the bare hydrogenic orbital, no Slater screening), `"STO-3G"`, `"NAO"`, `"GTO"` and `"6-31G"`/`"6-31G(d)"` bases. The GTO family is a minimal **STO-nG** basis generated in `sto_ng.py` by least-squares fitting `n_gaussians` primitives to the Slater-type orbital of each occupied subshell (Slater's-rules ζ = (Z−S)/n\*), with the reference fit done once at ζ=1 (cached, `_fit_reference`) and exponents rescaled by ζ². `BasisSet.build(method="GTO", n_gaussians=3)` → STO-3G-like; the fit reproduces published STO-nG exponents closely (H 1s → 2.22766/0.40577/0.10982). The **Pople split-valence** family (`pople.py`) reuses that fit to build 6-31G(d): 6-primitive cores, 3+1 split valence, and a native (Slater-heuristic) `d` polarization shell on non-H atoms. Shared aufbau config in `_config.py`, angular helpers in `_angular.py`. `_config.valence_subshells` returns the highest-`n` occupied subshells **plus the semicore `(n-1)d` / `(n-2)f`** when occupied, so Fe is `3d⁶4s²` (8 valence electrons) rather than a 2-electron `4s²` atom — this feeds both the basis and pseudopotential generation.
- `src/carcara/basis/multizeta.py` — **multiple-zeta and polarized NAOs**, selected by `BasisSet.build("NAO", size=...)` or `basis={"name":"NAO","size":"DZP","energy_shift":0.03}` (all `NAOBasisSet` options — `size`, `energy_shift`, `r_c`, `n_grid`, `split_norm` — pass through the dict). `ZETA_NAMES` covers `SZ`/`SZP`/`DZ`/`DZP`/`DZ2P`/`TZ`/`TZP`/`TZ2P`/`QZ`/`QZP`/`QZ2P` (or an explicit `(n_zeta, n_polarization)` pair); **the default is `DEFAULT_NAO_SIZE = "DZP"`** — `size="SZ"` is opt-in and keeps the original `NumericalAtomicOrbital` path byte-for-byte. Extra zetas use the **SIESTA split-valence** construction (`split_radius`/`split_valence_tail`): pick `r_s` leaving `split_norm` (0.15) of the norm outside, replace the inside by `r^l(a−b r²)` matched in value *and* slope at `r_s`, keep the difference — each zeta is strictly shorter-ranged than the last (H 1s: 3.99 → 2.09 → 1.22 → 0.81 a₀). Polarization adds a whole `l_max+1` shell solved in the same confining sphere (3 functions for s-valence, 5 for p, 7 for d). All orbitals become `TabulatedOrbital` (`R(r)·Y_lm` off a spline), so the integral engine sees them identically. **Caveat worth knowing:** high zetas are short-ranged by construction and the real-space grid must resolve them — the 3rd H zeta spans 0.65 Å ≈ 3 points at `h=0.20 Å` and contributes ~1e-6 Ha (3.6e-5 at `h=0.12`). DZP is the practical sweet spot; TZ/QZ need a fine grid to be worth anything.
- `src/carcara/integrals/` — real-space one- and two-body integral engine, grid, FFT Poisson solver, C backend binding
- `src/carcara/core/` — the second-quantized layer. `mapping.py`: `Fermion` (fermionic ladder operators with full algebra and a `from_integrals` builder for `H = Σ h_pq a†_p a_q + ½ Σ ⟨pq|rs⟩ a†_p a†_q a_s a_r`), `PauliSum` (the qubit-operator output type, with `to_sparse_pauli_op`), and the three fermion-to-qubit mappings — **Jordan-Wigner** (default), **parity** (with optional two-qubit reduction) and **Bravyi-Kitaev** — via a shared encoding-matrix construction (`map_to_qubits(method=...)`). `hamiltonian.py`: `MolecularIntegrals` drives the integral engine to build the spin-orbital molecular Hamiltonian as a `Fermion`. `planewave.py`: `PlaneWaveIntegrals` — a **periodic plane-wave basis** (`{"name":"PW","energy_cutoff":300}`; eV, default 300) computing the reciprocal-space one-/two-body integrals with PBC (diagonal kinetic `½|G|²`, structure-factor external potential, momentum-conserving `4π/Ω/|G_p−G_r|²` electron repulsion, G=0 removed by jellium), mirroring the `MolecularIntegrals` interface (`molecular_hamiltonian`, `hartree_fock`, `integration_profile`). It guards against an intractable O(N⁴) tensor via `max_plane_waves` (default 60) — a realistic cutoff on a molecule-sized cell yields far too many plane waves for exact state-vector VQE, so use a small cell/cutoff.
- `src/carcara/circuits/` — `base.py` (the **`Ansatz` protocol** — `num_parameters`/`n_qubits`/`reference_state`/`state(θ)`/`evolve(θ, references)` — that every ansatz conforms to structurally, so a new ansatz drops in with no driver change), `gates.py` (anti-Hermitian single/double fermionic excitation generators), `ansatz.py` (`UCCSD`, a state-vector ansatz `|ψ(θ)⟩ = exp(Σ θ_k (T_k − T_k†))|HF⟩`; default is the exact UCC exponential, `trotter=True` gives the circuit-faithful first-order product), `adapt_ansatz.py` (the growable `AdaptAnsatz`), `pools.py` (ADAPT-VQE operator pools — **fermionic**, **qubit** (qubit-ADAPT), **QEB** (Z-strings dropped) and **CEO** (coupled exchange, OVP) — behind a common `OperatorPool`/`PoolOperator` interface with a `build_pool` registry), and `profiling.py` (`CircuitMetrics`/`profile_ansatz` — compile `|HF⟩`+∏exp(A_k) to a native `{cx,u}` gate set for CNOT/depth). `AdaptAnsatz`/`profile_ansatz`/`CircuitMetrics`/`Ansatz`/`UCCSD` are imported from `carcara.circuits` (their canonical home — not re-exported through `carcara.algorithms`). The `evolve(θ, references)` method applies one shared unitary to a `(2ⁿ,k)` stack of reference states (used by the subspace-search solvers).
- `src/carcara/optimizers/optim.py` — `Optimizer`, a classical-optimizer wrapper with cost-history tracking. Six named methods (`NAMED_OPTIMIZERS`): **SPSA**, **COBYLA** (default), **Nelder-Mead**, **SLSQP**, **Adam**, **L-BFGS-B**. COBYLA/Nelder-Mead/SLSQP/L-BFGS-B dispatch to `scipy.optimize.minimize`; **SPSA** and **Adam** are implemented natively (SPSA = two-eval Spall stochastic gradient; Adam = finite-difference-gradient adaptive moments).
- `src/carcara/algorithms/base.py` — **`VariationalDriver`**, the shared ASE-`Calculator` base every variational driver subclasses. It owns the common **problem-setup surface** (`basis`/`grid`/`h`/`kpts`/`spin`/`initial_state`/`charge`/`n_electrons`/`frozen_core`/`frozen_orbitals`/`hamiltonian_builder`/`optimizer`/`device`/`run_options`/`sparse`), the ASE `calculate()` hook (geometry→Hamiltonian each call in calculator mode; reused in direct mode), the **state-vector backend** (`_materialize_hamiltonian` dense/sparse-Hermitize, `_as_pauli_sum`, `_resolve_sparse`, the canonical **`energy(psi)`** — a state vector in, uniformly), the Γ-point k-guard (`_check_kpts`/`_kpts_label`), timings/banner scaffolding (`_make_timings`/`_finalize_timings`/`_show_banner`) and `format_pauli_sum`. Subclasses implement just `_configure(hamiltonian, num_particles, n_orbitals)` (build the ansatz/pool + materialize) and `run()`. Excited-state **methods are mixins** over the base: **`DeflationMixin`** (`algorithms/deflation.py`) supplies `energy_levels(...)` once (the state-by-state VQD outer loop + `EnergyLevels`), with each driver providing the per-state `_deflated_ground` hook; **`SubspaceMixin`** (`algorithms/subspace.py`) supplies the SSVQE `run()` scaffolding, with each driver providing `_reference_occupied`/`_subspace_optimize`/`_make_subspace_result` (the run result always lands on the driver's `.result` — there is no per-class result attribute). So `VQE(DeflationMixin, VariationalDriver)`, `ADAPTVQE(DeflationMixin, VariationalDriver)`, `SubspaceVQE(SubspaceMixin, VQE)`, `SubspaceADAPTVQE(SubspaceMixin, ADAPTVQE)` — and a new method plugs in as a mixin/subclass without re-implementing setup. (`VQE.energy_at(θ)` is the parameter-space cost; the base `energy(psi)` is the state-vector expectation.)
- `src/carcara/algorithms/vqe.py` — `VQE`, an exact state-vector eigensolver (`⟨ψ(θ)|H|ψ(θ)⟩` minimized over ansatz params); validated on H₂ against exact diagonalization to ~1e-9 Ha. `VQE`/`VQEResult` mirror `ADAPTVQE`/`ADAPTVQEResult`: `optimizer` accepts a method-name string (`"SPSA"` / `"COBYLA"` default / `"Nelder-Mead"` / `"SLSQP"` / `"Adam"` / `"L-BFGS-B"`) or an `Optimizer`, `verbose=True` prints the qubit Hamiltonian as Pauli strings + a timing/resources summary on `run()`, and `VQEResult` exposes `num_parameters`/`energy_history`/`correlation_energy`. Both `VQE` and `ADAPTVQE` also have an **`energy_levels(num_states=2, ...)`** method computing molecular **excited states** via variational quantum deflation (VQD): each level minimizes `⟨H⟩ + β·Σⱼ|⟨ψⱼ|ψ⟩|²` over the previously found states (auto `β` from the Hamiltonian's coefficient 1-norm; the shared `DeflationMixin`/`EnergyLevels` live in `algorithms/deflation.py`), returning an `EnergyLevels` (ascending Hartree energies + `excitation_energies`/`in_units("eV")`/stored state vectors; ADAPT re-grows a fresh deflated ansatz per level and records `num_operators`). Reported energies are the bare `⟨H⟩` (penalty vanishes at the eigenstate) — every returned level is a true eigenvalue of H, limited to the sector the ansatz can reach from its HF reference (ADAPT's greedy screening hits Brillouin's zero-gradient wall for singles, so on H₂ it reaches the seniority-zero partner, while UCCSD-VQE also reaches a singly-excited level). `algorithms/subspace.py` adds **`SubspaceVQE`** and **`SubspaceADAPTVQE`** (via `SubspaceMixin` over `VQE`/`ADAPTVQE`) — **subspace-search VQE (SSVQE)**, which computes the ground + first few excited states **simultaneously** in one optimization: `num_states` orthogonal reference determinants (auto-generated as the lowest of the HF particle-number sector, `subspace_determinants`/`reference_matrix`) are sent through one shared unitary `U(θ)` and the weighted energy `Σⱼ wⱼ⟨φⱼ|U†HU|φⱼ⟩` (strictly-decreasing `weights`, default `(k,k-1,…,1)`) is minimized (`SubspaceADAPTVQE` grows one shared ansatz whose pool-screening gradient is the weighted per-reference sum). This needed the ansatz method **`evolve(θ, references)`** (added to `UCCSD` and `AdaptAnsatz`; applies the same unitary to a `(2ⁿ,k)` stack of references). Returns `SubspaceVQEResult`/`SubspaceADAPTVQEResult` (ascending Hartree `energies`, orthonormal `states`, `weights`, `optimal_energy`=ground, `excitation_energies`, `in_units("eV")`, `.levels` → `EnergyLevels`; both are ASE calculators exposing the spectrum on `.result`, ASE energy = ground). Levels are variational **upper bounds** (Hylleraas–Undheim `Eᵢ ≥ λᵢ`); the ground is exact from the default HF start, excited-state tightness tracks ansatz expressivity. **`VQE` is also an ASE calculator**, but the recommended user-facing form is `atoms.calc = QuantumCalculator(method="vqe", basis="FAO", optimizer=..., h=...)`; `atoms.get_total_energy()` builds the Hamiltonian + a default UCCSD ansatz from the geometry and runs, returning eV, with the run result on `atoms.calc.result`. The geometry→Hamiltonian building (grid-from-cell + basis integrals) is shared by both drivers in `algorithms/_hamiltonian_from_atoms.py`; the shared `resolve_optimizer` helper lives in `optimizers/optim.py`.
- **Profiling** (`utils/profiling.py`) — `Timings` accumulates named stage wall-times plus the OpenMP core count and peak process RSS (`peak_memory_mb`, via `resource.getrusage`). The C backend reports its thread count through `carcara_num_threads()` → `_backend.num_threads()`. `IntegralEngine` times its one-/two-body stages (`engine.integration_profile()` → `MolecularIntegrals.integration_profile()`); `VQE.run`/`ADAPTVQE.run` time optimization / gradient-screening / etc. and print a "Timings / Resources" block in the verbose summary (also on `result.timings` / `result.integration_profile`).
- `src/carcara/algorithms/adapt_vqe.py` — `ADAPTVQE`, the adaptive grow-then-reoptimize loop (gradient `⟨ψ|[H,A_i]|ψ⟩` over a pool, warm-started inner VQE) on the exact state-vector backend, using the growable `AdaptAnsatz` (`circuits/adapt_ansatz.py`; dense eigendecomposition backend, or a **sparse closed-form** backend for large active spaces) and Qiskit-based circuit profiling (`circuits/profiling.py`: `profile_ansatz` → CNOT count + depth in a native `{cx, u}` gate set). Both drivers subclass `VariationalDriver` (see `base.py`) so setup/materialization/`energy(psi)`/timings are shared. All four pools reach FCI on H₂. See `examples/01_ADAPTVQE_H2.py` … `examples/06_ADAPTVQE_O2_triplet.py`. Operator selection is the single pluggable hook **`_select_operator(grads, iteration)`** (default `argmax|g|`), used by `run()`, the deflation grow (`_grow_deflated`) and the subspace grow — so a subclass changes *which* operator grows the ansatz without touching convergence (`max|g| < tol`, computed independently of selection).
- `src/carcara/algorithms/vasqe.py` — **`VASQE`** (Variational Adaptive Stochastic Quantum Eigensolver), `ADAPTVQE` with **stochastic softmax operator selection** instead of greedy `argmax`: `P(i,τ) = exp(|gᵢ|/τ)/Σⱼexp(|gⱼ|/τ)` (`softmax_selection_probabilities`), so **τ→0 reduces to ADAPT-VQE** (picks largest gradient) and large τ → uniform exploration. `schedule` is `"constant"` or annealed `"exponential"`/`"linear"`/`"logarithmic"` from `temperature`→`final_temperature` over `annealing_steps` (`annealed_temperature`); `seed` makes selection reproducible (RNG reseeded per `run()`). It overrides only `_select_operator` (+`_temperature`) and wraps `run()` to emit a **`VASQEResult`** (an `ADAPTVQEResult` + `temperatures`/`schedule`/`initial`/`final_temperature`; ASE stores it on `.result`). Excited states come for free: `VASQE.energy_levels(...)` (deflation) and **`SubspaceVASQE(SubspaceADAPTVQE, VASQE)`** (subspace search) both grow stochastically because they route through `_select_operator` (MRO puts `VASQE` before `ADAPTVQE`). See `examples/10_VASQE_H2.py`.
- `src/carcara/algorithms/hartree_fock.py` — `RHF` (closed-shell SCF; supplies the **molecular-orbital basis** so ADAPT's HF reference is stationary and singles have zero gradient) and `UHF` (open-shell, for isolated-atom energies). `MolecularIntegrals.molecular_hamiltonian(mo_basis=True, n_electrons=...)` returns the MO-basis `Fermion`.
- `src/carcara/algorithms/bloch.py` — the **general (1-/2-/3-D) periodic-system driver `BlochCalculator`** — a single class whose variational solver is selected by `method="vqe"` (fixed UCCSD, default) / `"adapt-vqe"` / `"vasqe"`, mirroring `QuantumCalculator`. Takes an ASE `Atoms` *primitive cell* (`atoms.cell`/`atoms.pbc` define the lattice and periodic directions). `bands(kpts)`/`band_structure(path)` solve the single-particle **Bloch Hamiltonian** `H(k)c = ε(k)S(k)c` at each k-point — the cell-to-cell overlap/one-body blocks `S^{(R)}`,`h^{(R)}` are built from the FAO real-space integrals over a lattice window, the Bloch phase is the dimension-general `exp(2πi k·n)` over integer translations, and (being single-particle) the bands are **identical across the three methods**. `total_energy(kmesh, **solver_kwargs)` gives the **total energy per cell using all k-points** via the **Born–von Kármán equivalence** (an `(n1,n2,n3)` mesh ≡ Γ-point on the `(n1,n2,n3)` supercell): it builds the supercell with `atoms.repeat`, runs it through a molecular `QuantumCalculator(method=self.method, ...)`, and returns `(E(supercell)/n_cells, result)` where `result` is the method's `VQEResult`/`ADAPTVQEResult`/`VASQEResult` (read from `calc.result`; a finite-supercell estimate exact in the infinite-mesh limit; k-points come from ASE `monkhorst_pack`). `band_structure` returns `BandStructure` (x/energies/xticks/labels/kpts). See `examples/07_ADAPTVQE_H_chain_bands.py` and `examples/11_Bloch_crystals.py`.
- `src/carcara/algorithms/expressivity.py` — PQC **expressibility** (Sim *et al.* 2019): random-parameter state fidelities vs the Haar distribution scored by KL divergence (`compute_expressibility`, `calculate_kl_divergence`, `calculate_haar_distribution`). The Haar reference dimension is the *number-conserving sector* `d = C(M,nα)·C(M,nβ)` (`active_space_dimension`) or the empirical span rank (`estimate_effective_dimension`), **not** `2^N` — the fermionic ansätze never leave their symmetry sector. `ADAPTExpressivityTracker` / `track_adapt_expressivity` hook `ADAPTVQE.run(callback=...)` to log expressibility as the ansatz grows.

Recently implemented: `backends/hardware.py` (device registry — `AER_simulator` ideal simulator, `ibm-quantum` reserved/not-yet-runnable) and `utils/logging.py` (the ADAPT `output.txt` protocol, `AdaptOutputLogger`/`parse_output`). `ADAPTVQE` (`algorithms/adapt_vqe.py`) is also an **ASE calculator** — driven in user code via `atoms.calc = QuantumCalculator(method="adapt-vqe", pool=..., basis="FAO", mapping=..., optimizer=..., gradient=..., device=...)`; `atoms.get_total_energy()` builds the Hamiltonian from the geometry and runs the loop, returning eV (result on `atoms.calc.result`) with selectable `optimizer` (`"SPSA"` / `"COBYLA"` default / `"Nelder-Mead"` / `"SLSQP"` / `"Adam"` / `"L-BFGS-B"`, or an `Optimizer` instance) and `gradient` (`"finite_difference"` / `"parameter-shift"`). By default (`verbose=True`) `run()` prints a stdout trace of the quantum simulation — the qubit Hamiltonian's **term count only** (its Pauli expansion is no longer dumped), then a **column-aligned iteration table** (one single line per grown operator: `iter | max|grad| | energy | dE | npar | cnot | depth | operator`, built by `_iteration_heading`/`_print_iteration` in `adapt_vqe.py`; the selected operator's Pauli-string expansion is *not* printed — it lives on `result.operators` and in `output.txt`). `run()` takes no required arguments: `max_iterations` / `gradient_tolerance` / `output` / `verbose` all default to the constructor values. The class is `ADAPTVQE` and its result dataclass `ADAPTVQEResult` (no `AdaptVQE`/`AdaptVQEResult` aliases). Both drivers also accept `kpts` (Monkhorst-Pack mesh via ASE; a `(n1,n2,n3)` triple or the ASE dict `{"size":(...),"gamma":True}` — the engine is Γ-point/molecular so a denser mesh is generated + exposed on `.kpoints` but rejected at run with `NotImplementedError`), `spin` (bool, default False — spin-polarized/high-spin reference; open-shell odd-electron builds raise `NotImplementedError`, RHF-only), `initial_state` (default `"hartree-fock"`, the HF-determinant reference; validated), and the **frozen-core approximation** `frozen_core`/`frozen_orbitals` (`frozen_core=True`/`"auto"` freezes the chemical noble-gas core, an int freezes that many lowest MOs, or `frozen_orbitals=[...]` names exact spatial-MO indices; core orbitals are removed from the active space via `core.hamiltonian.freeze_core_integrals` — a constant core energy + effective one-body potential — so the ansatz/pool/qubit-count shrink. Resolved by `core_electrons`/`resolve_frozen_core` in `_hamiltonian_from_atoms.py`; PW rejects it with `NotImplementedError`). The **initial spin state** is read primarily from the ASE geometry's initial magnetic moments (`Atoms(..., magmoms=...)`): their rounded total is the number of unpaired electrons (`resolve_num_unpaired`), so a triplet is `magmoms=[1,1]` → reference `(n_alpha, n_beta)` with `n_alpha-n_beta=2` (the `spin` bool is the fallback when no magmoms are set). ADAPTVQE also takes **`sparse`** (default `"auto"` → sparse pool for `n_qubits ≥ 12`): the sparse path keeps the Hamiltonian + pool generators as scipy-sparse matrices (`PauliSum.to_sparse_matrix`), screens with the exact analytic gradient, and applies `exp(θA)` in `AdaptAnsatz` via the closed form `I + sinθ·A + (1−cosθ)·A²` valid because the excitation generators satisfy `A³=−A` (a `scipy.sparse.linalg.expm_multiply` fallback otherwise) — so only the few *selected* operators are ever densified, making 12+-qubit active spaces (e.g. frozen-core H₂O) tractable. The **ASE-calculator path softens the −Z/r cusp to half a grid step** (`MolecularIntegrals(..., softening=)`) so a nucleus landing on a grid node no longer produces a ~1e12 garbage core integral (needed since FAO now uses the bare Z). When `verbose`, `run()` first writes the **start-up banner** (`utils/banner.py` — `show()` writes provenance/versions to stdout via `_write`, not `print`) *before* anything is written to `output.txt`. `MolecularIntegrals.hartree_fock_hamiltonian(n_electrons)` reduces the full Hamiltonian to the mean-field (diagonal orbital-energy) HF `Fermion` whose ground state is the HF determinant at the RHF total energy. The calculator-mode grid is centered on the molecule (minimum-image via ASE `find_mic`), so the molecule's placement in the cell is irrelevant. The `basis` argument accepts a name **or** a `{"name": ..., <options>}` dict (`resolve_basis` in `_hamiltonian_from_atoms.py`): `{"name":"FAO"}`, `{"name":"NAO","energy_shift":0.03}`, `{"name":"GTO","n_gaussians":3}`, `{"name":"6-31G(d)"}`, or the periodic `{"name":"PW","energy_cutoff":300}` (routes to `PlaneWaveIntegrals`; requires `atoms.cell`).

Also implemented on the shared `VariationalDriver` (so VQE / ADAPTVQE / VASQE and their subspace variants all accept them):

- **Hamiltonian disk cache** (`core/serialization.py` — `save_hamiltonian`/`load_hamiltonian`/`HamiltonianRecord`/`detect_format`). Two interchangeable formats selected by `hamiltonian_format="parquet"` (default) or `"json"`: Parquet is a compressed columnar table of `pauli`/`real`/`imag` rows with the problem spec in the key/value metadata (~4x smaller than JSON); JSON is the same content as plain text and needs no Parquet engine. `save_hamiltonian=True|"path"` dumps the qubit Hamiltonian after it is built; `load_hamiltonian="path"` reads it back — **auto-detecting the format** from the extension, else from the leading bytes (`PAR1` vs `{`) — and **bypasses the integral engine and the fermion-to-qubit mapping entirely**. Parquet has two engines (`engine="fastparquet"` default, `"pyarrow"`); fastparquet leads deliberately because pyarrow's Parquet writer can segfault in a process that has also run Qiskit's `transpile` (reproduced on CPython 3.14 / qiskit 2.5 / pyarrow 25) — `hamiltonian_format="json"` avoids the issue entirely. Because the file records `num_particles`/`n_spatial_orbitals`, a loaded driver is in *direct mode with no geometry* — `ADAPTVQE(pool=..., load_hamiltonian=...).run()` works without any `Atoms`, and `VQE` rebuilds its default UCCSD from the file. (The *pool*'s own excitation generators are still mapped — that is a different operator.)
- **Multi-backend circuit providers** (`backends/providers.py` — `CircuitProvider` + `QiskitProvider`/`BraketProvider`/`CirqProvider`, `build_provider`/`normalize_provider`/`provider_available`). `backend_provider="qiskit"|"braket"|"cirq"` (default follows the `device`, else `"qiskit"`) selects the SDK; `execute_circuits` (default `True` for braket/cirq, `False` for qiskit) makes state preparation *run a real circuit* on that SDK's local state-vector simulator instead of the internal NumPy/sparse backend. Each anti-Hermitian generator `A = Σ i c_j P_j` has mutually commuting terms, so `exp(θA) = Π exp(iθc_j P_j)` factorizes **exactly**; each factor is a basis change + CNOT ladder + `Rz(-2θc_j)` + uncompute, emitted once by `CircuitProvider._emit` in a shared `{x,h,s,sdg,cx,rz}` gate set and translated per SDK. Qiskit is little-endian so Carcará qubit `k` is laid on wire `n-1-k`; Braket and Cirq are big-endian like Carcará. Wired into `AdaptAnsatz(provider=...)` and `UCCSD(provider=..., trotter=True)` (a circuit realizes the Trotter product, so UCCSD raises without `trotter=True`); `profile_ansatz(..., provider=)` counts gates/depth per SDK. Circuit execution only handles computational-basis (determinant) references — HF and the SSVQE references — and raises otherwise. See `examples/12_ADAPTVQE_LiH_backends.py` (LiH across all three, agreeing to ~5e-8 Ha).
- **Amazon Braket / real QPUs.** `BraketProvider(device=..., shots=...)` targets either the local simulator or the **AWS service** by ARN (`AwsDevice`). Verified constraint: Braket rejects the `StateVector` result type whenever `shots > 0`, and every QPU requires `shots > 0` — so the exact path is simulator-only. The QPU path is shot-based: `backends/measurement.py` partitions H into **qubit-wise-commuting groups** (`qubit_wise_commuting_groups`/`merge_basis`/`energy_from_counts`/`shot_noise_estimate`), submits one measurement circuit per group with the basis rotation appended, and assembles ⟨H⟩ from bit-string counts (118 Pauli terms → 29 circuits on LiH; error falls as 1/√shots). `hardware.py` now carries a `Device` registry with the Braket entries (`braket-local`, `braket-sv1`/`dm1`/`tn1`, `braket-ionq-aria`/`forte`, `braket-iqm-garnet`, `braket-rigetti-ankaa`, plus any raw ARN) and `device_arn`/`device_provider`/`is_aws_device`/`requires_shots`; a QPU named without `shots` is refused in the constructor. Drivers take `shots`/`backend_options` and route the cost through `VariationalDriver.ansatz_energy`. **Limitation:** only the energy evaluation is hardware-native — ADAPT-VQE's pool-gradient screening is still classical, so a fixed-ansatz `VQE` is the fully hardware-native driver today. See `examples/13_braket_aws_compatibility.py`.
- **Dynamic parametrization** `quenching` (default `True`). `True` re-optimizes **all** parameters each iteration (standard ADAPT-VQE — this is what reaches FCI). `False` optimizes only the newly appended parameter and freezes every earlier one at its prior optimum (a 1-D line search per growth step: far cheaper, variationally weaker). Implemented once on the base as `_optimize_grown` (used by `ADAPTVQE.run`, `_grow_deflated` and `SubspaceADAPTVQE._subspace_optimize`) and `_optimize_all` (used by `VQE.run`/`_deflated_ground`/`SubspaceVQE`, where `quenching=False` means a one-parameter-at-a-time sweep over the fixed ansatz).

**Pseudopotentials** (`basis/pseudopotential.py`, `basis/pseudo_io.py`, `basis/pseudo_orbital.py`, library in `pseudos/`) — norm-conserving **Troullier-Martins** pseudopotentials with **Kleinman-Bylander** projectors, generated from scratch by an LDA radial atomic solver (`basis/atomic_solver.py`). `pseudopotentials=True` on any driver switches to a valence-only Hamiltonian. **The `basis` argument is honoured, not ignored:** `_merge_pseudo_basis_options` folds `size`/`split_norm` from a `{"name":"PP"|"NAO", "size":...}` dict into the pseudo path (`pseudo_basis(..., size=)` builds the split-valence zetas *from the pseudized orbital*, polarization split off the outermost channel), and **raises** for an all-electron family (`FAO` with no other options passes through as the historical default). The first zeta must stay the pseudopotential's own orbital — the KB projectors were built from it. PP `size` defaults to `"SZ"`. The shipped library covers **every element with Z < 90** (H–Ac, `LIBRARY_Z_MAX = 89`), regenerable with `build_library()`. Storage is **Parquet by default** with **JSON** retained (`PSEUDO_FORMATS`); `load_pseudopotential` **auto-detects** the format from the extension, falling back to magic bytes (`PAR1` vs `{`), so the two are interchangeable. `save_pseudopotential` is **lossless and idempotent** (`stride=1`); the `STRIDE=4` decimation applies only at `build_library()` time, where the fine generation grid actually exists — applying it per-write made load→save compound. **Beware the pandas/pyarrow/qiskit interaction:** pandas 3 defaults `future.infer_string` on, so even a *fastparquet* read builds its column index as a pyarrow string array; after Qiskit's `transpile` has run in the same process that decode corrupts (`UnicodeDecodeError` / `ArrowException`). Every Parquet read therefore goes through `core.serialization.native_pandas_strings()` — keep new Parquet paths inside it. (Separately, importing pandas *after* qiskit's transpile segfaults at interpreter shutdown; importing it first is fine.)

**Forces / geometry optimization — known-broken, do not trust for relaxation.** `algorithms/forces.py` + `QuantumCalculator` produce forces, but **H2O relaxation diverges** (BFGS: fmax oscillates 35→944 eV/Å, angle 104.5°→164.5°). Two causes, both partly in the *energy*: (a) **egg-box** — rigidly translating H2O on a frozen grid changes E by ~160 eV/Å, and the analytic net force reproduces that numerical derivative to ~4%, i.e. the gradient faithfully differentiates a non-translation-invariant discretized energy; (b) a **residual gradient error** — vs finite differences the analytic forces are ~8x too small on H (H y: ±3.3 vs ±28.4). H2 forces are fine (transverse components exactly 0, isotropic). Fixed along the way (keep these): `nuclear_gradient` used to reach past `integrals.external_potential()` to the bare `-Z/r` and omit `kb_nonlocal()`, so on the PP path (`softening=0`) it built the *wrong* h_ao and diverged at grid nodes; and `_jax_energy._scf` unrolled a fixed 40 iterations whose derivative is only valid **if the SCF converged** — H2O sat on a metastable plateau ~19 iters then escaped, and differentiating the mid-transient unroll gave ~1e8 Ha/Bohr gradients that *looked* fine (finite, and the spurious part sat in a symmetry-zero direction). `scf_iterations_required` (plain-NumPy probe, runs untraced) now sizes the unroll via `_resolve_scf_iterations`; the caller's `scf_iterations` is a **floor**, and genuine non-convergence raises. Pinned by `test/test_scf_convergence.py`.

## The C integral backend

The heavy integral kernels live in C (`src/carcara/integrals/csrc/carcara_integrals.c`), an OpenMP-parallel shared library — **not** a CPython extension, so one compiled `.dylib`/`.so` serves every Python version. `_backend.py` loads it via `ctypes` with zero-copy pointer passing (NumPy `complex128` ⇄ C99 `double _Complex`).

The build is **optional**: if the library is absent, `HAS_C_BACKEND` is `False` and vectorized NumPy reference implementations (which mirror the C kernels exactly) run instead, so the package is always importable and testable without compiling anything.

Two one-body kernels: `carcara_one_body` (cubic fast path, single `npts`/`dx`) and `carcara_one_body_general` (per-axis `nx,ny,nz` + a 3×3 inverse-metric `ginv` and voxel volume `dV`), the latter handling **varying resolution per axis and non-orthogonal cells** via the generalized FD Laplacian `∇²f = Σ_ab ginv[a,b] ∂_a∂_b f` (diagonal 3-point + off-diagonal 4-point cross stencils). `_backend.one_body_matrices(psi, Vext, grid)` dispatches on `grid.is_cubic`. The two-body direct kernel already consumes explicit coordinates + `dV`, so it is geometry-agnostic.

Build it with CMake; the output must land in `csrc/build/` where `_backend.py` looks (it also honors the `CARCARA_INTEGRALS_LIB` env var). The `CMakeLists.txt` is macOS+Linux portable: on Linux OpenMP is found out of the box; on macOS (Apple Clang) it auto-discovers Homebrew `libomp` via `brew --prefix libomp` (override with `-DOpenMP_ROOT`).

```bash
cd src/carcara/integrals/csrc
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
# macOS: libomp is auto-discovered; to pin it explicitly:
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DOpenMP_ROOT=$(brew --prefix libomp)
```

When editing the numerics, keep the C kernel and its NumPy fallback in `_backend.py` in lockstep (both the cubic and the general Laplacian) — tests may exercise either depending on whether the library is built.

## Architecture: the integral engine

The one design principle that spans multiple files is that the integral machinery is **basis-agnostic**. The C backend and `IntegralEngine` never see analytic orbital forms — only **sampled values** `psi[i, :]` on the grid (cubic, orthorhombic, or non-orthogonal). This is what lets any basis drop in with zero changes to the integral core: a new family only implements `BasisFunction.evaluate(x, y, z)` (returning `complex128` in Bohr). `FullAtomicOrbital`, `NumericalAtomicOrbital` (spline of a confined radial solve) and `GaussianOrbital` (contracted Gaussians) all follow the same `R(r)·Y_lm` pattern; NAO/GTO share `_angular.py` for the Cartesian→spherical + spherical-harmonic step. Orbitals are normalized in 3D with orthonormal `Y_lm` (i.e. `∫|R|²r²dr = 1`) — preserve that convention for any new radial family.

The single contract is `BasisFunction.evaluate(x, y, z)` (in `basis/base.py`). The data flow:

1. `Grid` (`integrals/grid.py`) — a regular Cartesian grid specified by a physical spacing `h` (not a node count); node counts and `dx`/`dy`/`dz` are derived. Three shapes: **cubic** (scalar `box_size` + scalar `h`; the byte-exact historical path), **orthorhombic** (per-axis `box_size`/`h` — i.e. varying resolution per axis — or a diagonal `cell`), and **non-orthogonal** (full `cell` with `skew=True`, sampling the skewed lattice directly; default `skew=False` uses the cell's bounding box). Geometry is captured in the `step` (3×3 voxel basis) matrix, from which `dV = |det(step)|` and `metric_inverse()` = `(stepᵀstep)⁻¹` (the coefficients of the generalized FD Laplacian) are derived. Non-orthogonal / anisotropic two-body integrals should use `method="direct"` (the FFT-Poisson path assumes uniform orthogonal spacing).
2. Each `BasisFunction.sample(grid)` produces a contiguous `complex128` vector.
3. `IntegralEngine` (`integrals/engine.py`) stacks them into `(M, ngrid)`, evaluates the external potential callable `V(x,y,z)`, and dispatches to the backend:
   - `one_body(potential)` → kinetic `T` (finite-difference Laplacian) and potential `V` matrices → core Hamiltonian `h = T + V`.
   - `two_body(method=...)` → electron-repulsion tensor `<ab|cd>` in **physicists' notation** (electron 1 carries indices `a,c`; electron 2 `b,d`). `method="fft"` (default) uses the O(N log N) `PoissonFFTSolver` (`integrals/poisson.py`); `method="direct"` uses the O(N²) real-space double sum in C.
4. `MolecularIntegrals` (`core/hamiltonian.py`) drives the engine to build the spin-orbital `Fermion` Hamiltonian; the ASE-calculator drivers reach it through `algorithms/_hamiltonian_from_atoms.build_basis_hamiltonian` (geometry → basis → grid → integrals → Hamiltonian).

**Units convention** (`units.py` is the single source of truth): the numerical core — `evaluate`, the grid coordinate arrays, the C backend, the Poisson solver — always works in **atomic units (Bohr, Hartree)**. The user-facing classes (`Grid`, `FullAtomicOrbital`, `Potentials`, `IntegralEngine`) default to the **frontend units (Ångström, eV)** and convert at their boundary via a `units=`/`energy_units=` argument. When adding a user-facing length/energy argument, route it through `units.py` and default to Ångström/eV.

`FullAtomicOrbital` also provides Slater's-rules effective charges: `slater_effective_charge(atomic_number, n, l)` (static) and the `from_slater(n, l, m, atomic_number, ...)` constructor.

Validation anchor used throughout the tests: the hydrogen 1s on-site repulsion `<00|00>` must recover the exact `5/8 Ha` (`= 0.625` Ha `= 17.007` eV, depending on `energy_units`).

## Versioning

CalVer, single source of truth in `src/carcara/version.py` (`__version__`), consumed dynamically by hatchling. The scheme is `YY.M.patch` (e.g. `26.7.3` = 2026, month 7, patch 3). Releases are git-tagged `v<version>` and published to PyPI.
