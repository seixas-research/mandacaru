# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Mandacaru** is a framework for fermionic quantum simulation based on variational quantum algorithms (VQAs), targeting real NISQ-era quantum hardware (IBM Quantum via Qiskit). The intended end-to-end pipeline is: fermionic system → second-quantized Hamiltonian → qubit (Pauli) Hamiltonian → parameterized ansatz → VQA optimization → QPU/simulator execution → error mitigation. The flagship algorithm is **ADAPT-VQE** with pluggable operator pools (fermionic / qubit / QEB / CEO), plus its **excited-state** extensions (deflation / subspace-search).

**Important:** the project is mid-build. Implemented end-to-end: localized bases (FAO / NAO / STO-nG / 6-31G(d)), **a periodic plane-wave basis** and the **pseudopotential families NCPP / ONCVPSP / PAW** (selected as a basis name, `basis="PAW"`; package `mandacaru.pseudopotentials`, stable since 2026-09-15) → real-space (and reciprocal-space, for PW) integral engine → second-quantized `Fermion` Hamiltonian → fermion-to-qubit mappings → **UCCSD ansatz → VQE** and **ADAPT-VQE** (both exact state-vector solvers, validated on H₂), with **RHF/UHF** for the molecular-orbital basis. Also implemented: **excited states** (`energy_levels` via variational deflation, and `SubspaceVQE`/`SubspaceADAPTVQE` subspace-search), and the periodic-system **`BlochCalculator`** (band structure + BvK total energy, `method="adapt-vqe"|"vqe"`). All solvers share a common **`VariationalDriver`** base (`algorithms/base.py`) with the excited-state methods as composable mixins. **The single user-facing entry point is `Mandacaru(method=..., ...)`** (`algorithms/calculator.py`; renamed on 2026-09-09, the old name is gone without alias — also `from mandacaru import Mandacaru`) — an ASE calculator selecting the solver by the `method` string (`"adapt-vqe"` is **the default everywhere**, also for `BlochCalculator`; `STABLE_METHODS` = `"vqe"`, `"adapt-vqe"`, `"subspace-vqe"`, `"subspace-adapt-vqe"`; anything else must be added with `register_method(name, cls)` — the `mandacaru.experimental` package registers its own solvers when *explicitly* imported, and the stable code, docs, README, examples and website never name them; a repository sweep under `test/experimental/` enforces that), forwarding all solver options, and exposing the run result uniformly on `.result` (plus `.solver`/`.hamiltonian`/`.n_qubits`/`.num_particles`, direct-mode `run()`, and `energy_levels()`). **The algorithms are called solely through `Mandacaru` — no exceptions (user mandate, re-issued 2026-09-19).** The solver classes (`VQE`, `ADAPTVQE`, `SubspaceVQE`, `SubspaceADAPTVQE`) are the internal layer: they are **not exported** from `mandacaru.algorithms`, and no test, example or documentation page may import or construct one — `test/test_single_entry_point.py` sweeps the repository and fails if one does. Direct (no-geometry) problems go through the calculator too: `Mandacaru(method="adapt-vqe", hamiltonian=H, pool=..., num_particles=..., n_spatial_orbitals=...).run()`. To make that a complete replacement, `Mandacaru` **validates its options in the constructor** (by building the solver once with its dry-run switch on, which runs every constructor check and configures nothing — plus `_check_shots_for_hardware`, the one check a dry run waives) and builds the real solver **on first use** (`calc.solver` is a lazy property; `run()` reuses a solver built only to be read; every geometry evaluation replaces it). An invalid *option* is therefore refused by the constructor, an invalid *problem* (a non-Hermitian operator, a qubit-count mismatch) where the problem is built — on first use and **delegates unknown attributes to the solver** (`calc.pool`, `calc.ansatz`, `calc.kpoints`, `calc.energy_at`…); writes and monkeypatches that must land on the solver use `calc.solver`. `method` is spelling-insensitive (`"adapt-vqe"` = `"adaptvqe"` = `"ADAPT_VQE"`, `_method_key`). `resolve_method` is the one place the solver classes are imported from. When working on this codebase, never reach for a solver class in a test or example — if `Mandacaru` cannot express what is needed, extend `Mandacaru`. The `backends/hardware.py` device registry is written and every entry is runnable (`AER_simulator`, IBM Quantum via Qiskit Runtime, Amazon Braket); **not written at all: error mitigation** — there is no `backends/mitigation.py` and no `plan/` directory (both were named here for a long time; neither exists). Before building on a module, check that it exists and has code (`wc -l`). `pyproject.toml` is the source of truth for the build (currently Python ≥ 3.14).

## Current state of the code

Implemented:
- `src/mandacaru/basis/` — localized single-particle basis functions (`BasisFunction` ABC) and three concrete families: `FullAtomicOrbital` (analytic, with Slater charges), `NumericalAtomicOrbital` (confined Sankey/SIESTA-type, `nao.py`), `GaussianOrbital` (contracted GTOs, `gaussian.py`). **All families are generated natively from scratch — no tabulated/external basis-set data.** The `BasisSet` factory (`factory.py`) builds `"FAO"` (Full Atomic Orbitals; one analytic orbital per occupied subshell, carrying the **actual atomic number Z** as the orbital's nuclear charge — the bare hydrogenic orbital, no Slater screening; **`{"name": "FAO", "virtual_orbitals": k}`** appends the `k` lowest *unoccupied* subshells per atom, see below), `"STO-3G"`, `"NAO"`, `"GTO"` and `"6-31G"`/`"6-31G(d)"` bases. The GTO family is a minimal **STO-nG** basis generated in `sto_ng.py` by least-squares fitting `n_gaussians` primitives to the Slater-type orbital of each occupied subshell (Slater's-rules ζ = (Z−S)/n\*), with the reference fit done once at ζ=1 (cached, `_fit_reference`) and exponents rescaled by ζ². `BasisSet.build(method="GTO", n_gaussians=3)` → STO-3G-like; the fit reproduces published STO-nG exponents closely (H 1s → 2.22766/0.40577/0.10982). The **Pople split-valence** family (`pople.py`) reuses that fit to build 6-31G(d): 6-primitive cores, 3+1 split valence, and a native (Slater-heuristic) `d` polarization shell on non-H atoms. Shared aufbau config in `_config.py`, angular helpers in `_angular.py`. `_config.valence_subshells` returns the highest-`n` occupied subshells **plus the semicore `(n-1)d` / `(n-2)f`** when occupied, so Fe is `3d⁶4s²` (8 valence electrons) rather than a 2-electron `4s²` atom — this feeds both the basis and pseudopotential generation.
- `src/mandacaru/basis/gaussian_families.py` — **named Gaussian families** (`BasisSet.build("cc-pVTZ" | "6-311+G(2df,2p)" | "def2-TZVP" | "STO-4G" ...)` → `GaussianBasisSet`): `parse_basis_name` turns a name into a `GaussianRecipe` (core/valence contraction *patterns*, heavy/H polarization `(l,count)` tuples, diffuse lists or `diffuse_present`, tight functions, `polarization_min_z`=11 for Pople's `3-21G*`), and `gaussian_shells(Z, recipe)` generates `(l, exps, coeffs)` natively: each `(n,l)` shell is one `_fit_reference` Slater fit of `sum(pattern)` Gaussians partitioned tightest-first (`(3,1)` = 6-31G split, `(3,1,1)` = 6-311G), polarization `f_l·ζ_val²` (`HEAVY_/HYDROGEN_POLARIZATION_FACTOR`, ratio 3 spread — `6-31G*` reproduces `pople_631g_shells` exactly), diffuse = most diffuse exponent of that `l` / `DIFFUSE_RATIO` 3.5, tight = tightest valence × 3. Function counts match the published shell notation (`cc-pVTZ` C `[4s3p2d1f]`, `def2-QZVP` C `[7s4p3d2f1g]`, spherical shells); exponents are Mandacaru's own. `MAX_CONTRACTION = 10`: the Slater fit is numerically singular past ~10 primitives, so `sto_ng._projected_overlap` now rejects ill-conditioned trials (cond > 1e12, overlap > 1) and `_fit_reference` raises instead of returning garbage — keep contractions ≤ 10. `NAMED_BASIS_SETS` lists the 40 validated names; pinned by `test/test_gaussian_families.py` (structure table + H₂ RHF/Hamiltonian integration per family). `6-31G`/`6-31G(d)`/`6-31G*`/`STO-nG` still route to the dedicated `Pople631GBasisSet`/`GTOBasisSet`.
- `src/mandacaru/basis/multizeta.py` — **multiple-zeta and polarized NAOs**, selected by `BasisSet.build("NAO", size=...)` or `basis={"name":"NAO","size":"DZP","energy_shift":0.03}` (all `NAOBasisSet` options — `size`, `energy_shift`, `r_c`, `n_grid`, `split_norm` — pass through the dict). `ZETA_NAMES` covers `SZ`/`SZP`/`DZ`/`DZP`/`DZ2P`/`TZ`/`TZP`/`TZ2P`/`QZ`/`QZP`/`QZ2P` (or an explicit `(n_zeta, n_polarization)` pair); **the default is `DEFAULT_NAO_SIZE = "DZP"`** — `size="SZ"` is opt-in and keeps the original `NumericalAtomicOrbital` path byte-for-byte. Extra zetas use the **SIESTA split-valence** construction (`split_radius`/`split_valence_tail`): pick `r_s` leaving `split_norm` (0.15) of the norm outside, replace the inside by `r^l(a−b r²)` matched in value *and* slope at `r_s`, keep the difference — each zeta is strictly shorter-ranged than the last (H 1s: 3.99 → 2.09 → 1.22 → 0.81 a₀). Polarization adds a whole `l_max+1` shell solved in the same confining sphere (3 functions for s-valence, 5 for p, 7 for d). All orbitals become `TabulatedOrbital` (`R(r)·Y_lm` off a spline), so the integral engine sees them identically. **Caveat worth knowing:** high zetas are short-ranged by construction and the real-space grid must resolve them — the 3rd H zeta spans 0.65 Å ≈ 3 points at `h=0.20 Å` and contributes ~1e-6 Ha (3.6e-5 at `h=0.12`). DZP is the practical sweet spot; TZ/QZ need a fine grid to be worth anything.
- `src/mandacaru/integrals/` — real-space one- and two-body integral engine, grid, FFT Poisson solver, C backend binding
- `src/mandacaru/core/` — the second-quantized layer. `mapping.py`: `Fermion` (fermionic ladder operators with full algebra and a `from_integrals` builder for `H = Σ h_pq a†_p a_q + ½ Σ ⟨pq|rs⟩ a†_p a†_q a_s a_r`), `PauliSum` (the qubit-operator output type, with `to_sparse_pauli_op`), and the four fermion-to-qubit mappings — **Jordan-Wigner** (default), **parity**, **parity-reduced**, and **Bravyi-Kitaev** — via a shared encoding-matrix construction (`map_to_qubits(method=...)`). `hamiltonian.py`: `MolecularIntegrals` drives the integral engine to build the spin-orbital molecular Hamiltonian as a `Fermion`. `planewave.py`: `PlaneWaveIntegrals` — a **periodic plane-wave basis** (`{"name":"PW","energy_cutoff":300}`; eV, default 300) computing the reciprocal-space one-/two-body integrals with PBC (diagonal kinetic `½|G|²`, structure-factor external potential, momentum-conserving `4π/Ω/|G_p−G_r|²` electron repulsion, G=0 removed by jellium), mirroring the `MolecularIntegrals` interface (`molecular_hamiltonian`, `hartree_fock`, `integration_profile`). It guards against an intractable O(N⁴) tensor via `max_plane_waves` (default 60) — a realistic cutoff on a molecule-sized cell yields far too many plane waves for exact state-vector VQE, so use a small cell/cutoff.
- `src/mandacaru/circuits/` — `base.py` (the **`Ansatz` protocol** — `num_parameters`/`n_qubits`/`reference_state`/`state(θ)`/`evolve(θ, references)` — that every ansatz conforms to structurally, so a new ansatz drops in with no driver change), `gates.py` (anti-Hermitian single/double fermionic excitation generators), `ansatz.py` (`UCCSD`, a state-vector ansatz `|ψ(θ)⟩ = exp(Σ θ_k (T_k − T_k†))|HF⟩`; default is the exact UCC exponential, `trotter=True` gives the circuit-faithful first-order product), `adapt_ansatz.py` (the growable `AdaptAnsatz`), `pools.py` (ADAPT-VQE operator pools — **fermionic**, **qubit** (qubit-ADAPT), **QEB** (Z-strings dropped) and **CEO** (coupled exchange, OVP) — behind a common `OperatorPool`/`PoolOperator` interface with a `build_pool` registry), and `profiling.py` (`CircuitMetrics`/`profile_ansatz` — compile `|HF⟩`+∏exp(A_k) to a native `{cx,u}` gate set for CNOT/depth). `AdaptAnsatz`/`profile_ansatz`/`CircuitMetrics`/`Ansatz`/`UCCSD` are imported from `mandacaru.circuits` (their canonical home — not re-exported through `mandacaru.algorithms`). The `evolve(θ, references)` method applies one shared unitary to a `(2ⁿ,k)` stack of reference states (used by the subspace-search solvers).
- `src/mandacaru/optimizers/optim.py` — `Optimizer`, a classical-optimizer wrapper with cost-history tracking. Six named methods (`NAMED_OPTIMIZERS`): **SPSA**, **COBYLA** (default), **Nelder-Mead**, **SLSQP**, **Adam**, **L-BFGS-B**. COBYLA/Nelder-Mead/SLSQP/L-BFGS-B dispatch to `scipy.optimize.minimize`; **SPSA** and **Adam** are implemented natively (SPSA = two-eval Spall stochastic gradient; Adam = finite-difference-gradient adaptive moments).
- `src/mandacaru/algorithms/base.py` — **`VariationalDriver`**, the shared ASE-`Calculator` base every variational driver subclasses. It owns the common **problem-setup surface** (`basis`/`grid`/`h`/`kpts`/`spin`/`initial_state`/`charge`/`n_electrons`/`frozen_core`/`frozen_orbitals`/`hamiltonian_builder`/`optimizer`/`device`/`run_options`/`sparse`), the ASE `calculate()` hook (geometry→Hamiltonian each call in calculator mode; reused in direct mode), the **state-vector backend** (`_materialize_hamiltonian` dense/sparse-Hermitize, `_as_pauli_sum`, `_resolve_sparse`, the canonical **`energy(psi)`** — a state vector in, uniformly), the Γ-point k-guard (`_check_kpts`/`_kpts_label`), timings/banner scaffolding (`_make_timings`/`_finalize_timings`/`_show_banner`) and `format_pauli_sum`. Subclasses implement just `_configure(hamiltonian, num_particles, n_orbitals)` (build the ansatz/pool + materialize) and `run()`. Excited-state **methods are mixins** over the base: **`DeflationMixin`** (`algorithms/deflation.py`) supplies `energy_levels(...)` once (the state-by-state VQD outer loop + `EnergyLevels`), with each driver providing the per-state `_deflated_ground` hook; **`SubspaceMixin`** (`algorithms/subspace.py`) supplies the SSVQE `run()` scaffolding, with each driver providing `_reference_occupied`/`_subspace_optimize`/`_make_subspace_result` (the run result always lands on the driver's `.result` — there is no per-class result attribute). So `VQE(DeflationMixin, VariationalDriver)`, `ADAPTVQE(DeflationMixin, VariationalDriver)`, `SubspaceVQE(SubspaceMixin, VQE)`, `SubspaceADAPTVQE(SubspaceMixin, ADAPTVQE)` — and a new method plugs in as a mixin/subclass without re-implementing setup. (`VQE.energy_at(θ)` is the parameter-space cost; the base `energy(psi)` is the state-vector expectation.)
- `src/mandacaru/algorithms/vqe.py` — `VQE`, an exact state-vector eigensolver (`⟨ψ(θ)|H|ψ(θ)⟩` minimized over ansatz params); validated on H₂ against exact diagonalization to ~1e-9 Ha. `VQE`/`VQEResult` mirror `ADAPTVQE`/`ADAPTVQEResult`: `optimizer` accepts a method-name string (`"SPSA"` / `"COBYLA"` default / `"Nelder-Mead"` / `"SLSQP"` / `"Adam"` / `"L-BFGS-B"`) or an `Optimizer`, `verbose=True` prints the qubit Hamiltonian as Pauli strings + a timing/resources summary on `run()`, and `VQEResult` exposes `num_parameters`/`energy_history`/`correlation_energy`. Both `VQE` and `ADAPTVQE` also have an **`energy_levels(num_states=2, ...)`** method computing molecular **excited states** via variational quantum deflation (VQD): each level minimizes `⟨H⟩ + β·Σⱼ|⟨ψⱼ|ψ⟩|²` over the previously found states (auto `β` from the Hamiltonian's coefficient 1-norm; the shared `DeflationMixin`/`EnergyLevels` live in `algorithms/deflation.py`), returning an `EnergyLevels` (ascending Hartree energies + `excitation_energies`/`in_units("eV")`/stored state vectors; ADAPT re-grows a fresh deflated ansatz per level and records `num_operators`). Reported energies are the bare `⟨H⟩` (penalty vanishes at the eigenstate) — every returned level is a true eigenvalue of H, limited to the sector the ansatz can reach from its HF reference (ADAPT's greedy screening hits Brillouin's zero-gradient wall for singles, so on H₂ it reaches the seniority-zero partner, while UCCSD-VQE also reaches a singly-excited level). `algorithms/subspace.py` adds **`SubspaceVQE`** and **`SubspaceADAPTVQE`** (via `SubspaceMixin` over `VQE`/`ADAPTVQE`) — **subspace-search VQE (SSVQE)**, which computes the ground + first few excited states **simultaneously** in one optimization: `num_states` orthogonal reference determinants (auto-generated as the lowest of the HF particle-number sector, `subspace_determinants`/`reference_matrix`) are sent through one shared unitary `U(θ)` and the weighted energy `Σⱼ wⱼ⟨φⱼ|U†HU|φⱼ⟩` (strictly-decreasing `weights`, default `(k,k-1,…,1)`) is minimized (`SubspaceADAPTVQE` grows one shared ansatz whose pool-screening gradient is the weighted per-reference sum). This needed the ansatz method **`evolve(θ, references)`** (added to `UCCSD` and `AdaptAnsatz`; applies the same unitary to a `(2ⁿ,k)` stack of references). Returns `SubspaceVQEResult`/`SubspaceADAPTVQEResult` (ascending Hartree `energies`, orthonormal `states`, `weights`, `optimal_energy`=ground, `excitation_energies`, `in_units("eV")`, `.levels` → `EnergyLevels`; both reached as `Mandacaru(method="subspace-vqe"|"subspace-adapt-vqe")`, exposing the spectrum on `.result`, ASE energy = ground). Levels are variational **upper bounds** (Hylleraas–Undheim `Eᵢ ≥ λᵢ`); the ground is exact from the default HF start, excited-state tightness tracks ansatz expressivity. **The user-facing form is `atoms.calc = Mandacaru(method="vqe", basis="FAO", optimizer=..., h=...)` — the only one;** `atoms.get_total_energy()` builds the Hamiltonian + a default UCCSD ansatz from the geometry and runs, returning eV, with the run result on `atoms.calc.result`. The geometry→Hamiltonian building (grid-from-cell + basis integrals) is shared by both drivers in `algorithms/_hamiltonian_from_atoms.py`; the shared `resolve_optimizer` helper lives in `optimizers/optim.py`.
- **Profiling** (`utils/profiling.py`) — `Timings` accumulates named stage wall-times plus the OpenMP core count and peak process RSS (`peak_memory_mb`, via `resource.getrusage`). The C backend reports its thread count through `mandacaru_num_threads()` → `_backend.num_threads()`. `IntegralEngine` times its one-/two-body stages (`engine.integration_profile()` → `MolecularIntegrals.integration_profile()`); `VQE.run`/`ADAPTVQE.run` time optimization / gradient-screening / etc. and print a "Timings / Resources" block in the verbose summary (also on `result.timings` / `result.integration_profile`).
- `src/mandacaru/algorithms/adapt_vqe.py` — `ADAPTVQE`, the adaptive grow-then-reoptimize loop (gradient `⟨ψ|[H,A_i]|ψ⟩` over a pool, warm-started inner VQE) on the exact state-vector backend, using the growable `AdaptAnsatz` (`circuits/adapt_ansatz.py`; dense eigendecomposition backend, or a **sparse closed-form** backend for large active spaces) and Qiskit-based circuit profiling (`circuits/profiling.py`: `profile_ansatz` → CNOT count + depth in a native `{cx, u}` gate set). Both drivers subclass `VariationalDriver` (see `base.py`) so setup/materialization/`energy(psi)`/timings are shared. All four pools reach FCI on H₂. See `examples/01_ADAPTVQE_H2.py` … `examples/06_ADAPTVQE_O2_triplet.py`. Operator selection is the single pluggable hook **`_select_operator(grads, iteration)`** (default `argmax|g|`), used by `run()`, the deflation grow (`_grow_deflated`) and the subspace grow — so a subclass changes *which* operator grows the ansatz without touching convergence (`max|g| < tol`, computed independently of selection).
- `src/mandacaru/algorithms/hartree_fock.py` — `RHF` (closed-shell SCF; supplies the **molecular-orbital basis** so ADAPT's HF reference is stationary and singles have zero gradient) and `UHF` (`run()` → energy, for the isolated-atom references; `solve()` → `UHFResult` with both spin-orbital sets, the **natural orbitals** of `D_α+D_β` (`natural_orbitals`, occupation-ordered) and `h_mo`/`eri_mo` in that basis, plus `reference_energy` of the NO determinant and `spin_contamination`). **Open shells (2026-09-09):** `MolecularIntegrals.molecular_hamiltonian(mo_basis=True, n_electrons, num_particles=(nα,nβ), open_shell=None)` uses RHF for even counts and the **UHF natural-orbital basis** for odd counts (or `open_shell=True`), one spatial basis for both spins so the α/β-block spin-orbital form and everything downstream (pools, ansätze, mappings, frozen core, dry run) are unchanged; the NO reference is not stationary, so ADAPT also selects singles (fine). `resolve_num_unpaired` makes an odd count a doublet by default (`spin` is now only a compatibility flag; magmoms select quartets etc.), `_num_particles` checks parity instead of refusing odd counts, `resolve_frozen_core(..., n_doubly=n_beta)` freezes only doubly occupied NOs; the **PW** basis still refuses odd counts (RHF-only). `VQE` now stores `num_particles`/`n_spatial_orbitals` like ADAPT; `adapt_vqe._max_abs` treats an **empty pool** (H atom: 1 electron, 1 orbital) as converged instead of crashing on `max([])`. Pinned by `test/test_open_shell.py` (H, H₃ doublet/quartet, Li frozen core, H₂⁺, OH dry run; ADAPT/VQE reach the sector FCI computed by `_sector_ground_state`).
- `src/mandacaru/algorithms/bloch.py` — the **general (1-/2-/3-D) periodic-system driver `BlochCalculator`** — a single class whose variational solver is selected by `method="adapt-vqe"` (default) / `"vqe"`, mirroring `Mandacaru`. Takes an ASE `Atoms` *primitive cell* (`atoms.cell`/`atoms.pbc` define the lattice and periodic directions). `bands(kpts)`/`band_structure(path)` solve the single-particle **Bloch Hamiltonian** `H(k)c = ε(k)S(k)c` at each k-point — the cell-to-cell overlap/one-body blocks `S^{(R)}`,`h^{(R)}` are built from the FAO real-space integrals over a lattice window, the Bloch phase is the dimension-general `exp(2πi k·n)` over integer translations, and (being single-particle) the bands are **identical across the three methods**. `total_energy(kmesh, **solver_kwargs)` gives the **total energy per cell using all k-points** via the **Born–von Kármán equivalence** (an `(n1,n2,n3)` mesh ≡ Γ-point on the `(n1,n2,n3)` supercell): it builds the supercell with `atoms.repeat`, runs it through a molecular `Mandacaru(method=self.method, ...)`, and returns `(E(supercell)/n_cells, result)` where `result` is the method's `VQEResult`/`ADAPTVQEResult` (read from `calc.result`; a finite-supercell estimate exact in the infinite-mesh limit; k-points come from ASE `monkhorst_pack`). `band_structure` returns `BandStructure` (x/energies/xticks/labels/kpts). See `examples/07_ADAPTVQE_H_chain_bands.py` and `examples/11_Bloch_crystals.py`.
- `src/mandacaru/algorithms/expressivity.py` — PQC **expressibility** (Sim *et al.* 2019): random-parameter state fidelities vs the Haar distribution scored by KL divergence (`compute_expressibility`, `calculate_kl_divergence`, `calculate_haar_distribution`). The Haar reference dimension is the *number-conserving sector* `d = C(M,nα)·C(M,nβ)` (`active_space_dimension`) or the empirical span rank (`estimate_effective_dimension`), **not** `2^N` — the fermionic ansätze never leave their symmetry sector. `ADAPTExpressivityTracker` / `track_adapt_expressivity` hook `ADAPTVQE.run(callback=...)` to log expressibility as the ansatz grows.

`backends/hardware.py` is the device registry (`AER_simulator`, IBM Quantum via Qiskit Runtime, Amazon Braket) and `utils/logging.py` is the ADAPT `output.txt` protocol (`AdaptOutputLogger`/`parse_output`). ADAPT-VQE is driven as `atoms.calc = Mandacaru(method="adapt-vqe", pool=..., basis="FAO", mapping=..., optimizer=..., gradient=..., device=...)`; `atoms.get_total_energy()` builds the Hamiltonian from the geometry and runs the loop, returning eV with the result on `atoms.calc.result`. `optimizer` takes a method name or an `Optimizer`; `gradient` is `"analytic"` (default) / `"finite_difference"` / `"parameter_shift"`. `run()` takes no required arguments (`max_iterations` / `gradient_tolerance` / `output` default to the constructor values) and prints the qubit Hamiltonian's **term count only**, then a column-aligned iteration table (one line per grown operator: `iter | |grad| | E (eV) | dE | expr | cnot | 1q | depth | type | operator`); neither the pool nor the selected operator's Pauli expansion is printed — they live on `result.operators` and, with `verbose_operators=True`, in `pool.json`. The class is `ADAPTVQE` and its result dataclass `ADAPTVQEResult` (no `AdaptVQE`/`AdaptVQEResult` aliases).

Both drivers also accept `kpts` (Monkhorst-Pack mesh via ASE — a `(n1,n2,n3)` triple or the ASE dict; the engine is Gamma-point/molecular, so a denser mesh is generated and exposed on `.kpoints` but rejected at run with `NotImplementedError`), `spin` (bool, default False — high-spin reference), `initial_state` (default `"hartree-fock"`, validated), and the **frozen-core approximation** `frozen_core`/`frozen_orbitals` (`True`/`"auto"` freezes the chemical noble-gas core, an int freezes that many lowest MOs, or `frozen_orbitals=[...]` names exact spatial-MO indices; core orbitals leave the active space via `core.hamiltonian.freeze_core_integrals` — a constant core energy plus an effective one-body potential — so the ansatz/pool/qubit count shrink. Resolved by `core_electrons`/`resolve_frozen_core` in `_hamiltonian_from_atoms.py`; PW rejects it). The **initial spin state** is read primarily from the geometry's initial magnetic moments (`Atoms(..., magmoms=[1,1])` -> a triplet, via `resolve_num_unpaired`); the `spin` bool is the fallback. ADAPTVQE also takes **`sparse`** (default `"auto"` -> sparse pool for `n_qubits >= 12`): the Hamiltonian and pool generators stay scipy-sparse (`PauliSum.to_sparse_matrix`), screening uses the exact analytic gradient, and `AdaptAnsatz` applies `exp(theta A)` through the closed form `I + sin(theta) A + (1-cos(theta)) A^2` (valid because the excitation generators satisfy `A^3 = -A`; `scipy.sparse.linalg.expm_multiply` otherwise), so only the few *selected* operators are ever densified and 12+-qubit active spaces stay tractable.

The ASE-calculator path **softens the -Z/r cusp to half a grid step** (`MolecularIntegrals(..., softening=)`) so a nucleus landing on a grid node no longer produces a garbage core integral (needed since FAO uses the bare Z), and centers the grid on the molecule (minimum-image via ASE `find_mic`), so placement in the cell is irrelevant. `run()` writes the start-up banner once per process (`utils/banner.py` — `lines()` renders it, `show()` writes those lines to stdout) *before* anything is written to `output.txt`, and the same `lines()` go once into the top of the log. `MolecularIntegrals.hartree_fock_hamiltonian(n_electrons)` reduces the full Hamiltonian to the mean-field (diagonal orbital-energy) HF `Fermion` whose ground state is the HF determinant at the RHF total energy. The `basis` argument accepts a name **or** a `{"name": ..., <options>}` dict (`resolve_basis` in `_hamiltonian_from_atoms.py`): `{"name":"FAO"}`, `{"name":"NAO","energy_shift":0.03}`, `{"name":"NAO-AE","tier":1}`, `{"name":"GTO","n_gaussians":3}`, `{"name":"6-31G(d)"}`, or the periodic `{"name":"PW","energy_cutoff":300}` (routes to `PlaneWaveIntegrals`; requires `atoms.cell`).

Also implemented on the shared `VariationalDriver` (so VQE / ADAPTVQE and their subspace variants all accept them):

- **Hamiltonian disk cache** (`core/serialization.py` — `save_hamiltonian`/`load_hamiltonian`/`HamiltonianRecord`/`detect_format`). Two interchangeable formats selected by `hamiltonian_format="parquet"` (default) or `"json"`: Parquet is a compressed columnar table of `pauli`/`real`/`imag` rows with the problem spec in the key/value metadata (~4x smaller than JSON); JSON is the same content as plain text and needs no Parquet engine. `save_hamiltonian=True|"path"` dumps the qubit Hamiltonian after it is built; `load_hamiltonian="path"` reads it back — **auto-detecting the format** from the extension, else from the leading bytes (`PAR1` vs `{`) — and **bypasses the integral engine and the fermion-to-qubit mapping entirely**. Parquet has two engines (`engine="fastparquet"` default, `"pyarrow"`); fastparquet leads deliberately because pyarrow's Parquet writer can segfault in a process that has also run Qiskit's `transpile` (reproduced on CPython 3.14 / qiskit 2.5 / pyarrow 25) — `hamiltonian_format="json"` avoids the issue entirely. Because the file records `num_particles`/`n_spatial_orbitals`, a loaded driver is in *direct mode with no geometry* — `Mandacaru(method="adapt-vqe", pool=..., load_hamiltonian=...).run()` works without any `Atoms`, and `method="vqe"` rebuilds its default UCCSD from the file. (The *pool*'s own excitation generators are still mapped — that is a different operator.)
- **Multi-backend circuit providers** (`backends/providers.py` — `CircuitProvider` + `QiskitProvider`/`BraketProvider`/`CirqProvider`, `build_provider`/`normalize_provider`/`provider_available`). `backend_provider="qiskit"|"braket"|"cirq"` (default follows the `device`, else `"qiskit"`) selects the SDK; `execute_circuits` (default `True` for braket/cirq, `False` for qiskit) makes state preparation *run a real circuit* on that SDK's local state-vector simulator instead of the internal NumPy/sparse backend. Each anti-Hermitian generator `A = Σ i c_j P_j` has mutually commuting terms, so `exp(θA) = Π exp(iθc_j P_j)` factorizes **exactly**; each factor is a basis change + CNOT ladder + `Rz(-2θc_j)` + uncompute, emitted once by `CircuitProvider._emit` in a shared `{x,h,s,sdg,cx,rz}` gate set and translated per SDK. Qiskit is little-endian so Mandacaru qubit `k` is laid on wire `n-1-k`; Braket and Cirq are big-endian like Mandacaru. Wired into `AdaptAnsatz(provider=...)` and `UCCSD(provider=..., trotter=True)` (a circuit realizes the Trotter product, so UCCSD raises without `trotter=True`); `profile_ansatz(..., provider=)` counts gates/depth per SDK. Circuit execution only handles computational-basis (determinant) references — HF and the SSVQE references — and raises otherwise. See `examples/12_ADAPTVQE_LiH_backends.py` (LiH across all three, agreeing to ~5e-8 Ha).
- **Amazon Braket / real QPUs.** `BraketProvider(device=..., shots=...)` targets either the local simulator or the **AWS service** by ARN (`AwsDevice`). Verified constraint: Braket rejects the `StateVector` result type whenever `shots > 0`, and every QPU requires `shots > 0` — so the exact path is simulator-only. The QPU path is shot-based: `backends/measurement.py` partitions H into **qubit-wise-commuting groups** (`qubit_wise_commuting_groups`/`merge_basis`/`energy_from_counts`/`shot_noise_estimate`), submits one measurement circuit per group with the basis rotation appended, and assembles ⟨H⟩ from bit-string counts (118 Pauli terms → 29 circuits on LiH; error falls as 1/√shots). `hardware.py` now carries a `Device` registry with the Braket entries (`braket-local`, `braket-sv1`/`dm1`/`tn1`, `braket-ionq-aria`/`forte`, `braket-iqm-garnet`, `braket-rigetti-ankaa`, plus any raw ARN) and `device_arn`/`device_provider`/`is_aws_device`/`requires_shots`; a QPU named without `shots` is refused in the constructor. Drivers take `shots`/`backend_options` and route the cost through `VariationalDriver.ansatz_energy`. **Limitation:** only the energy evaluation is hardware-native — ADAPT-VQE's pool-gradient screening is still classical, so a fixed-ansatz `VQE` is the fully hardware-native driver today. See `examples/13_braket_aws_compatibility.py`.
- **IBM Quantum hardware (2026-09-11), Estimator-based.** `QiskitProvider(device="statevector"|"fake_<name>"|"ibm-quantum"|"ibm_<name>"|"ibm_a,ibm_b,...", shots=, instance=, token=, channel=, optimization_level=3, estimator_options=, physical_qubits=)` has `supports_shots=True`; with `shots > 0` the energy is the **Estimator** expectation value of the Hamiltonian as a `SparsePauliOp` (`observable()` = `PauliSum.to_sparse_pauli_op()` — Mandacaru labels coincide with Qiskit labels because qubit `k` sits on wire `n-1-k`; `pub()` = `transpile(qc, backend=backend)` + `observable.apply_layout(isa.layout)`). Targets: `"statevector"` -> `qiskit.primitives.StatevectorEstimator(default_precision=1/sqrt(shots))` (exact for shots=0); `fake_*` -> `qiskit_ibm_runtime.fake_provider.Fake<Name>[V2]` run by `BackendEstimatorV2`; `"ibm-quantum"` -> `QiskitRuntimeService().least_busy(operational=True, simulator=False)`, `ibm_x` -> `service.backend`, a comma list -> the least busy operational one of those (`_ibm_backend`), then `qiskit_ibm_runtime.Estimator(mode=backend, options=estimator_options)`. `energies(problems)` submits **one job with one PUB per problem**; `energy()` wraps it; `last_result` holds the `PrimitiveResult`, `last_job` the Runtime job. **Both local primitives are driven through their synchronous `_run([EstimatorPub.coerce(pub, precision)])`, never `run()`:** `run()` executes on a one-off `ThreadPoolExecutor` thread and Qiskit circuit data allocated on another thread makes a later garbage collection spin forever in Qiskit's Rust mimalloc (macOS / Python 3.14 / qiskit 2.5; `RAYON_NUM_THREADS` and `QISKIT_PARALLEL` do not help). `hardware.py` marks `ibm-quantum` runnable and `requires_shots`, and passes `ibm_*`/`fake_*` names verbatim (`IBM_PREFIX`/`FAKE_PREFIX`, `is_ibm_device`/`is_fake_device`). Driver plumbing: `shots > 0` is allowed for `"qiskit"` (cirq still refused); `_provider_options` passes `device`/`shots` only when shots or an IBM/fake device are involved; **`ansatz_provider()`** is `None` whenever `shots > 0` (the ansatz prepares states internally for ADAPT's screening, while energies go through `ansatz_energy` -> `provider.energy`; `VQE` uses `trotter=True` then); a dry run may name hardware without shots. **Budget-friendly use — optimize locally, measure once:** `ADAPTVQE.run` keeps `self.ansatz`, `VariationalDriver.ansatz_problem(theta=None)` -> `(n_qubits, occupied, generators, theta, hamiltonian)`, `measured_energy(provider)` evaluates the optimized state on a provider, and `algorithms.base.measure_energies(drivers, provider)` measures a whole dissociation curve in **one** Estimator job. The user's IBM open plan has 10 min/month of QPU time (`service.usage()`): never run optimizations on hardware; rehearse on `fake_kingston`/`fake_fez`/`fake_marrakesh` (needs `qiskit-aer` for the idle-qubit truncation) and submit only the final job. **Two hardware lessons, paid for:** unmitigated 12-qubit LiH circuits (92 CZ, depth ~300) landed 0.5-0.8 Ha above exact, and an H2 curve on a drifted readout qubit came out *below* the exact ground state because the Estimator's readout mitigation divided by a 35 % assignment error whose calibration record claimed 0.7 % — `physical_qubits=[...]` pins the layout (Mandacaru qubit k -> `physical_qubits[k]`, mapped to `initial_layout` on the reversed wires); rank pairs by `backend.properties()` readout + CZ error and prefer a live readout check over the calibration record. On a pinned good pair the 2-qubit (parity + reduction) H2 curve landed within ~0.015 Ha of exact and *above* it at every point. Rule of thumb: keep circuits to a few tens of two-qubit gates. Raw data in `examples/data/h2_dissociation_ibm*.{csv,json}` and `lih_dissociation_ibm.{csv,json}`; plots `examples/plot_h2_ibm.py` / `plot_lih_ibm.py`. Pinned by `test/test_ibm_quantum.py` (local estimator, `fake_manila`, mocked service for device selection, ADAPT/VQE end to end with shots, `measure_energies`); examples `24_ADAPTVQE_LiH_IBM.py` and `25_ADAPTVQE_H2_IBM.py` (which carries a `PHYSICAL_QUBITS` constant).
- **Parity-reduced mapping.** `mapping="parity_reduced"` tapers the two parity qubits fixed by the particle numbers consistently across the Hamiltonian, operator pool, ansatz, particle sector, checkpoints, cached Hamiltonians, forces, and dry-run estimates. The mapping name is the sole source of the register representation. `FermionicPool`, `QEBPool`, and `CEOPool` support it; `QubitPool` and the subspace solvers refuse it because their operators or reference determinants are not tapered. H₂/FAO uses 2 qubits instead of 4 while retaining the untapered energy.
- **Dynamic parametrization** `quenching` (default `True`). `True` re-optimizes **all** parameters each iteration (standard ADAPT-VQE — this is what reaches FCI). `False` optimizes only the newly appended parameter and freezes every earlier one at its prior optimum (a 1-D line search per growth step: far cheaper, variationally weaker). Implemented once on the base as `_optimize_grown` (used by `ADAPTVQE.run`, `_grow_deflated` and `SubspaceADAPTVQE._subspace_optimize`) and `_optimize_all` (used by `VQE.run`/`_deflated_ground`/`SubspaceVQE`, where `quenching=False` means a one-parameter-at-a-time sweep over the fixed ansatz).

**No `vacuum` argument anywhere (removed 2026-09-15).** The real-space box is **always the geometry's `atoms.cell`**: `Mandacaru` lost `vacuum` (its frozen force grid is now `grid_from_cell(atoms, h)` — the same grid a single-point energy uses, centered on the molecule, no padding), `BlochCalculator` lost `vacuum` (the band-structure grid is the nuclei window `(2·n_images+1)` cells along each periodic axis × the primitive cell along the open axes, via `Grid(cell=window[:, None] * cell)`; `supercell(kmesh)` is plain `atoms.repeat(kmesh)` with the repeated cell and **no extra padding** — the primitive cell is what the user sizes; a zero-length lattice vector raises), and the CLI lost `--vacuum` (a geometry file must carry a cell — extxyz `Lattice`, CIF, POSCAR — and a bare g2 name needs an explicit **`--cell L | Lx Ly Lz | 9 components`**, `cli.parse_cell`, which centers the molecule; without either `load_geometry` exits with a clear message). A geometry without a cell raises `ValueError(missing_cell_message(h))` (`_hamiltonian_from_atoms.missing_cell_message`) telling the user to define the cell in the geometry (`atoms.center(vacuum=3.0)` on the ASE side is geometry, not calculator, and stays the idiom in tests/docs). Pinned by `test/test_dry_run.py` (`--cell`, the no-cell exit), `test/test_forces.py` (frozen grid from the cell), `test/test_bloch.py`. **Documentation style rule (2026-09-15):** in every documentation page (`docs/source/**`, README, `docs/experimental/*.md`, the website's `content.py` snippets) and every example script, `Mandacaru(...)` and `BlochCalculator(...)` constructor calls are written one argument per line, continuation lines aligned with the first argument, `method=` first (`calc = Mandacaru(method="adapt-vqe",\n                 basis={"name": "PAW", "size": "DZP"},\n                 h=0.20,\n                 pool="fermionic")`); single-argument calls may stay on one line; tests may keep compact calls. The reflow was done mechanically (a script splitting top-level arguments, inserting `method="adapt-vqe"` where a multi-argument call omitted it) — keep new snippets in that shape.

**Pseudopotentials — part of the main API (graduated 2026-09-15).** The whole feature lives in `src/mandacaru/pseudopotentials/` (`generation.py`, `io.py`, `orbitals.py`, `families.py`, `oncv.py`, `paw.py`, `link_library.py`, the library in `library/ncpp/` plus the git-ignored `library/oncvpsp` and `library/paw` **symlinks**, re-created with `python -m mandacaru.pseudopotentials.link_library --oncvpsp DIR --paw DIR`; `io.library_root()` is the parent (env `MANDACARU_PSEUDO_PATH`), `default_library_path()` = `ncpp/`). Tests are `test/test_{pseudo_io,pseudopotential,pseudopotential_engine,ncpp_family,oncvpsp,paw,link_library}.py` (together ~340 tests / 50 s / 2.4 GB; the project-wide `test/conftest.py` times every test and reads its peak RSS into `test/.resource_report.txt` — budget: test < 3 min, suite < 10 min, RSS < 8 GB), examples `26_pseudopotential_generation.py` / `27_pseudopotential_calculations.py`, guide `docs/source/guide/pseudopotentials.md`. `mandacaru.experimental` holds only VASQE.

**The selector is the `basis` argument — there is no `pseudopotentials=` argument anywhere:** `basis="NCPP"` (aliases `"TM"`, `"NCPP-TM"`), `"ONCVPSP"` (alias `"ONCV"`), `"PAW"`, `"UPAW"`, or the dict form with the size hierarchy `{"name": "PAW", "size": "DZP", "split_norm": ..., "directory": ...}` (every family also takes `tail_norm`; PAW/UPAW also take `projector_basis`, `energy_shift`, `confinement`, `polarization`, and default `filter` to on), exactly like `"FAO"`/`"NAO"`/`"cc-pVTZ"`; the per-element form `{"O": {"name": "PAW", "size": "DZP"}, "H": "PAW"}` works with sizes per element within ONE family (mixing a pseudo family with an all-electron family, or two pseudo families, raises a clear `ValueError`). Plumbing: `_hamiltonian_from_atoms.pseudopotential_family(name)` -> `FamilySpec | None` via `families.lookup_family` (the registry is the single source of truth, so `register_family` makes a new family a basis name with no driver edit); `resolve_pseudo_basis(name, options, symbols)` handles the per-element case; `build_basis_hamiltonian(atoms, basis, grid, h, charge, n_electrons, spin, frozen_core, frozen_orbitals, kinetic)` dispatches to `_pseudopotential_hamiltonian(..., family, options, kinetic)`, which validates the option keys against `FamilySpec.options` (default `COMMON_OPTIONS` = size/split_norm/directory) — an unknown key raises at driver construction (`VariationalDriver._check_pseudo_basis`), as does `frozen_core` with a pseudo basis. `dry_run.count_basis_functions(atoms, basis)` / `estimate_qubits(..., basis=)` count the pseudo basis (label `"PAW (DZP, pseudopotentials)"`). The old `"PP"`/`"PSEUDO"` basis names are a **deprecation error** (`RETIRED_PSEUDO_BASIS_NAMES`, `_check_retired_basis_name`) pointing at the new spelling — no silent aliasing.

**The family registry** is `families.PSEUDO_FAMILIES`: `FamilySpec(name, description, generate, get, build, norm_conserving, aliases, options)` with `register_family`/`unregister_family`/`resolve_family`/`lookup_family`/`canonical_family_name`/`family_names`/`family_listing`; unknown names raise a `ValueError` listing the registry. `_pseudopotential_hamiltonian` is a thin dispatcher — `family.build(atoms, grid, h, charge, spin, options, kinetic)` returns the usual 5-tuple. `PseudoPotential.family` is written and read by `io.py` (`FORMAT_VERSION` 2; a v1 file without the field loads as `LEGACY_FAMILY`), and the canonical Troullier-Martins key is **`"ncpp"`** (aliases `("tm", "ncpp-tm")`, `FamilySpec.label` = `"NCPP"`) — the shipped library files still say `"tm"` and are canonicalized on load.

**NCPP (Troullier-Martins).** Norm-conserving TM pseudopotentials with **Kleinman-Bylander** projectors, generated from scratch by an LDA radial atomic solver (`basis/atomic_solver.py`). The nonlocal term is the general separable form `H_NL = C D C+`: `C = projections()` (M x P, cached, C kernel `kb_projections`, fills `kb_resolution_ratios`), `D = nonlocal_coupling_matrix()` block-diagonal over `(atom_index, l, m)` from `nonlocal_coupling` (`core.hamiltonian.projector_blocks`/`assemble_block_matrix`; `None` -> the projectors' `kb_energy` diagonal). `MolecularIntegrals.kb_nonlocal()` (alias `nonlocal_matrix`) evaluates it; `KBProjector` carries `atom_index`, `channel=(l,m)`, `index` (radial projector within the channel, 0 for KB), `block_key`, and accepts `radial=`/`kb_energy=` overrides, with `orbitals.kb_coupling_blocks(projectors)` giving the TM `[[E_KB]]` blocks. **Overlap hook:** `nonlocal_overlap` (PAW's `q_ij`; TM passes `None`) makes `overlap()` = `bare_overlap() + C Q C+`, which feeds `_lowdin_x` and hence every orthonormalized integral / RHF / UHF-NO path (`Q = 0` reproduces the plain Hamiltonian exactly). Pinned by `test/test_ncpp_family.py`: H2 RHF -1.061096 / FCI -1.075333 Ha, LiH RHF -0.729555 / FCI -0.740839 Ha (re-pinned by ~1e-8 Ha when the FFT self-energy became exact; the old values stay under `before_exact_self_energy`). H and Li have one (local) channel, so H2/LiH carry no TM projectors.

**ONCVPSP** (`oncv.py`, Hamann PRB 88, 085117; family `"oncvpsp"`, alias `"oncv"`). Construction: `bound_state` (Numerov outward/inward shooting; `generation_points(Z)` = max(6000, 1500 Z); `_origin_seed` is a **six-term power series** — the two-term one admixes the irregular solution) and `scattering_wave` at `eps_1 + energy_offset` -> `optimize_pseudo_waves` (8 spherical Bessel functions at the **interleaved zeros of j_l and j_l'** — the RRKJ log-derivative roots make the third-derivative row linearly dependent — constraints value + 3 derivatives from the AE radial equation (`matching_targets`) plus generalized norm conservation, residual kinetic energy beyond `q_cut` = 5 Bohr^-1 minimized **exactly** by null-space elimination and a 1-D Lagrange-multiplier root, `constrained_minimum`) -> `polynomial_local_potential` (even polynomial inside `r_cut_local` = 0.9 min r_c, optional `local_shift`) -> `assemble_channel` (analytic projectors, `B_ij = <phi~_i|chi_j>` asserted symmetric to `B_ASYMMETRY_TOLERANCE` 1e-6 — needs cubic-spline resampling and the ODE-based targets — `D = B^-1`) -> unscreen with the TM machinery. Records `ONCVPseudoPotential`/`ONCVChannel` (two projectors and a 2x2 coupling block per l, `v_local_screened`); `io.py` dispatches on the family (`oncv.to_payload`/`from_payload`, tables under `radial_tables`). Library `library/oncvpsp/` (`build_oncv_library`, `get_oncv`, `oncv_library_path`; `DEFAULT_CUTOFFS` H 1.30 / Li 2.60 / C 1.50 / N 1.45 / O 1.45 / F 1.40 Bohr — Li at 2.2 or 3.3 grows a ghost, 3.0 shifts LiH by 0.15 Ha). Molecule path `build_oncv` mirrors the TM one with `oncv_projectors` (two `KBProjector`s per (atom,l,m)) and `oncv_coupling_blocks`. Diagnostics: `check_oncv_channel`, `radial_spectrum` (3-point Laplacian + Richardson — a 5-point stencil breaks the Dirichlet origin for l=0), `log_derivative_ae`/`log_derivative_ps`, `report_oncv`, `diagonalized_projectors`. Validation (`test/test_oncvpsp.py`, 50 tests): eigenvalues <= 1e-7 Ha, log derivatives <= 1.7e-4 at the references; **H2 (h=0.25) RHF -1.044179 / ADAPT -1.058561, LiH (h=0.30) RHF -0.774343 / ADAPT -0.782341 Ha**. Known limits: no NLCC, no relativistic terms, no projectors above the valence l, |D| up to ~300 Ha (the two partial waves are nearly proportional in the core; harmless to first order). ONCVPSP still **grid-samples its projectors** — the exact on-site quadrature exists only in `PAWIntegrals` — which makes its O/C curves erratic at the +-3 eV level; prefer PAW there.

**PAW** (`paw.py`, Bloechl PRB 50, 17953; family `"paw"`, `norm_conserving=False`, extra option `projector_basis="raw"|"dual"`). Frozen-core, one-center-expansion form with the one-center terms **linearized** at the LDA reference (fixed `D^ion` per species plus the constant `one_center_energy`). `generate_paw` -> `PAWDataset`/`PAWChannel`: the ONCV Numerov pair (`DEFAULT_ENERGY_OFFSETS` H/Li 0.5 Ha, else 1) -> `smooth_partial_waves` = `oncv.optimize_pseudo_waves(..., norm_factor=1-s)` so the inner-norm matrix is scaled and `q = s <phi_i|phi_j>_rc` is **positive definite by construction** (`DEFAULT_NORM_DEFICITS` H 0.05 / Li 0.02 / C 0.10 / N,O,F 0.15; free waves gave an *indefinite* q and a singular `1 + sum |p~>q<p~|`, which `assemble_paw_channel` refuses via `OVERLAP_MINIMUM`) -> `polynomial_local_potential` with **`DEFAULT_LOCAL_SHIFTS`** C 12 / N 10 / O 6 / F 8 Ha (without them the continued potential binds a 1s-like ghost 0.6-1 Ha below eps_2s in the first-row s channel) -> `chi_i = (eps_i - T - v~) phi~_i`, `B_ij = <phi~_i|chi_j>`, dual projectors `p~_i = sum_k (B^-1)_ki chi_k` (duality asserted to `DUALITY_TOLERANCE` 1e-8, achieved 1e-14), `q`, `dT`, `dV`, `D^scr = B + eps_j q_ij` (= `dT + dV` to 1e-15, `consistency_error`) -> monopole compensation charge with `compensation_shape` `(1-r^2/r_g^2)^3`, `r_g = min r_c`, analytic `compensation_potential` -> unscreen `v~^ion` -> `D^ion` and `one_center_energy` (the Hartree/xc double-counting difference that makes the LDA reference atom exact). Molecule path `build_paw` -> **`PAWIntegrals(MolecularIntegrals)`** with `datasets=`: `paw_projectors`, `paw_coupling_blocks` / `paw_overlap_blocks` (via `PAWDataset.projector_set(l, basis)` — `"raw"` samples the smooth chi_k, `"dual"` the p~; identical energies, only the resolution ratio differs), **exact on-site projections** (`projections()` overrides same-center entries by radial quadrature — grid sampling gave 0.7-3x the exact value depending on the nucleus/node offset and collapsed LiH by 0.2-0.6 Ha), the **augmented two-body tensor** (`two_body_augmentation`: pair densities + `Q^A g_A`, `compensation_moments`, `compensation_potentials` W, `compensation_coulomb` U — exact 1/R for disjoint spheres, Gauss-Legendre when overlapping) and `one_body_augmentation` (see the compensation-charge section). Two hooks were added to `core/hamiltonian.MolecularIntegrals` for this and are inert elsewhere: `two_body_augmentation()` (None by default, added to the grid ERI before Loewdin) and `constant_energy` (0; added with the nuclear repulsion). Diagnostics: `check_paw_channel`, `paw_spectrum` (generalized `eigh(H, S)` + Richardson), `paw_eigenstate`, `reconstruct_ae`, `log_derivative_paw`, `report_paw`. Library `library/paw/` (`build_paw_library`, `get_paw`, `paw_library_path`; 9.6 s to regenerate). Validation (`test/test_paw.py`, 70 tests): duality <= 1e-14, eps_1 reproduced to <= 1.2e-7 Ha with no ghost, AE reconstruction <= 6.5e-5, `q_11` H 0.0212 / Li 0.0045 / O 0.114; **H2 (h=0.25) RHF -1.095396 / ADAPT -1.109168, LiH (h=0.30) RHF -0.773001 / ADAPT -0.780800 Ha** (the pre-2026-09-17 table is kept beside it as `PAW_BEFORE_COMPENSATION_ATTRACTION`). Omitted vs Bloechl: self-consistent `D_ij[rho]`, NLCC (`smooth_core_density` stored, unused), relativity, GGA, projectors above the valence l.

**Sizes, library coverage and storage.** The basis dict's options are the size hierarchy: `{"name": "PAW", "size": "DZP", "split_norm": ...}` reaches `pseudo_basis(..., size=)`, which builds the split-valence zetas *from the pseudized orbital* (polarization split off the outermost channel); the first zeta must stay the pseudopotential's own orbital (the KB projectors were built from it), and `size` defaults to `"SZ"`. An all-electron family can never be paired with a pseudopotential — the family *is* the basis. The shipped library covers **every element with Z <= 92** (`LIBRARY_Z_MAX = 92`, regenerable with `build_library()`); the ONCVPSP (110 MB) and PAW (190 MB) libraries live in the sibling repositories `mandacaru-oncvpsp` / `mandacaru-paw` (flat `<Symbol>.parquet`) and are linked in, never committed (`link_library(family, source, root=, files=, force=)`, `status()`, per-file links with `--files`; pinned by `test/test_link_library.py`, whose real-loader test skips when the links are absent). Storage is **Parquet by default** with **JSON** retained (`PSEUDO_FORMATS`); `load_pseudopotential` **auto-detects** the format from the extension, falling back to magic bytes (`PAR1` vs `{`). `save_pseudopotential` is lossless and idempotent (`stride=1`); the `STRIDE=4` decimation applies only at `build_library()` time, where the fine generation grid exists — applying it per-write made load->save compound. **Beware the pandas/pyarrow/qiskit interaction:** pandas 3 defaults `future.infer_string` on, so even a *fastparquet* read builds its column index as a pyarrow string array, and after Qiskit's `transpile` has run in the same process that decode corrupts (`UnicodeDecodeError` / `ArrowException`). Every Parquet read therefore goes through `core.serialization.native_pandas_strings()` — keep new Parquet paths inside it. (Separately, importing pandas *after* qiskit's transpile segfaults at interpreter shutdown; importing it first is fine.)

**PAW / ONCVPSP forces, particle-number sectors, real orbitals (2026-09-15).** `atoms.get_forces()` with a pseudopotential basis goes through `algorithms/pseudo_forces.pseudo_nuclear_gradient`: the energy `E = sum D h^MO + 1/2 sum Gamma g^MO + E_ion + E_1c` with `h^MO = A+ h A`, `A = S^-1/2 V` is differentiated with the spin-summed RDMs (`spatial_rdms`) and the MOs `V` (`MolecularIntegrals.mo_coefficients`, set by `molecular_hamiltonian`) held fixed — exact for an orbital-stationary state, with `details["orbital_gradient"]` measuring the residual. Hellmann-Feynman = operators move (local potential, projectors in `C D C+` and `S = S~ + C q C+`, compensation `W`/`U`, ion-ion); Pulay = basis functions move (`S~`, `T`, `V_loc`, `C`, grid ERI, `W`). Matrix derivatives come from displaced sampling on the frozen grid, contracted as a central-difference directional derivative of `AlgebraicEnergy(S, h, g)` (complex-safe, no energy-weighted density matrices). The calculator refuses a force whose rebuilt energy differs from the solver's by more than `ENERGY_CHECK_TOLERANCE` (1e-6 Ha). Validated analytic vs central difference of the fixed-state energy at **8.6e-5 eV/Angstrom** (H2 PAW-DZP, h = 0.25).

**Three fixes are load-bearing and must stay.** (1) **`PAWIntegrals.projections()` are atom-centered spherical quadratures** (`atom_centered_projections`, 64x24x48 points over each projector sphere; `atom_centered_projection_gradients` gives `G = <dphi/dR|p>`, Pulay `+G`, HF `-G`; `exact_projections = True`) — grid-sampled projections put a 3.9 eV nonlocal egg-box on H2 at h = 0.25 and 2 eV/Angstrom force errors; the remaining egg-box (kinetic/local/Hartree) is 18/13/5 meV at h = 0.25/0.20/0.15. (2) **`PAWDataset.local_potential` is a cubic spline** (C2, `_local_spline`, cached by id) — `np.interp` kinks made derivatives step-dependent at 2e-2 eV/Angstrom. (3) **Conjugation-real MOs** (`core.hamiltonian.conjugation_real_orbitals`, `MolecularIntegrals.conjugation_matrix`/`real_orbitals`, applied in `molecular_hamiltonian` for RHF and UHF-NO, rotating only within the occupied/virtual blocks): complex `Y_lm` orbitals leave the SCF with arbitrary phases and mixed degenerate pairs, the MO ERIs pick up imaginary parts (5.7e-2 Ha on H2 DZP), and every real pool then **stalls** (ADAPT 62 meV above FCI with every optimizer, 0.05 eV/Angstrom force error); with real MOs ADAPT reaches the sector FCI to 1e-9 eV. This affected every l > 0 basis, not just PAW.

**Particle-number sector** (`core/sector.py`): `ParticleSector(n_qubits, (n_alpha, n_beta), mapping)` with `restrict`, `positions`, `basis_vector`, `embed`, `project`, `apply_pauli_sum`. `restrict(PauliSum, max_entries=None)` builds the CSR on the sector by bit masks, **folded in batches of `RESTRICT_BATCH_ENTRIES = 8_000_000` staged entries**: every Pauli term contributes one entry per sector state, so holding them all before de-duplicating costs `len(terms) x dim` (OH in PAW-DZ — 14,707 terms, dim 25,200 — staged 3.7e8 entries, about 12 GB, for a 16.5M-nonzero result and died climbing past 2.35 GB). Folding batch by batch is exact (the sum is linear in the terms; pinned bit-identical down to `max_entries=1`) and brings that case to 33.5 s / 2.74 GB peak. `ADAPTVQE(sector="auto")` materializes H and the pool on the sector for `n_qubits >= SECTOR_AUTO_QUBITS = 16` (no circuit provider, not the subspace solvers) — H2/LiH PAW-DZP are 20 qubits but 100 states; `AdaptAnsatz(sector=)` and `rdm.one_rdm/two_rdm(..., sector=)` follow (not with `mapping="parity_reduced"`). Also: **`Fermion.map_to_qubits` accumulates in place** — `result = result + op` copied the whole sum per term and took 22 s of a 24 s H2 DZP run.

**Two radial on-node bugs, both fixed and both still load-bearing.** (1) `multizeta.TabulatedOrbital.radial` and `nao.NumericalAtomicOrbital.radial` evaluated their `CubicSpline(extrapolate=False)` below the first table point, got NaN and returned 0, so every s function vanished within ~0.005 Bohr of its own center and a nucleus sitting **exactly on a grid node** (a symmetric molecule centered in its cell) lost the orbital's peak sample: LiH PAW-DZP -18.31 instead of -21.28 eV, H2 -29.76 instead of -31.72 eV. Both now continue as `R(r0)(r/r0)^l` below `r0`, and the rigid-shift ripple is back to 23 meV (LiH) / 14 meV (H2) at h = 0.20. (2) `pseudo_basis` built the polarization shell from the outermost channel's radial function *itself*, so `R_p(0) != 0` and the p function was discontinuous at its own nucleus; its displaced-sampling derivative exploded on-node (analytic -8.12 vs finite-difference -5.11 eV/Angstrom). The shell is now `r^k R_outer(r)` normalized (k = 1 for the first polarization shell) — same range, vanishing as `r^l`. Both changed every pseudo-family DZP/TZP energy.

**Measured forces and the tapered register (2026-09-15).** `Mandacaru(measurement_provider=QiskitProvider(...))` optimizes the ansatz on the local state vector (never on hardware), then measures the optimized state's Pauli expectation values in **one PUB / one job per geometry** (`QiskitProvider.expectation_values(n_qubits, occupied, generators, thetas, labels)` → `({label: <P>}, {label: std})`; the provider's transpile/run code is now shared as `_transpiled` / `_run_pubs`) and takes the ASE energy **and** the forces from them: `Mandacaru._measure` collects every label of the qubit Hamiltonian and of `rdm.rdm_qubit_operators(n_modes, mapping, num_particles)` (the spin-conserving `a†_p a_q` / `a†_p a†_q a_s a_r` mapped and tapered one by one; `MAX_PAULI_RDM_MODES = 12`), assembles γ/Γ with `rdms_from_expectations`, and `_forces(solver, rdms=, reference_energy=)` checks the RDM-rebuilt energy against the *measured* one (an algebraic identity, so it validates the wiring on hardware too); the last measurement is on `calc.measurement` (`energy_eV`, `expectation_values`, `stds`, `job_id`). **Forces / geometry optimization (rewritten 2026-09-16; the old "known-broken for the all-electron path" claim is retired).** `Mandacaru` has **two** gradient implementations, selected by **`force_method`** (`calculator.py`): **`"rdm"` is the default for every basis** — the complex-safe reduced-density-matrix gradient of `algorithms/pseudo_forces.py`, generalized from the PP families to all-electron bases by `_atom_potentials(integrals)` (a dataset's `local_potential` for a pseudopotential family, else a softened `-Z/max(r, floor)` closure); `"scf-response"` is the legacy differentiated-SCF path (`algorithms/forces.py` + `_jax_energy.py`), kept for cross-checking and still restricted to real closed-shell RHF (`_check_force_support` holds the open-shell / complex-orbital / spectral-kinetic gates, which are now *legacy-only*). A **frozen core** is refilled before the RDMs are contracted (`rdm.expand_frozen_core(gamma, gamma2, frozen, n_spatial_orbitals)`; core-core `δ_pr δ_qs − δ_ps δ_qr` and core-active `δ_pr γ^act_qs − δ_ps γ^act_qr` blocks, verified *exactly* against an explicit determinant). The state is not orbital-stationary in general, so the neglected orbital-response term is **measured, not assumed**: `ForceResult.details["orbital_gradient"]` carries it and the calculator warns above `ORBITAL_RESPONSE_TOLERANCE = 1e-3` Ha. Validated against central differences of the *same* energy on the *same* frozen grid: **H2 FAO 3.6e-3 eV/Å** (largest force 9.4), **LiH FAO frozen-core 4.6e-3** on 151.1 (3e-5 rel.), **H2O FAO frozen-core 0.146** on 1186.7 (1.2e-4 rel., p orbitals + complex MOs), **H2O PAW 18.2258 analytic vs 18.2267 finite-difference** eV/Å. Pinned by `test/test_all_electron_forces.py`. **What is still true:** (a) **egg-box** — rigidly translating a molecule on a frozen grid changes E (~160 eV/Å for H2O, 23 meV for LiH at h=0.20), and the net force faithfully differentiates that non-translation-invariant discretized energy; (b) **H2O still will not relax**, but the cause is now diagnosed and is *not* the gradient: the H2O **energy surface has no bound minimum** in this model — scanning both O–H at h=0.25 gives −461.20 / −468.82 / −470.68 / −472.37 eV at 0.97 / 1.40 / 2.00 / 2.40 Å, monotonically downhill, and refining to h=0.15 (which silences the projector-resolution warning) does not change it. Fixed earlier and still load-bearing: `nuclear_gradient` used to reach past `integrals.external_potential()` to the bare `-Z/r` and omit `kb_nonlocal()`, so on the PP path (`softening=0`) it built the *wrong* h_ao and diverged at grid nodes; and `_jax_energy._scf` unrolled a fixed 40 iterations whose derivative is only valid **if the SCF converged** — H2O sat on a metastable plateau ~19 iters then escaped, and differentiating the mid-transient unroll gave ~1e8 Ha/Bohr gradients that *looked* fine. `scf_iterations_required` (plain-NumPy probe, runs untraced) now sizes the unroll via `_resolve_scf_iterations`; the caller's `scf_iterations` is a **floor**, and genuine non-convergence raises. **`mandacaru --link-paw DIR` / `--link-oncvpsp DIR` / `--pseudo-status` (2026-09-18)** — the ONCVPSP and PAW datasets are too large to ship, so setting them up is the first thing a user does after cloning, and it should not require knowing `python -m mandacaru.pseudopotentials.link_library` exists. `cli.link_library_command` wraps `link_library(family, source, force=True)` (no geometry required, like `--build-backend`): the CLI passes `force=True` because naming a path *is* the request to use it, so an existing **link** is replaced (the data repository can be moved freely) while a real non-empty `library/paw/` directory is still refused with its message and never deleted. **Dry run** (`algorithms/dry_run.py`, `cli.py`, `__main__.py`): `estimate_qubits(atoms | load_hamiltonian= | hamiltonian=)` → `QubitEstimate` (`n_qubits = 2·(basis functions − frozen)`, plus `num_particles`, per-atom function counts, the device capacity from `Device.qubits` in `backends/hardware.py`, and the state-vector memory) — it *instantiates* the basis family to count functions but never samples a grid. **NAO-AE basis** (`basis/nao_ae.py`, `NAOAEBasisSet` in `factory.py`, `BasisSet.build("NAO-AE", tier=1, onset=3.0, width=1.0, scale=1.0, extra=None, linear_dependence_tol=1e-4, tail_norm=1e-4)`): all-electron numerical atomic orbitals, generated from scratch. The minimal basis is every occupied shell (core included) of the self-consistent LDA atom (`atomic_solver.solve_atom`, which now takes a `confinement=` potential applied only in the orbital solves) re-solved in `v_free + v_cut`, where `v_cut = s·exp(−w/(r−r₀))/(r₀+w−r)²` is a smooth exponential wall (zero below the onset `r₀`, capped at `WALL_CAP` beyond `r₀+w`; `onset`/`width` are user-facing Å). Tiers add hydrogen-like states of `−z/r + v_cut` whose `z` is **derived from the atom** via `⟨r⟩ = [3n²−l(l+1)]/(2z)` (`effective_charge_for_radius`; `TIER_RADIUS_RATIOS`: polarization 1×, diffuse 2×, contracted 0.6× the valence ⟨r⟩): tier 1 = polarization at `l_max+1` + one diffuse (n+1) function per valence channel; tier 2 adds `l_max+2`, a noded `l_max+1` and a contracted function per channel (H: 1/5/14 functions, O: 5/14/30). Tier functions are shortened by `tail_norm` (wall re-centred, re-solved); each `l` channel is Gram–Schmidt orthonormalized (`orthonormalize`, minimal first, rejection below `linear_dependence_tol`, a rejected minimal function raises). Output is `RadialTable` → `TabulatedOrbital` (`r_c` at the wall). Cannot be mixed with a pseudopotential family in a per-element basis (all-electron by definition; `resolve_pseudo_basis` raises). On H₂ tier 0 (LDA 1s, more diffuse than the exact 1s) sits *above* FAO and tier 1 well below; core functions are as sharp as FAO's, so use `frozen_core` beyond the first row. Pinned by `test/test_nao_ae.py`; guide in `docs/source/guide/nao_ae.md`; example `examples/23_NAO_AE_basis.py`.

Pinned by `test/test_interaction.py`; guide `docs/source/guide/interaction_energy.md`. ## FAO virtual orbitals (2026-09-17)

`basis={"name": "FAO", "virtual_orbitals": k}` (default **0** = the historical minimal basis, byte-identical) appends the `k` lowest **unoccupied** subshells of each atom to the FAO basis, in aufbau order and with the same bare `Z` as the occupied orbitals. `_config.unoccupied_subshells(atomic_number, count)` is the single source: it returns the `_AUFBAU_ORDER` entries the ground-state filling never reached, so H -> 2s, Li -> 2p, C/O -> 3s, Fe -> 4p. **A partially filled subshell counts as occupied** (carbon's `2p^2` is already a basis shell, so its first virtual level is `3s`), and the helper raises when `count` exceeds the levels left below the end of the filling table. `FAOBasisSet(virtual_orbitals=)` gains `subshells(element)` (occupied in the historical `(n,l)`-sorted order, then the virtuals appended — never interleaved, so the occupied functions keep their indices) and `function_count(element)`; the constructor refuses negatives, non-integers and `bool`.

**`virtual_orbitals` counts levels, not functions** — one virtual `p` level is 3 functions. Deliberate: half a shell would break the atom's spherical symmetry and make the energy orientation-dependent, and "one orbital per subshell" is already the FAO family's own language. H2 costs 4 -> 8 -> 20 -> 24 qubits for k = 0/1/2/3. The option reaches every path for free (`resolve_basis` -> `BasisSet.build(name, **options)` in `build_basis_hamiltonian`, `dry_run` and `bloch`), including the per-element form; the dry-run label becomes `FAO {"virtual_orbitals": 1}`. Electron counts are untouched — only `n_spatial_orbitals` grows.

Validated (H2, 0.74 Angstrom, 8 Angstrom cell, h = 0.30, ADAPT-VQE/fermionic to basis FCI): **-28.161879 eV (k=0, 4 qubits) -> -28.300907 (k=1, 8 q) -> -28.338413 (k=2, 20 q)**, monotone as a strict basis superset requires. **Caveat:** a virtual hydrogenic orbital is diffuse (H 2s has <r> = 6 a0 ~ 3.2 Angstrom), so the cell must contain it or the grid clips the tail. Pinned by `test/test_fao_virtual_orbitals.py` (32 tests); guide `docs/source/guide/basis_sets.md`.

## PAW and p-valence binding: the compensation-charge fix (2026-09-17)

**Symptom.** PAW had no bound minimum for O/C-containing molecules: exact sector ground states of OH, CH and H2O went monotonically downhill to dissociation in every `size` and `h` (OH/SZ +7.50 eV above dissociation at r_e), while s-valence systems were fine (LiH was the positive control). The relaxations still *converged*, cleanly, to the wrong answer: **a converged relaxation is not evidence that the model binds — check with an energy scan.**

**Root cause.** `_compute_one_body` builds `T + V + C D C+`, where `V` is the grid integral of `v^ion` against the **smooth pair density**. PAW's compensation charge is an *extra* density the grid integral could not see, while `two_body_augmentation` gave it its full Hartree repulsion: it repelled every electron and was attracted to no nucleus. It scales with the augmentation charge (O 0.64 e against Li 0.009, H 0.021): **+102 eV for OH** against +0.55 for LiH, growing by **+8.7 eV** between 4.0 and 0.97 Angstrom — exactly the binding deficit.

**The fix.** The hook `MolecularIntegrals.one_body_augmentation()` (`None` by default), added to `one` in `_compute_one_body` and to the force's energy rebuild. `PAWIntegrals.one_body_augmentation` returns `sum_{A,LM} Q^{A,LM}_pr V^{A,LM}` with `V^{A,LM} = integral g^_{A,LM} sum_{B != A} v^ion_B` from `compensation_ionic_at(centers)` — an **atom-centered spherical quadrature** (the shape spans ~4 grid points at h = 0.20; a grid sum would inject an egg-box), converged to 1e-9. The on-site `B = A` term is excluded (already inside the dataset). Taking `centers` as an argument lets the force difference it (`pseudo_forces._ionic_shift`).

**Results** (exact sector ground states, PAW-SZ, h = 0.20, 12 Angstrom cell): OH -> **bound, 1.05 Angstrom, 3.46 eV** (exp. 0.9697, 4.6); CH -> **1.25 Angstrom, 1.77 eV** (1.1199, 3.47); LiH 1.69 Angstrom, 1.44 -> 1.65 eV. PAW-DZ moves OH to ~0.90 Angstrom, bracketing experiment. CH relaxes to 1.3103 / 1.3105 Angstrom from opposite sides, OH from 1.15 to 1.0399.

**Pins moved with it — do not restore the old ones.** Every PAW energy dropped in proportion to the augmentation charge (the old table is `PAW_BEFORE_COMPENSATION_ATTRACTION`). **H2 PAW-DZP `d_eq` moved 0.807 -> 0.712 Angstrom** (h = 0.25; exp. 0.741, VASP-PBE 0.750), so in `test_paw_forces` 0.75 Angstrom is now *outside* the minimum (`bond_force > 1.0`) and `test_h2_force_curve_follows_vasp` compares only *signs* where |VASP force| > 2 eV/Angstrom. **Y_LM convention:** `compensation_moments()` / `compensation_coulomb()` are keyed by `(atom, L, M)`; the monopole carries `1/sqrt(4 pi)` and the Coulomb matrix `4 pi`.

**Two hypotheses built, measured and REFUTED** — correct machinery, not the cause; do not "re-fix" them. (1) **Multipole compensation** (`pseudopotentials/multipoles.py`): `shape_function`/`shape_potential` for any L, `gaunt` by quadrature, `radial_moments`, `multipole_coulomb_matrix`, `paw_multipole_blocks` + `PAWDataset.multipole_moments`; `L = 0` reduces to the monopole to 3e-16 and uses the *stored* `q_ij`. O gains 9 channels, H keeps 1. Effect on OH binding: 0.5 eV. Kept, because the fix sums over the same channels. (2) **One-center two-body term** (`pseudopotentials/onecenter.py`: `radial_coulomb`, `angular_coupling`, `one_center_coulomb`, `reference_density_matrix`) — `1/2 (D-D0)^2 dW`, **measured at 0.08-0.33 eV for oxygen**, ~0 for Li/H. **Not wired into the Hamiltonian** (tested by `test/test_onecenter.py`).

**Cost note.** OH/PAW-SZP is 26 qubits, **127,948 Pauli terms**, sector dim **204,490**: memory is fine (~2.1 GB, batched `restrict`) but one Hamiltonian takes **~40 min** — `ParticleSector.restrict`'s per-term Python loop is what to optimize. **DZ is the practical improvement over SZ.**

## The compensation potentials are not Hermitian (2026-09-17)

**Root cause of the p-valence *force* error.** `PAWIntegrals.compensation_potentials()` returns `W^{A,LM}_qs = integral phi~*_q phi~_s v_L(r_A) Y_LM(r^_A)`. **The weight is complex whenever M != 0**, so `W` is Hermitian only for M = 0 (on water `|W - W^H|` is 1e-16 for `(A,L,0)` and *as large as `|W|`* otherwise). The Pulay branch wrote `dW = cross_w + cross_w.conj().T`, and `cross^H` puts **`conj(v)`** in the second half. Both halves are now written out explicitly. One line.

**Why it hid.** The channels come from the pseudopotential's angular channels, so an s-valence atom has only `(A,0,0)`: **H and Li never exercise it** (H2 4.4e-5, LiH 1.6e-4 against OH 4.2e-2) and all 76 `test_paw*.py` tests passed before and after. On C2v water (bonds along y and z) z rides the real `M = 0` harmonic and y the complex `M = +-1` pair: the oxygen force came out **2.2496 along y against 2.7841 along z**.

**How it was found** (repeat this next time): monkeypatch `AlgebraicEnergy.directional` to capture every `(dS, dh, dg)`, rebuild the integrals at displaced geometries **on the same frozen grid**, and compare each matrix derivative with its own central difference: `dS` 2e-6, `dh` 6e-6, **`dg` 1.4e-1**, only for oxygen. `dU` cleared at 1e-5, `dQ`/`dC` cleared by `dS`/`dh`, leaving `dW`. **Units trap: the analytic derivatives are per Bohr, an ASE displacement is in Angstrom — a factor 0.5292 that looks exactly like a physics bug.**

**Results** (water, PAW-SZ, h = 0.20): analytic vs finite difference **0.575 -> 0.0032 eV/Angstrom**, C2v restored (O: 2.82747 vs 2.82755). The net force got *larger*, 0.869 -> 1.158, **and that is correct** (rigid-translation finite difference -0.8162 per axis against -0.8188; the old cancellation was accidental). What remained was a real egg-box, net/largest force **1.85 / 0.86 / 0.41 / 0.099 / 0.025 at h = 0.30 / 0.25 / 0.20 / 0.16 / 0.13** — before the filter and exact-local defaults; oxygen needed **h <= 0.16 for geometry**.

**H2O in PAW-SZ binds** (the older "no bound minimum" note was the **all-electron FAO** path). Symmetric O-H scan, h = 0.16, 104.5 degrees: minimum **-482.291 eV at 1.00 Angstrom**, monotonic to -474.657 at 3.20, so **7.63 eV for the two bonds** (exp. 4.8 each). A relaxation from 90 degrees / 1.0 Angstrom reaches 0.9921 Angstrom / 117.29 degrees in 3 BFGS steps: the angle error is the minimal s+p shell, not the gradient (PAW-DZ water would be 24 qubits / sector dim 245,025).

Pinned by `test/test_paw_forces.py`: `test_compensation_potentials_are_hermitian_only_for_m_zero`, `test_forces_respect_the_c2v_symmetry`, `test_p_valence_force_is_the_derivative_of_the_energy` (both **verified to fail pre-fix**), `test_translation_projection_zeroes_the_net_force`.

## The run log (`output.txt`) and stdout (2026-09-18 … 09-20)

All in `utils/logging.py` (`AdaptOutputLogger`, `parse_output`, the `append_*` module functions) plus the call sites in `adapt_vqe.py` / `calculator.py`. Guide: `docs/source/guide/run_output.md`. Pinned by `test/test_noncubic_and_output.py` (one class per block) and `test_adapt_args_gradient.py::TestGradientNames`.

**One file per relaxation.** `Mandacaru.calculate` builds a fresh solver per geometry, so every BFGS step used to truncate the file. Now: the banner (`utils/banner.lines()`, the single source; `show()` prints the same lines once per process) is written only into a **freshly opened** file (`self._fh.tell() == 0`; `banner=False` opts out); `_LOG_STEPS` maps each **absolute path** to the blocks written in this process — the first logger truncates, later ones append (`append=True|False` overrides; `log_steps(path)`, `reset_log(path=None)`), and the counter advances only *after* the file opened; missing parent directories are created. **Consequence:** a *scan* reusing one `output=` across several `Mandacaru` objects in one process concatenates — give each geometry its own path for separate files. Blocks are **indented 4 spaces** (`INDENT`, `_indent`, `_emit_body(level=)`): markers, `====` rules and the banner at column 0, keyed lines one level in, tables one more; blank separators truly empty. Indentation is invisible to `parse_output` (it strips every line), so old logs still read.

**Block order per step, and who owns what — each fact has ONE owner** (a value written in two blocks can disagree with itself; pinned by `TestNothingIsSaidTwice`):

- **`[SYSTEM]`** (`write_system`): `step`, units, geometry, cell vectors / lengths / angles.
- **`[BASIS]`** (`write_basis(fields, tables)`, built by `algorithms/basis_report.basis_report(basis, context, symbols)` via `VariationalDriver._basis_report()`): the basis **that ran**, not the options typed — family defaults the user never wrote (PAW `filter`, the range-separated `local_potential` with its sigma), `size`, `split_norm`, `projector_basis`, `energy_shift` + `confinement_potential`, `filter_cutoff` (Bohr^-1 and eV), `dataset_xc` (LDA, datasets only), `basis_functions`, and three tables: `datasets` (symbol, Z, Z_ion, l_max, r_cut, **source file** — `io.load_library_dataset` sets `pp.source`), `orbitals` (per channel: zetas, polarization, `r_c` in Bohr and Angstrom, free and basis eigenvalue, **achieved** shift) and `functions` (per element). All-electron bases get it too (name, options, functions); **direct mode / a loaded Hamiltonian has none** (no basis was built). Table cells never contain spaces; the parser returns each table as a list of dicts keyed by the heading row, integers kept as `int`.

## The orbital-response warning: what it means, and the pool fix (2026-09-18)

The user asked why `atoms.get_forces()` on H2O/PAW-SZ warns `the state is not stationary with respect to orbital rotations (max |dE/dkappa| = 8.5e-03 Ha)`, and **the message's advice was wrong**, so it is rewritten.

**What the residual is.** `AlgebraicEnergy.orbital_gradient` is `max |dE/dkappa|` over orbital rotations with the RDMs frozen. It vanishes at *both* ends of the correlation range — RHF is orbital-stationary, and a full CI in an orbital space is invariant under rotating those orbitals, so the frozen-orbital gradient is the *whole* derivative there. Measured at the relaxed water geometry (h = 0.25, 6 orbitals, sector dim 225): **HF determinant 1.2e-9 Ha, exact sector FCI 1.8e-9 Ha, ADAPT (30 `ceo` operators, 5.4e-4 Ha above FCI) 1.0e-2 Ha.** So a nonzero residual does **not** report an unconverged optimizer — it reports an ansatz that stopped short of its space's FCI.

**Why tightening the tolerance does nothing.** The energy is *second* order in the state error, this residual *first* order: `gradient_tolerance` 1e-3 -> 1e-4 with `max_iterations` 50 -> 100 grew 30 -> 41 operators and moved the screening gradient 1.8e-4 -> 7.6e-5, the energy by **1e-6 eV** and the residual by **0.6 %**. Pinned as a scaling law by `test_all_electron_forces.py::TestOrbitalResponseResidual` (contaminate the exact state by epsilon: residual proportional to epsilon, energy error to epsilon^2; the two zeros are pinned there too). **The test system is a scalene H3+ triangle on purpose:** H2 in a minimal basis has two orbitals of opposite g/u parity, so its energy is *even* in the rotation angle and the residual is identically zero however bad the state is — the test would pass for the wrong reason.

**The lever is the pool.** Same geometry, same h = 0.25, `gradient_tolerance=1e-4`, `max_iterations=100`:

| pool | size | ops | max grad | E-E_FCI (Ha) | dE/dkappa (Ha) | fmax (eV/Ang) | CNOTs |
|---|---|---|---|---|---|---|---|
| `ceo` | 92 | 37 | 9.1e-5 | 5.44e-4 | **1.00e-2** | 2.6257 | 1456 |
| `fermionic` | 92 | 85 | 9.4e-5 | 4.06e-4 | **2.91e-5** | 2.5696 | 8138 |
| `qubit` | 640 | 100 | 1.9e-4 | 4.05e-4 | **6.36e-5** | 2.5698 | 1226 |

`fermionic` and `qubit` cut the residual **~300x** (below `ORBITAL_RESPONSE_TOLERANCE`, so no warning) while improving the energy only 25 % — exactly the first-order/second-order asymmetry. And the forces follow the residual, not the energy: the exact-FCI state gives fmax 2.5441, the two low-residual pools land within 0.026 of it and agree with each other to 0.0002, while `ceo` is 0.082 off. **`pool="qubit"` is the recommendation for this system** — smallest residual-to-cost ratio and *fewer* CNOTs than `ceo` (1226 vs 1456), at the price of 100 operators and a 640-operator screening. (`ceo` is `qeb` in this codebase, so it is not the varied pool its name suggests.) **Consequence for the user's relaxation:** the ADAPT-vs-FCI force error is **0.085 eV/Angstrom** at that geometry, ~6x the `fmax = 0.0131` the run converged to — a second error source above the threshold, alongside the 0.022 eV/Angstrom grid egg-box.

## `project_translation="auto"` is the default (2026-09-18)

The user asked when `project_translation` makes sense and whether it can decide for itself. It can, and the argument is a theorem rather than a heuristic: **the exact force of a free molecule sums to zero, so subtracting the mean is the orthogonal projection onto a subspace that *contains* the true answer, and an orthogonal projection can never increase the distance to a point already in the subspace.** The reported force is therefore never made worse by projecting and is usually made better, whatever the grid error happens to be. Pinned by `test_paw_forces.py::test_projection_cannot_increase_the_error_against_a_zero_sum_force`.

**What it gives up** is the identity `forces == -dE/dR` of the *discretized* energy, which genuinely is not translation invariant. That is a property of the approximation, not of the physics — but it is the property most of the force tests exist to check, so the raw array is kept: **`ForceResult.unprojected`** (backed by `details["forces_unprojected"]`, equal to `forces` when nothing was projected), alongside `details["translational_residual"]` (always the *unprojected* residual, since `_check_translational_invariance` runs first and still warns) and `details["translation_removed"]`.

`DEFAULT_PROJECT_TRANSLATION = "auto"`, `PROJECT_TRANSLATION_CHOICES = (True, False, "auto")`. `Mandacaru._projection_applies(result)` is the gate: **at least 2 atoms** (a single atom's grid re-centers on it, so its residual is zero by construction and says nothing) and **not periodic** (the sum over a cell's atoms is not the free-molecule identity; an explicit `project_translation=True` there emits a `RuntimeWarning` saying it is ignored rather than doing nothing silently). Validation is by *type* — `1 in (True, False, "auto")` is `True` in Python, so an int is refused as the typo it is.

**Consequence for recorded numbers:** every force quoted in this file before 2026-09-18 is the *unprojected* one, reproducible with `project_translation=False`; the differences are the egg-box residuals documented per system. Flipping the default failed 8 tests, every one asserting a property of the raw gradient (finite-difference checks in `test_fao_forces`/`test_all_electron_forces`/`test_paw_forces`, the LiH egg-box measurements, the Hellmann-Feynman + Pulay identity); all now read `force_result.unprojected` with a comment saying why, so the trade-off is visible at each assertion instead of hidden in a default. Policy tests: `test_fao_forces.TestTranslationProjectionPolicy`.

**When to turn it off:** validating a gradient against a finite difference, comparing against the driver's raw output, or measuring the egg-box itself. For relaxation and dynamics — where the artifact is systematic and integrates into a centre-of-mass drift — leave it on. ASE's plain `BFGS`/`FIRE` use forces only, never the energy, so projection introduces no inconsistency into the optimizer; `BFGSLineSearch`/`QuasiNewton` do use the energy, and there the projected force and the unprojected energy are mildly inconsistent by exactly the residual.

## UPAW: an option, not the default (2026-09-18)

Ivanov *et al.*, arXiv:2408.03159v2 (`~/Dropbox/UPAW.pdf`): **unitary PAW** picks pseudo partial waves with `O_ij = <phi_i|phi_j> - <phi~_i|phi~_j> = 0`, so `T+T = I`. **Mandacaru already had the knob:** `q = s * norms`, so **`norm_deficit=0` *is* UPAW** (H, Li, C, O build cleanly: `|q| <= 3e-14`, overlap minimum exactly 1, no ghosts). **Not the default, for three measured reasons:** (1) **we do not need it** — `_lowdin_x` orthogonalizes `S = S~ + C q C+` before the second-quantized Hamiltonian is built; the paper's problem is specific to plane waves. (2) **It does not remove the augmentation machinery** — the constraint fixes only the **L = 0** moment: water's oxygen `|Q^{L=0}|` 3.2e-2 -> 7.7e-15, but `|Q^{L=2}|` 1.4e-3 -> **2.2e-2 (16x larger)**; `W`, `U`, both augmentations and their force derivatives all remain. (3) **The waves are harder, and it lands on the forces** — water's net force is **5x larger** (0.380 -> 1.918 eV/Angstrom at h = 0.25) and the energy converges ~19 % more slowly in `h`. Physics agrees (LiH d_eq 1.6782 vs 1.6802 Angstrom; binding 3.2389 vs 3.1413 eV) and the LCU one-norm is unchanged (H2 1.3563 -> 1.3579 Ha), so this is a cost judgement.

**Worth taking from the paper instead** (neither implemented): **down-sampling** (`E_ds(n+1) = E_ds(n) + E(n+1, n_b) - E(n, n_b)`; maps onto `BlochCalculator.total_energy(kmesh)` and the SZ->DZ->DZP hierarchy) and **lambda / Gamma as dry-run outputs** (lambda = sum |c_P| ranks basis/mapping choices by fault-tolerant cost). Double factorization is a real project.

**Shipped as the family `"upaw"`** (`basis="UPAW"`, alias `"unitary-paw"`, a registered `FamilySpec`; dry-run label `"UPAW (DZP, …)"`). In `paw.py`: `UPAW_FAMILY`/`UPAW_LIBRARY_SUBDIR`, `generate_upaw(symbol, **options)` = `generate_paw(norm_deficit=0.0, ...)` tagged via `dataclasses.replace` (an explicit `norm_deficit=` is a `TypeError`), `upaw_library_path`, `get_upaw`, `build_upaw_library`, `build_upaw`, and `build_paw(..., loader=None)` so the molecular path is shared. **No library is shipped, so `get_upaw` generates on demand** (0.4-2.2 s per element, cached in `_CACHE`, warns once); an *explicit* `directory=` with a missing element raises with the `build_upaw_library` recipe — deliberate asymmetry. **Serialization:** `io.TABLE_FAMILIES` maps **family -> codec** (`"upaw": ".paw"`, not invertible); the writer stores the record's own family, `paw.from_payload` reads `payload["family"]`; a PAW file is refused as UPAW and vice versa. ## PAW egg-box: the Fourier basis filter and the exact local potential (2026-09-20)

Two independent cures for the PAW egg-box (the net force on a free molecule, i.e. the grid's broken translation invariance), **both on by default for `paw` and `upaw`** and each separately switchable. They attack different terms, and the measurement below is why both are defaults: alone the quadrature looks weak and the filter leaves the local potential as the dominant residue; together they compound.

Water, PAW-SZ, 10 Angstrom cell, ADAPT/fermionic, `project_translation=False` — net force in eV/Angstrom (ratio to the largest force):

| | neither | exact local only | filter only | **both (default)** |
|---|---|---|---|---|
| h = 0.25 | 2.3944 (0.862) | 1.7990 (0.651) | 0.1596 (0.055) | **0.0507 (0.017)** |
| h = 0.20 | 1.1579 (0.409) | 0.1511 (0.062) | 0.0450 (0.019) | **0.0021 (0.001)** |

So ~47x at h = 0.25 and ~550x at h = 0.20. Energies for the same four columns: -492.187084 / -492.164040 / -491.376101 / -491.381780 eV (h = 0.25) and -485.987612 / -486.000510 / -485.577732 / -485.578633 eV (h = 0.20). **The filter raises the energy** (+0.8 eV at h = 0.25, +0.4 at h = 0.20): it removes variational freedom the grid could not represent anyway, and most of the "cost" is the unfiltered basis's own aliasing error (a fixed-cutoff series gives 530/422/294/237 meV as h falls). Geometry barely moves: H2 0.0001, LiH 0.0002, OH 0.002 Angstrom (0.037 eV in binding).

**Fourier filter** (`src/mandacaru/basis/filtering.py`). Every radial table of the pseudo basis is transformed per `l` with a spherical-Bessel transform (`spherical_bessel_transform` / `inverse_spherical_bessel_transform`, `TRANSFORM_OVERSAMPLE = 8`), multiplied by a raised-cosine `cutoff_window` (1 below `(1 - ROLLOFF_FRACTION) k_c` = 0.75 k_c, 0 at k_c), transformed back, switched off smoothly in real space out to `SWITCH_MARGIN = 1.5` x the original `support_radius` (`DEFAULT_FILTER_METHOD = "switch"`; `"plain"` and `"mask"` exist in `FILTER_METHODS` — **the mask method measured worse than no filter on long-ranged functions**, do not promote it) and renormalized to the table's own norm (`filter_radial` / `filter_table`). The cutoff is `k_c = FILTER_NYQUIST_FRACTION (1.0) x pi/h` of the **coarsest** grid axis. `band_weight` / `residual_weight` measure what is lost, and above `FILTER_WEIGHT_WARN = 0.05` a `RuntimeWarning` says the grid is too coarse for that function. The basis option is **`filter`**: `True` / `"auto"` (grid Nyquist), a number (cutoff **in eV**), `False` / `None` (off) — `validate_filter`, `filter_cutoff`, `filter_label`. Defaults are per family through the new **`FamilySpec.default_options`** with `FamilySpec.resolved_options(options)` as the *single* merge point (every default key must be in `options`, checked in `__post_init__`): `{"filter": True}` for `paw` / `upaw`, nothing for `ncpp` / `oncvpsp` (their projectors are still grid-sampled, so filtering the basis alone is not the same win — not measured as a default there). The dry-run label always names the filter state, and the builder's `context["filter_cutoff"]` records the cutoff used. Per-term rigid-shift ripple at h = 0.25: kinetic 367.5 -> 0.05, local 1608.3 -> 21.0, ERI 1321.5 -> 7.1 meV — the local term is what is left, which is the second fix's job.

**Exact local potential** (`src/mandacaru/pseudopotentials/local_split.py`). `v^ion = v_lr + v_sr` with `v_lr = -Z erf(r / (sqrt(2) sigma)) / r` (`long_range_potential`), `sigma = SIGMA_FACTOR (1.4) x h` (`split_width`): the long-range part is smooth on the grid's own scale and stays a grid integral, while the short-range part `v_sr = v^ion - v_lr` (`short_range_potential`, computed as a difference from the dataset's cubic spline) is integrated on an **atom-centred spherical quadrature** inside `max(RADIUS_SIGMAS (6.5) x sigma, r_cut_local)` — a two-panel Gauss radial rule split at `r_cut_local` (the potential is only C2 there), `RADIAL_POINTS = 64` per panel, `POLAR_POINTS = 32`, `AZIMUTHAL_POINTS = 64` (`short_range_matrices`, in `SHELL_BLOCK`s to bound memory). Hook: **`MolecularIntegrals.short_range_local()`** returns `None` by default (every other basis untouched) and is added in `_compute_one_body`; `PAWIntegrals.short_range_local` supplies it and `external_potential()` then returns only the long-range part. Class switch **`PAWIntegrals.exact_local_potential = True`** (monkeypatch it to `False` to get the old grid integral). Forces: `short_range_local_matrices(gradients=True)` gives `G^A[p,q,k]`, contracted in `pseudo_forces` as `short_range_pulay` (basis functions move) and `short_range_hellmann_feynman` (the potential's centre moves); `PAWIntegrals.local_potential_functions()` is what `_atom_potentials` now reads, so the grid part of the gradient differentiates the *same* long-range potential the energy used. `force_method="scf-response"` **raises** on a range-separated potential (the legacy path rebuilds `-Z/r`-like potentials itself and would differentiate a different energy).

**Pins moved — four tables in `test/test_paw.py`, do not collapse them.** `PAW` (both defaults): H2 RHF -1.095388 / ADAPT -1.109147, LiH -0.772498 / -0.780327 Ha; `PAW_FILTER_ONLY`: -1.095435 / -1.109194, -0.772482 / -0.780311; `PAW_EXACT_LOCAL_ONLY`: -1.095403 / -1.109176, -0.772959 / -0.780763; `PAW_BEFORE_BASIS_FILTER` (= the 2026-09-17 values quoted earlier in this file): -1.095396 / -1.109168, -0.773001 / -0.780800. `test_each_default_is_separately_auditable` reproduces all four to 1e-6 by switching `{"filter": ...}` and monkeypatching `exact_local_potential`, so a future shift can be attributed to one feature. **Every PAW/UPAW energy and force quoted earlier in this file predates both defaults**; reproduce them with `basis={"name": "PAW", "filter": False}` and `PAWIntegrals.exact_local_potential = False`. Tests: `test/test_basis_filtering.py`, `test/test_paw_exact_local.py`. One tolerance lesson: `test_the_geometry_barely_moves` compares a force at 0.90 Angstrom, next to its zero crossing, so it is an **absolute** 0.05 eV/Angstrom bound — a relative one fails on a number that is nearly zero (H2's d_eq stays within 0.9132-0.9147 Angstrom across the four combinations).

## PAW `energy_shift`: confined orbitals, the GPAW recipe (2026-09-20)

**Why:** the user compares ADAPT-VQE here with GPAW LCAO-DFT "in the same basis", which means fixing `size` **and** `energy_shift`. Until now the first zeta of a PAW basis was the dataset's bound smooth partial wave — the **free-atom** orbital, i.e. `energy_shift = 0` with no range of its own (99.99 % of the norm at 8.4 Bohr for H 1s, **14.3 Bohr for Li 2s**, 4.7 / 6.5 for O 2s / 2p). One file per element stays enough: size, confinement and filter are all run-time constructions on that one function.

`basis={"name": "PAW", "size": "DZP", "energy_shift": 0.1}` — **eV** (as GPAW and as the `"NAO"` family), accepted by `paw` / `upaw` only (`PAW_EXTRA_OPTIONS = ("projector_basis", "energy_shift")`; NCPP/ONCVPSP refuse it as an unknown option — their radial solve is not written), **default 0.1 eV since the same day** (see below; `None` / `False` / `0` switch it off), scalar or `{symbol: eV, "*": default}` (also through the per-element basis form; an element left out stays unconfined). `pseudopotentials/confinement.py`: `validate_energy_shift`, `energy_shift_of`, `energy_shift_label` (`"unconfined"` / `"energy_shift 0.1 eV"` — the dry-run label names it **always** for PAW/UPAW), `confinement_potential`, `confined_energy`, `confined_eigenstate`, `confinement_radius`, `confined_orbital` -> `ConfinedOrbital(symbol, l, energy_shift, r_c, energy, free_energy, radial, achieved_shift)` cached per dataset (`_CACHE` keyed by `id` with an identity check), `first_zeta_factory(energy_shift, record)`.

**Construction.** The lowest solution of the dataset's own generalized radial problem `(T_l + v~scr + v_conf + |p~>D<p~|) u = eps (1 + |p~>q<p~|) u`, `u(r_c) = 0` (`paw._channel_operator_on(pp, l, r)` — factored out of `_channel_operator` so the grid can put a node **exactly on the wall**, `h = r_c/n`; otherwise eps(r_c) is a staircase and the root search has nothing smooth) on two grids, Richardson-extrapolated, S-normalized and signed like the stored wave. `v_conf = A/(r_c - r) exp(-(r_c - r_i)/(r - r_i))` with **`CONFINEMENT_AMPLITUDE = 12` Ha and `CONFINEMENT_INNER_FRACTION = 0.6` — GPAW's `vconf_args` defaults, on purpose**. `r_c` by an outward bracket scan + `brentq` on `eps(r_c) - eps_free = shift` (`eps_free` = `reference_energies[0]`), from `r_cut / 0.6` (so `r_i` stays outside the augmentation sphere) to 95 % of the table; both limits raise with the usable range. **The operator is untouched** (projectors, `D`, `q`, local potential): only the trial function changes, as in GPAW — the old docstring claim that the first zeta "cannot be replaced" was too strict. Plumbing: `pseudo_basis(..., first_zeta=callable(symbol, pp, l) -> R | None)` — the zetas and the polarization shell (`r^k R_outer`) are split from the *confined* orbital and inherit its `r_c`; the filter runs after; with the hook and the filter both off the SZ path is byte-identical. `build_valence_hamiltonian(..., confined_orbital=)`, `context["confinement"]` (`{symbol: {l: ConfinedOrbital}}`) and `context["options"]`; `VariationalDriver._check_pseudo_basis` validates the value at construction.

**Measured.** Shifts achieved to <= 4e-5 eV; 0.1-2.4 s per channel. `r_c` at 0.01 / 0.1 / 0.3 eV: H 1s 8.97 / **6.68** / 5.59 Bohr (GPAW's H `dzp` sits at ~6.4), Li 2s 14.82 / 11.20 / 9.42, O 2s 5.53 / 4.37 / 3.81, O 2p 7.15 / 5.35 / 4.51. **A mild confinement lowers the energy** (free-atom orbitals are too diffuse for a molecule): H2 (0.74 Angstrom, 8 Angstrom cell, h = 0.25) SZ -30.2425 / -30.3292 / -30.7093 / -31.1507 eV for off / 0.01 / 0.1 / 0.3, DZP -33.3847 / -33.4102 / -33.4845 / -33.5108 — the gain shrinks as the basis grows. Forces differentiate the confined basis (analytic vs finite difference on the frozen grid within 5 meV/Angstrom).

**GPAW is the convention, SIESTA the alternative (user directive, 2026-09-20).** Every choice below was read from GPAW's source (`~/Codes/gpaw/gpaw/atom/basis.py`, `all_electron.py`) and checked against its own generator (`gpaw_fast` conda env: `BasisMaker.from_symbol(s, xc="LDA").generate(2, 1, energysplit=0.1)`), not recalled.

- **Split-valence scheme — the default changed.** SIESTA and GPAW share the polynomial `r^l(a - b r^2)` but not the convention: GPAW's `tailnorm=(0.16, 0.3, 0.6)` is the **norm** of the tail and every zeta is split from the **first** one; the SIESTA-style `split_norm=0.15` is the **squared norm**, each zeta split from the **previous** one, halved each time. 0.16 as a norm is 0.0256 of the squared norm, so GPAW's zetas are longer-ranged (H 1s second zeta at 0.1 eV: 3.68 vs 2.52 Bohr). `basis/multizeta.py`: `GPAW_TAIL_NORMS`, `validate_tail_norm` (a number replaces the first entry), **`resolve_split_scheme(split_norm, tail_norm) -> (split_norm, tail_norms)`** — GPAW's unless `split_norm` is written, both together refused — and `zeta_tables(..., tail_norms=)`. Only four tests moved (three option/label pins and `test_paw_forces.test_hellmann_feynman_and_pulay`, where 0.75 Angstrom is now just *inside* the minimum: `-0.8 < bond_force < 0`; `test_the_siesta_split_is_still_available` keeps the old behavior reproducible) — the pinned energies are SZ or state the scheme.
- **`"confinement": (amplitude_Ha, r_i/r_c)`** — default `(12.0, 0.6)` = GPAW's `vconf_args` (`validate_confinement`); the root search starts at `r_cut / inner_fraction`.

## Volumetric output: `.cube` / `.xsf` of the variational state (2026-09-20)

**A many-electron state has 3N coordinates and cannot be put in a volumetric file**; what is written are its exact **one-particle reductions**, built from the 1-RDM, the MO coefficients and the run's *actual* basis functions on the calculation's own grid — the docs say so and new text must not call it "the wavefunction". API, on `Mandacaru` only: `calc.write_cube(path, quantity="density", index=None, state=None, component=, grid=, format=)` -> `VolumetricField` (`integral`, `norm`, `occupation`, `n_electrons`, `augmentation_charge`, `output_path`, `summary()`, `write()`), `calc.volumetric_field(...)` (no file) and `calc.natural_orbitals()` (occupations + coefficients). Quantities: `density`, `alpha_density`, `beta_density`, `spin_density`, `difference_density` (n - n_HF), `natural_orbital`, `molecular_orbital`. `state=` is an index into a subspace result's `states` or an explicit state vector (how `energy_levels().states[i]` is drawn). Direct mode (no basis) is refused. Modules: `algorithms/volumetric.py` (`volumetric_field(integrals, gamma, ...)`, `state_natural_orbitals`, `OrbitalExpansion`, `spin_resolved_rdm`, `reference_occupations` — testable without a solver) and `utils/cube.py` (`write_cube` / `write_xsf` / `write_volumetric` / `detect_format`). It reuses the forces' RDM pipeline: `Mandacaru._state_rdms(psi=None, two_body=True)` gained those two arguments (defaults byte-identical; a density never builds the O(M^4) 2-RDM), so frozen cores, `parity_reduced` registers and sector runs all work (densities agree to 3e-17).

**Do not use `ase.io.cube.write_cube` for this grid**: it derives the voxels from `atoms.cell / n` and writes `atoms.positions`, while Mandacaru's grid is centered on the molecule with `n = round(L/h) + 1` nodes and a 3x3 `step` matrix — every nucleus would land in the wrong place. The writer here takes `origin = node (0,0,0)`, the columns of `grid.step` as voxel vectors (Bohr) and the nuclei from `integrals._potentials.nuclei` (the `coherent_positions` frame the basis functions sit in); `.xsf` does go through ASE (`origin` / `span_vectors`). Alignment is pinned for a molecule **not** centered in its cell and for a skewed grid. Validated: integral of n = 2.0000000000 (H2/FAO), 4.0 (LiH, frozen core refilled), H3 doublet spin density 1.0; H2 natural-orbital occupations (1.9749, 0.0251) at 0.74 Angstrom, (1.7589, 0.2411) at 1.60, (1.3149, 0.6851) at 2.50, HF exactly (2, 0); cube round trip 4.8e-7 (the format's 5 significant figures). **PAW writes the smooth *pseudo valence* density**, which does not integrate to N: grid 1.943466 + augmentation 0.056534 = 2 for H2-SZ — tests pin that *identity*, not literals. Left out on purpose: all-electron reconstruction inside the spheres (`reconstruct_ae` is radial only), a `--cube` CLI flag. `test/test_volumetric.py` (47 tests, 5 s), guide `docs/source/guide/visualization.md` (VESTA / VMD instructions), `examples/32_wavefunction_cube.py` -> `examples/data/h2_stretched_*.cube` (120 kB each) and `h2_cube_slice.png` (density and n_ADAPT - n_HF of stretched H2: gain on the nuclei, loss in the bond).
