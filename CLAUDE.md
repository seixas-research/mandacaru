# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Mandacaru** is a framework for fermionic quantum simulation based on variational quantum algorithms (VQAs), targeting real NISQ-era quantum hardware (IBM Quantum via Qiskit). The intended end-to-end pipeline is: fermionic system → second-quantized Hamiltonian → qubit (Pauli) Hamiltonian → parameterized ansatz → VQA optimization → QPU/simulator execution → error mitigation. The flagship algorithm is **ADAPT-VQE** with pluggable operator pools (fermionic / qubit / QEB / CEO), plus its **excited-state** extensions (deflation / subspace-search).

**Important:** the project is mid-build. Implemented end-to-end: localized bases (FAO / NAO / STO-nG / 6-31G(d)), **a periodic plane-wave basis** and the **pseudopotential families NCPP / ONCVPSP / PAW** (selected as a basis name, `basis="PAW"`; package `mandacaru.pseudopotentials`, stable since 2026-09-15) → real-space (and reciprocal-space, for PW) integral engine → second-quantized `Fermion` Hamiltonian → fermion-to-qubit mappings → **UCCSD ansatz → VQE** and **ADAPT-VQE** (both exact state-vector solvers, validated on H₂), with **RHF/UHF** for the molecular-orbital basis. Also implemented: **excited states** (`energy_levels` via variational deflation, and `SubspaceVQE`/`SubspaceADAPTVQE` subspace-search), and the periodic-system **`BlochCalculator`** (band structure + BvK total energy, `method="adapt-vqe"|"vqe"`). All solvers share a common **`VariationalDriver`** base (`algorithms/base.py`) with the excited-state methods as composable mixins. **The single user-facing entry point is `Mandacaru(method=..., ...)`** (`algorithms/calculator.py`; renamed on 2026-09-09, the old name is gone without alias — also `from mandacaru import Mandacaru`) — an ASE calculator selecting the solver by the `method` string (`"adapt-vqe"` is **the default everywhere**, also for `BlochCalculator`; `STABLE_METHODS` = `"vqe"`, `"adapt-vqe"`, `"subspace-vqe"`, `"subspace-adapt-vqe"`; anything else must be added with `register_method(name, cls)` — the `mandacaru.experimental` package registers its own solvers when *explicitly* imported, and the stable code, docs, README, examples and website never name them; a repository sweep under `test/experimental/` enforces that), forwarding all solver options, and exposing the run result uniformly on `.result` (plus `.solver`/`.hamiltonian`/`.n_qubits`/`.num_particles`, direct-mode `run()`, and `energy_levels()`). **The algorithms are called solely through `Mandacaru` — no exceptions (user mandate, re-issued 2026-09-19).** The solver classes (`VQE`, `ADAPTVQE`, `SubspaceVQE`, `SubspaceADAPTVQE`) are the internal layer: they are **not exported** from `mandacaru.algorithms`, and no test, example or documentation page may import or construct one — `test/test_single_entry_point.py` sweeps the repository and fails if one does. Direct (no-geometry) problems go through the calculator too: `Mandacaru(method="adapt-vqe", hamiltonian=H, pool=..., num_particles=..., n_spatial_orbitals=...).run()`. To make that a complete replacement, `Mandacaru` **validates its options in the constructor** (by building the solver once with its dry-run switch on, which runs every constructor check and configures nothing — plus `_check_shots_for_hardware`, the one check a dry run waives) and builds the real solver **on first use** (`calc.solver` is a lazy property; `run()` reuses a solver built only to be read; every geometry evaluation replaces it). An invalid *option* is therefore refused by the constructor, an invalid *problem* (a non-Hermitian operator, a qubit-count mismatch) where the problem is built — on first use and **delegates unknown attributes to the solver** (`calc.pool`, `calc.ansatz`, `calc.kpoints`, `calc.energy_at`…); writes and monkeypatches that must land on the solver use `calc.solver`. `method` is spelling-insensitive (`"adapt-vqe"` = `"adaptvqe"` = `"ADAPT_VQE"`, `_method_key`). `resolve_method` is the one place the solver classes are imported from. When working on this codebase, never reach for a solver class in a test or example — if `Mandacaru` cannot express what is needed, extend `Mandacaru`. The `backends/hardware.py` device registry is written and every entry is runnable (`AER_simulator`, IBM Quantum via Qiskit Runtime, Amazon Braket); **not written at all: error mitigation** — there is no `backends/mitigation.py` and no `plan/` directory (both were named here for a long time; neither exists). Before building on a module, check that it exists and has code (`wc -l`). `pyproject.toml` is the source of truth for the build (currently Python ≥ 3.14).

## Current state of the code

Implemented:
- `src/mandacaru/basis/` — localized single-particle basis functions (`BasisFunction` ABC) and three concrete families: `FullAtomicOrbital` (analytic, with Slater charges), `NumericalAtomicOrbital` (confined Sankey/SIESTA-type, `nao.py`), `GaussianOrbital` (contracted GTOs, `gaussian.py`). **All families are generated natively from scratch — no tabulated/external basis-set data.** The `BasisSet` factory (`factory.py`) builds `"FAO"` (Full Atomic Orbitals; one analytic orbital per occupied subshell, carrying the **actual atomic number Z** as the orbital's nuclear charge — the bare hydrogenic orbital, no Slater screening; **`{"name": "FAO", "virtual_orbitals": k}`** appends the `k` lowest *unoccupied* subshells per atom, see below), `"STO-3G"`, `"NAO"`, `"GTO"` and `"6-31G"`/`"6-31G(d)"` bases. The GTO family is a minimal **STO-nG** basis generated in `sto_ng.py` by least-squares fitting `n_gaussians` primitives to the Slater-type orbital of each occupied subshell (Slater's-rules ζ = (Z−S)/n\*), with the reference fit done once at ζ=1 (cached, `_fit_reference`) and exponents rescaled by ζ². `BasisSet.build(method="GTO", n_gaussians=3)` → STO-3G-like; the fit reproduces published STO-nG exponents closely (H 1s → 2.22766/0.40577/0.10982). The **Pople split-valence** family (`pople.py`) reuses that fit to build 6-31G(d): 6-primitive cores, 3+1 split valence, and a native (Slater-heuristic) `d` polarization shell on non-H atoms. Shared aufbau config in `_config.py`, angular helpers in `_angular.py`. `_config.valence_subshells` returns the highest-`n` occupied subshells **plus the semicore `(n-1)d` / `(n-2)f`** when occupied, so Fe is `3d⁶4s²` (8 valence electrons) rather than a 2-electron `4s²` atom — this feeds both the basis and pseudopotential generation.
- `src/mandacaru/basis/gaussian_families.py` — **named Gaussian families** (`BasisSet.build("cc-pVTZ" | "6-311+G(2df,2p)" | "def2-TZVP" | "STO-4G" ...)` → `GaussianBasisSet`): `parse_basis_name` turns a name into a `GaussianRecipe` (core/valence contraction *patterns*, heavy/H polarization `(l,count)` tuples, diffuse lists or `diffuse_present`, tight functions, `polarization_min_z`=11 for Pople's `3-21G*`), and `gaussian_shells(Z, recipe)` generates `(l, exps, coeffs)` natively: each `(n,l)` shell is one `_fit_reference` Slater fit of `sum(pattern)` Gaussians partitioned tightest-first (`(3,1)` = 6-31G split, `(3,1,1)` = 6-311G), polarization `f_l·ζ_val²` (`HEAVY_/HYDROGEN_POLARIZATION_FACTOR`, ratio 3 spread — `6-31G*` reproduces `pople_631g_shells` exactly), diffuse = most diffuse exponent of that `l` / `DIFFUSE_RATIO` 3.5, tight = tightest valence × 3. Function counts match the published shell notation (`cc-pVTZ` C `[4s3p2d1f]`, `def2-QZVP` C `[7s4p3d2f1g]`, spherical shells); exponents are Mandacaru's own. `MAX_CONTRACTION = 10`: the Slater fit is numerically singular past ~10 primitives, so `sto_ng._projected_overlap` now rejects ill-conditioned trials (cond > 1e12, overlap > 1) and `_fit_reference` raises instead of returning garbage — keep contractions ≤ 10. `NAMED_BASIS_SETS` lists the 40 validated names; pinned by `test/test_gaussian_families.py` (structure table + H₂ RHF/Hamiltonian integration per family). `6-31G`/`6-31G(d)`/`6-31G*`/`STO-nG` still route to the dedicated `Pople631GBasisSet`/`GTOBasisSet`.
- `src/mandacaru/basis/multizeta.py` — **multiple-zeta and polarized NAOs**, selected by `BasisSet.build("NAO", size=...)` or `basis={"name":"NAO","size":"DZP","energy_shift":0.03}` (all `NAOBasisSet` options — `size`, `energy_shift`, `r_c`, `n_grid`, `split_norm` — pass through the dict). `ZETA_NAMES` covers `SZ`/`SZP`/`DZ`/`DZP`/`DZ2P`/`TZ`/`TZP`/`TZ2P`/`QZ`/`QZP`/`QZ2P` (or an explicit `(n_zeta, n_polarization)` pair); **the default is `DEFAULT_NAO_SIZE = "DZP"`** — `size="SZ"` is opt-in and keeps the original `NumericalAtomicOrbital` path byte-for-byte. Extra zetas use the **SIESTA split-valence** construction (`split_radius`/`split_valence_tail`): pick `r_s` leaving `split_norm` (0.15) of the norm outside, replace the inside by `r^l(a−b r²)` matched in value *and* slope at `r_s`, keep the difference — each zeta is strictly shorter-ranged than the last (H 1s: 3.99 → 2.09 → 1.22 → 0.81 a₀). Polarization adds a whole `l_max+1` shell solved in the same confining sphere (3 functions for s-valence, 5 for p, 7 for d). All orbitals become `TabulatedOrbital` (`R(r)·Y_lm` off a spline), so the integral engine sees them identically. **Caveat worth knowing:** high zetas are short-ranged by construction and the real-space grid must resolve them — the 3rd H zeta spans 0.65 Å ≈ 3 points at `h=0.20 Å` and contributes ~1e-6 Ha (3.6e-5 at `h=0.12`). DZP is the practical sweet spot; TZ/QZ need a fine grid to be worth anything.
- `src/mandacaru/integrals/` — real-space one- and two-body integral engine, grid, FFT Poisson solver, C backend binding
- `src/mandacaru/core/` — the second-quantized layer. `mapping.py`: `Fermion` (fermionic ladder operators with full algebra and a `from_integrals` builder for `H = Σ h_pq a†_p a_q + ½ Σ ⟨pq|rs⟩ a†_p a†_q a_s a_r`), `PauliSum` (the qubit-operator output type, with `to_sparse_pauli_op`), and the three fermion-to-qubit mappings — **Jordan-Wigner** (default), **parity** (with optional two-qubit reduction) and **Bravyi-Kitaev** — via a shared encoding-matrix construction (`map_to_qubits(method=...)`). `hamiltonian.py`: `MolecularIntegrals` drives the integral engine to build the spin-orbital molecular Hamiltonian as a `Fermion`. `planewave.py`: `PlaneWaveIntegrals` — a **periodic plane-wave basis** (`{"name":"PW","energy_cutoff":300}`; eV, default 300) computing the reciprocal-space one-/two-body integrals with PBC (diagonal kinetic `½|G|²`, structure-factor external potential, momentum-conserving `4π/Ω/|G_p−G_r|²` electron repulsion, G=0 removed by jellium), mirroring the `MolecularIntegrals` interface (`molecular_hamiltonian`, `hartree_fock`, `integration_profile`). It guards against an intractable O(N⁴) tensor via `max_plane_waves` (default 60) — a realistic cutoff on a molecule-sized cell yields far too many plane waves for exact state-vector VQE, so use a small cell/cutoff.
- `src/mandacaru/circuits/` — `base.py` (the **`Ansatz` protocol** — `num_parameters`/`n_qubits`/`reference_state`/`state(θ)`/`evolve(θ, references)` — that every ansatz conforms to structurally, so a new ansatz drops in with no driver change), `gates.py` (anti-Hermitian single/double fermionic excitation generators), `ansatz.py` (`UCCSD`, a state-vector ansatz `|ψ(θ)⟩ = exp(Σ θ_k (T_k − T_k†))|HF⟩`; default is the exact UCC exponential, `trotter=True` gives the circuit-faithful first-order product), `adapt_ansatz.py` (the growable `AdaptAnsatz`), `pools.py` (ADAPT-VQE operator pools — **fermionic**, **qubit** (qubit-ADAPT), **QEB** (Z-strings dropped) and **CEO** (coupled exchange, OVP) — behind a common `OperatorPool`/`PoolOperator` interface with a `build_pool` registry), and `profiling.py` (`CircuitMetrics`/`profile_ansatz` — compile `|HF⟩`+∏exp(A_k) to a native `{cx,u}` gate set for CNOT/depth). `AdaptAnsatz`/`profile_ansatz`/`CircuitMetrics`/`Ansatz`/`UCCSD` are imported from `mandacaru.circuits` (their canonical home — not re-exported through `mandacaru.algorithms`). The `evolve(θ, references)` method applies one shared unitary to a `(2ⁿ,k)` stack of reference states (used by the subspace-search solvers).
- `src/mandacaru/optimizers/optim.py` — `Optimizer`, a classical-optimizer wrapper with cost-history tracking. Six named methods (`NAMED_OPTIMIZERS`): **SPSA**, **COBYLA** (default), **Nelder-Mead**, **SLSQP**, **Adam**, **L-BFGS-B**. COBYLA/Nelder-Mead/SLSQP/L-BFGS-B dispatch to `scipy.optimize.minimize`; **SPSA** and **Adam** are implemented natively (SPSA = two-eval Spall stochastic gradient; Adam = finite-difference-gradient adaptive moments).
- `src/mandacaru/algorithms/base.py` — **`VariationalDriver`**, the shared ASE-`Calculator` base every variational driver subclasses. It owns the common **problem-setup surface** (`basis`/`grid`/`h`/`kpts`/`spin`/`initial_state`/`charge`/`n_electrons`/`frozen_core`/`frozen_orbitals`/`hamiltonian_builder`/`optimizer`/`device`/`run_options`/`sparse`), the ASE `calculate()` hook (geometry→Hamiltonian each call in calculator mode; reused in direct mode), the **state-vector backend** (`_materialize_hamiltonian` dense/sparse-Hermitize, `_as_pauli_sum`, `_resolve_sparse`, the canonical **`energy(psi)`** — a state vector in, uniformly), the Γ-point k-guard (`_check_kpts`/`_kpts_label`), timings/banner scaffolding (`_make_timings`/`_finalize_timings`/`_show_banner`) and `format_pauli_sum`. Subclasses implement just `_configure(hamiltonian, num_particles, n_orbitals)` (build the ansatz/pool + materialize) and `run()`. Excited-state **methods are mixins** over the base: **`DeflationMixin`** (`algorithms/deflation.py`) supplies `energy_levels(...)` once (the state-by-state VQD outer loop + `EnergyLevels`), with each driver providing the per-state `_deflated_ground` hook; **`SubspaceMixin`** (`algorithms/subspace.py`) supplies the SSVQE `run()` scaffolding, with each driver providing `_reference_occupied`/`_subspace_optimize`/`_make_subspace_result` (the run result always lands on the driver's `.result` — there is no per-class result attribute). So `VQE(DeflationMixin, VariationalDriver)`, `ADAPTVQE(DeflationMixin, VariationalDriver)`, `SubspaceVQE(SubspaceMixin, VQE)`, `SubspaceADAPTVQE(SubspaceMixin, ADAPTVQE)` — and a new method plugs in as a mixin/subclass without re-implementing setup. (`VQE.energy_at(θ)` is the parameter-space cost; the base `energy(psi)` is the state-vector expectation.)
- `src/mandacaru/algorithms/vqe.py` — `VQE`, an exact state-vector eigensolver (`⟨ψ(θ)|H|ψ(θ)⟩` minimized over ansatz params); validated on H₂ against exact diagonalization to ~1e-9 Ha. `VQE`/`VQEResult` mirror `ADAPTVQE`/`ADAPTVQEResult`: `optimizer` accepts a method-name string (`"SPSA"` / `"COBYLA"` default / `"Nelder-Mead"` / `"SLSQP"` / `"Adam"` / `"L-BFGS-B"`) or an `Optimizer`, `verbose=True` prints the qubit Hamiltonian as Pauli strings + a timing/resources summary on `run()`, and `VQEResult` exposes `num_parameters`/`energy_history`/`correlation_energy`. Both `VQE` and `ADAPTVQE` also have an **`energy_levels(num_states=2, ...)`** method computing molecular **excited states** via variational quantum deflation (VQD): each level minimizes `⟨H⟩ + β·Σⱼ|⟨ψⱼ|ψ⟩|²` over the previously found states (auto `β` from the Hamiltonian's coefficient 1-norm; the shared `DeflationMixin`/`EnergyLevels` live in `algorithms/deflation.py`), returning an `EnergyLevels` (ascending Hartree energies + `excitation_energies`/`in_units("eV")`/stored state vectors; ADAPT re-grows a fresh deflated ansatz per level and records `num_operators`). Reported energies are the bare `⟨H⟩` (penalty vanishes at the eigenstate) — every returned level is a true eigenvalue of H, limited to the sector the ansatz can reach from its HF reference (ADAPT's greedy screening hits Brillouin's zero-gradient wall for singles, so on H₂ it reaches the seniority-zero partner, while UCCSD-VQE also reaches a singly-excited level). `algorithms/subspace.py` adds **`SubspaceVQE`** and **`SubspaceADAPTVQE`** (via `SubspaceMixin` over `VQE`/`ADAPTVQE`) — **subspace-search VQE (SSVQE)**, which computes the ground + first few excited states **simultaneously** in one optimization: `num_states` orthogonal reference determinants (auto-generated as the lowest of the HF particle-number sector, `subspace_determinants`/`reference_matrix`) are sent through one shared unitary `U(θ)` and the weighted energy `Σⱼ wⱼ⟨φⱼ|U†HU|φⱼ⟩` (strictly-decreasing `weights`, default `(k,k-1,…,1)`) is minimized (`SubspaceADAPTVQE` grows one shared ansatz whose pool-screening gradient is the weighted per-reference sum). This needed the ansatz method **`evolve(θ, references)`** (added to `UCCSD` and `AdaptAnsatz`; applies the same unitary to a `(2ⁿ,k)` stack of references). Returns `SubspaceVQEResult`/`SubspaceADAPTVQEResult` (ascending Hartree `energies`, orthonormal `states`, `weights`, `optimal_energy`=ground, `excitation_energies`, `in_units("eV")`, `.levels` → `EnergyLevels`; both reached as `Mandacaru(method="subspace-vqe"|"subspace-adapt-vqe")`, exposing the spectrum on `.result`, ASE energy = ground). Levels are variational **upper bounds** (Hylleraas–Undheim `Eᵢ ≥ λᵢ`); the ground is exact from the default HF start, excited-state tightness tracks ansatz expressivity. **The user-facing form is `atoms.calc = Mandacaru(method="vqe", basis="FAO", optimizer=..., h=...)` — the only one;** `atoms.get_total_energy()` builds the Hamiltonian + a default UCCSD ansatz from the geometry and runs, returning eV, with the run result on `atoms.calc.result`. The geometry→Hamiltonian building (grid-from-cell + basis integrals) is shared by both drivers in `algorithms/_hamiltonian_from_atoms.py`; the shared `resolve_optimizer` helper lives in `optimizers/optim.py`.
- **Profiling** (`utils/profiling.py`) — `Timings` accumulates named stage wall-times plus the OpenMP core count and peak process RSS (`peak_memory_mb`, via `resource.getrusage`). The C backend reports its thread count through `mandacaru_num_threads()` → `_backend.num_threads()`. `IntegralEngine` times its one-/two-body stages (`engine.integration_profile()` → `MolecularIntegrals.integration_profile()`); `VQE.run`/`ADAPTVQE.run` time optimization / gradient-screening / etc. and print a "Timings / Resources" block in the verbose summary (also on `result.timings` / `result.integration_profile`).
- `src/mandacaru/algorithms/adapt_vqe.py` — `ADAPTVQE`, the adaptive grow-then-reoptimize loop (gradient `⟨ψ|[H,A_i]|ψ⟩` over a pool, warm-started inner VQE) on the exact state-vector backend, using the growable `AdaptAnsatz` (`circuits/adapt_ansatz.py`; dense eigendecomposition backend, or a **sparse closed-form** backend for large active spaces) and Qiskit-based circuit profiling (`circuits/profiling.py`: `profile_ansatz` → CNOT count + depth in a native `{cx, u}` gate set). Both drivers subclass `VariationalDriver` (see `base.py`) so setup/materialization/`energy(psi)`/timings are shared. All four pools reach FCI on H₂. See `examples/01_ADAPTVQE_H2.py` … `examples/06_ADAPTVQE_O2_triplet.py`. Operator selection is the single pluggable hook **`_select_operator(grads, iteration)`** (default `argmax|g|`), used by `run()`, the deflation grow (`_grow_deflated`) and the subspace grow — so a subclass changes *which* operator grows the ansatz without touching convergence (`max|g| < tol`, computed independently of selection).
- `src/mandacaru/algorithms/hartree_fock.py` — `RHF` (closed-shell SCF; supplies the **molecular-orbital basis** so ADAPT's HF reference is stationary and singles have zero gradient) and `UHF` (`run()` → energy, for the isolated-atom references; `solve()` → `UHFResult` with both spin-orbital sets, the **natural orbitals** of `D_α+D_β` (`natural_orbitals`, occupation-ordered) and `h_mo`/`eri_mo` in that basis, plus `reference_energy` of the NO determinant and `spin_contamination`). **Open shells (2026-09-09):** `MolecularIntegrals.molecular_hamiltonian(mo_basis=True, n_electrons, num_particles=(nα,nβ), open_shell=None)` uses RHF for even counts and the **UHF natural-orbital basis** for odd counts (or `open_shell=True`), one spatial basis for both spins so the α/β-block spin-orbital form and everything downstream (pools, ansätze, mappings, frozen core, dry run) are unchanged; the NO reference is not stationary, so ADAPT also selects singles (fine). `resolve_num_unpaired` makes an odd count a doublet by default (`spin` is now only a compatibility flag; magmoms select quartets etc.), `_num_particles` checks parity instead of refusing odd counts, `resolve_frozen_core(..., n_doubly=n_beta)` freezes only doubly occupied NOs; the **PW** basis still refuses odd counts (RHF-only). `VQE` now stores `num_particles`/`n_spatial_orbitals` like ADAPT; `adapt_vqe._max_abs` treats an **empty pool** (H atom: 1 electron, 1 orbital) as converged instead of crashing on `max([])`. Pinned by `test/test_open_shell.py` (H, H₃ doublet/quartet, Li frozen core, H₂⁺, OH dry run; ADAPT/VQE reach the sector FCI computed by `_sector_ground_state`).
- `src/mandacaru/algorithms/bloch.py` — the **general (1-/2-/3-D) periodic-system driver `BlochCalculator`** — a single class whose variational solver is selected by `method="adapt-vqe"` (default) / `"vqe"`, mirroring `Mandacaru`. Takes an ASE `Atoms` *primitive cell* (`atoms.cell`/`atoms.pbc` define the lattice and periodic directions). `bands(kpts)`/`band_structure(path)` solve the single-particle **Bloch Hamiltonian** `H(k)c = ε(k)S(k)c` at each k-point — the cell-to-cell overlap/one-body blocks `S^{(R)}`,`h^{(R)}` are built from the FAO real-space integrals over a lattice window, the Bloch phase is the dimension-general `exp(2πi k·n)` over integer translations, and (being single-particle) the bands are **identical across the three methods**. `total_energy(kmesh, **solver_kwargs)` gives the **total energy per cell using all k-points** via the **Born–von Kármán equivalence** (an `(n1,n2,n3)` mesh ≡ Γ-point on the `(n1,n2,n3)` supercell): it builds the supercell with `atoms.repeat`, runs it through a molecular `Mandacaru(method=self.method, ...)`, and returns `(E(supercell)/n_cells, result)` where `result` is the method's `VQEResult`/`ADAPTVQEResult` (read from `calc.result`; a finite-supercell estimate exact in the infinite-mesh limit; k-points come from ASE `monkhorst_pack`). `band_structure` returns `BandStructure` (x/energies/xticks/labels/kpts). See `examples/07_ADAPTVQE_H_chain_bands.py` and `examples/11_Bloch_crystals.py`.
- `src/mandacaru/algorithms/expressivity.py` — PQC **expressibility** (Sim *et al.* 2019): random-parameter state fidelities vs the Haar distribution scored by KL divergence (`compute_expressibility`, `calculate_kl_divergence`, `calculate_haar_distribution`). The Haar reference dimension is the *number-conserving sector* `d = C(M,nα)·C(M,nβ)` (`active_space_dimension`) or the empirical span rank (`estimate_effective_dimension`), **not** `2^N` — the fermionic ansätze never leave their symmetry sector. `ADAPTExpressivityTracker` / `track_adapt_expressivity` hook `ADAPTVQE.run(callback=...)` to log expressibility as the ansatz grows.

`backends/hardware.py` is the device registry (`AER_simulator`, IBM Quantum via Qiskit Runtime, Amazon Braket) and `utils/logging.py` is the ADAPT `output.txt` protocol (`AdaptOutputLogger`/`parse_output`). ADAPT-VQE is driven as `atoms.calc = Mandacaru(method="adapt-vqe", pool=..., basis="FAO", mapping=..., optimizer=..., gradient=..., device=...)`; `atoms.get_total_energy()` builds the Hamiltonian from the geometry and runs the loop, returning eV with the result on `atoms.calc.result`. `optimizer` takes a method name or an `Optimizer`; `gradient` is `"analytic"` (default) / `"finite_difference"` / `"parameter-shift"`. `run()` takes no required arguments (`max_iterations` / `gradient_tolerance` / `output` default to the constructor values) and prints the qubit Hamiltonian's **term count only**, then a column-aligned iteration table (one line per grown operator: `iter | |grad| | E (eV) | dE | expr | cnot | 1q | depth | type | operator`); neither the pool nor the selected operator's Pauli expansion is printed — they live on `result.operators` and, with `verbose_operators=True`, in `pool.json`. The class is `ADAPTVQE` and its result dataclass `ADAPTVQEResult` (no `AdaptVQE`/`AdaptVQEResult` aliases).

Both drivers also accept `kpts` (Monkhorst-Pack mesh via ASE — a `(n1,n2,n3)` triple or the ASE dict; the engine is Gamma-point/molecular, so a denser mesh is generated and exposed on `.kpoints` but rejected at run with `NotImplementedError`), `spin` (bool, default False — high-spin reference), `initial_state` (default `"hartree-fock"`, validated), and the **frozen-core approximation** `frozen_core`/`frozen_orbitals` (`True`/`"auto"` freezes the chemical noble-gas core, an int freezes that many lowest MOs, or `frozen_orbitals=[...]` names exact spatial-MO indices; core orbitals leave the active space via `core.hamiltonian.freeze_core_integrals` — a constant core energy plus an effective one-body potential — so the ansatz/pool/qubit count shrink. Resolved by `core_electrons`/`resolve_frozen_core` in `_hamiltonian_from_atoms.py`; PW rejects it). The **initial spin state** is read primarily from the geometry's initial magnetic moments (`Atoms(..., magmoms=[1,1])` -> a triplet, via `resolve_num_unpaired`); the `spin` bool is the fallback. ADAPTVQE also takes **`sparse`** (default `"auto"` -> sparse pool for `n_qubits >= 12`): the Hamiltonian and pool generators stay scipy-sparse (`PauliSum.to_sparse_matrix`), screening uses the exact analytic gradient, and `AdaptAnsatz` applies `exp(theta A)` through the closed form `I + sin(theta) A + (1-cos(theta)) A^2` (valid because the excitation generators satisfy `A^3 = -A`; `scipy.sparse.linalg.expm_multiply` otherwise), so only the few *selected* operators are ever densified and 12+-qubit active spaces stay tractable.

The ASE-calculator path **softens the -Z/r cusp to half a grid step** (`MolecularIntegrals(..., softening=)`) so a nucleus landing on a grid node no longer produces a garbage core integral (needed since FAO uses the bare Z), and centers the grid on the molecule (minimum-image via ASE `find_mic`), so placement in the cell is irrelevant. `run()` writes the start-up banner once per process (`utils/banner.py` — `lines()` renders it, `show()` writes those lines to stdout) *before* anything is written to `output.txt`, and the same `lines()` go once into the top of the log. `MolecularIntegrals.hartree_fock_hamiltonian(n_electrons)` reduces the full Hamiltonian to the mean-field (diagonal orbital-energy) HF `Fermion` whose ground state is the HF determinant at the RHF total energy. The `basis` argument accepts a name **or** a `{"name": ..., <options>}` dict (`resolve_basis` in `_hamiltonian_from_atoms.py`): `{"name":"FAO"}`, `{"name":"NAO","energy_shift":0.03}`, `{"name":"NAO-AE","tier":1}`, `{"name":"GTO","n_gaussians":3}`, `{"name":"6-31G(d)"}`, or the periodic `{"name":"PW","energy_cutoff":300}` (routes to `PlaneWaveIntegrals`; requires `atoms.cell`).

Also implemented on the shared `VariationalDriver` (so VQE / ADAPTVQE and their subspace variants all accept them):

- **Hamiltonian disk cache** (`core/serialization.py` — `save_hamiltonian`/`load_hamiltonian`/`HamiltonianRecord`/`detect_format`). Two interchangeable formats selected by `hamiltonian_format="parquet"` (default) or `"json"`: Parquet is a compressed columnar table of `pauli`/`real`/`imag` rows with the problem spec in the key/value metadata (~4x smaller than JSON); JSON is the same content as plain text and needs no Parquet engine. `save_hamiltonian=True|"path"` dumps the qubit Hamiltonian after it is built; `load_hamiltonian="path"` reads it back — **auto-detecting the format** from the extension, else from the leading bytes (`PAR1` vs `{`) — and **bypasses the integral engine and the fermion-to-qubit mapping entirely**. Parquet has two engines (`engine="fastparquet"` default, `"pyarrow"`); fastparquet leads deliberately because pyarrow's Parquet writer can segfault in a process that has also run Qiskit's `transpile` (reproduced on CPython 3.14 / qiskit 2.5 / pyarrow 25) — `hamiltonian_format="json"` avoids the issue entirely. Because the file records `num_particles`/`n_spatial_orbitals`, a loaded driver is in *direct mode with no geometry* — `Mandacaru(method="adapt-vqe", pool=..., load_hamiltonian=...).run()` works without any `Atoms`, and `method="vqe"` rebuilds its default UCCSD from the file. (The *pool*'s own excitation generators are still mapped — that is a different operator.)
- **Multi-backend circuit providers** (`backends/providers.py` — `CircuitProvider` + `QiskitProvider`/`BraketProvider`/`CirqProvider`, `build_provider`/`normalize_provider`/`provider_available`). `backend_provider="qiskit"|"braket"|"cirq"` (default follows the `device`, else `"qiskit"`) selects the SDK; `execute_circuits` (default `True` for braket/cirq, `False` for qiskit) makes state preparation *run a real circuit* on that SDK's local state-vector simulator instead of the internal NumPy/sparse backend. Each anti-Hermitian generator `A = Σ i c_j P_j` has mutually commuting terms, so `exp(θA) = Π exp(iθc_j P_j)` factorizes **exactly**; each factor is a basis change + CNOT ladder + `Rz(-2θc_j)` + uncompute, emitted once by `CircuitProvider._emit` in a shared `{x,h,s,sdg,cx,rz}` gate set and translated per SDK. Qiskit is little-endian so Mandacaru qubit `k` is laid on wire `n-1-k`; Braket and Cirq are big-endian like Mandacaru. Wired into `AdaptAnsatz(provider=...)` and `UCCSD(provider=..., trotter=True)` (a circuit realizes the Trotter product, so UCCSD raises without `trotter=True`); `profile_ansatz(..., provider=)` counts gates/depth per SDK. Circuit execution only handles computational-basis (determinant) references — HF and the SSVQE references — and raises otherwise. See `examples/12_ADAPTVQE_LiH_backends.py` (LiH across all three, agreeing to ~5e-8 Ha).
- **Amazon Braket / real QPUs.** `BraketProvider(device=..., shots=...)` targets either the local simulator or the **AWS service** by ARN (`AwsDevice`). Verified constraint: Braket rejects the `StateVector` result type whenever `shots > 0`, and every QPU requires `shots > 0` — so the exact path is simulator-only. The QPU path is shot-based: `backends/measurement.py` partitions H into **qubit-wise-commuting groups** (`qubit_wise_commuting_groups`/`merge_basis`/`energy_from_counts`/`shot_noise_estimate`), submits one measurement circuit per group with the basis rotation appended, and assembles ⟨H⟩ from bit-string counts (118 Pauli terms → 29 circuits on LiH; error falls as 1/√shots). `hardware.py` now carries a `Device` registry with the Braket entries (`braket-local`, `braket-sv1`/`dm1`/`tn1`, `braket-ionq-aria`/`forte`, `braket-iqm-garnet`, `braket-rigetti-ankaa`, plus any raw ARN) and `device_arn`/`device_provider`/`is_aws_device`/`requires_shots`; a QPU named without `shots` is refused in the constructor. See `examples/13_braket_aws_compatibility.py`.

The user's IBM open plan has 10 min/month of QPU time (`service.usage()`): never run optimizations on hardware; rehearse on `fake_kingston`/`fake_fez`/`fake_marrakesh` (needs `qiskit-aer` for the idle-qubit truncation) and submit only the final job. **Two hardware lessons, paid for:** unmitigated 12-qubit LiH circuits (92 CZ, depth ~300) landed 0.5-0.8 Ha above exact, and an H2 curve on a drifted readout qubit came out *below* the exact ground state because the Estimator's readout mitigation divided by a 35 % assignment error whose calibration record claimed 0.7 % — `physical_qubits=[...]` pins the layout (Mandacaru qubit k -> `physical_qubits[k]`, mapped to `initial_layout` on the reversed wires); rank pairs by `backend.properties()` readout + CZ error and prefer a live readout check over the calibration record. Raw data in `examples/data/h2_dissociation_ibm*.{csv,json}` and `lih_dissociation_ibm.{csv,json}`; plots `examples/plot_h2_ibm.py` / `plot_lih_ibm.py`. Pinned by `test/test_ibm_quantum.py` (local estimator, `fake_manila`, mocked service for device selection, ADAPT/VQE end to end with shots, `measure_energies`); examples `24_ADAPTVQE_LiH_IBM.py` and `25_ADAPTVQE_H2_IBM.py` (which carries a `PHYSICAL_QUBITS` constant).
- **Parity two-qubit reduction (2026-09-12).** `two_qubit_reduction=True` on any driver (requires `mapping="parity"`; `Mandacaru(..., mapping="parity", two_qubit_reduction=True)`) tapers the two parity qubits fixed by the particle numbers (`core.mapping.parity_tapered_qubits(n)` = `(n/2−1, n−1)`, `two_qubit_reduce(op, n_modes, num_particles)` wraps `_parity_two_qubit_reduction`; `reference_qubit_bits(..., two_qubit_reduction, num_particles)` drops the same positions) **consistently** from the Hamiltonian (`_as_pauli_sum(h, n_qubits, num_particles)` maps on `n_qubits+2` modes then tapers), the pool (`PoolBase(two_qubit_reduction=)`: `n_modes` = 2M, `n_qubits` = 2M−2; `FermionicPool`, `QEBPool` and `CEOPool` all have `supports_two_qubit_reduction = True` since the encoding fix of 2026-09-16 — only `QubitPool` raises, because its individual Pauli strings do not commute with the tapered symmetries by design), `AdaptAnsatz(two_qubit_reduction=, num_particles=)` / `UCCSD(two_qubit_reduction=)` (reference bits tapered; **UCCSD's reference now goes through `reference_qubit_bits` for every mapping** — it used to write JW occupation bits regardless of the mapping) and the dry run (`n_qubits_reduced`). `SubspaceMixin._supports_two_qubit_reduction = False` (its extra determinants are untapered → `NotImplementedError`). H₂/FAO: 4 → 2 qubits, 15 → 5 Pauli terms, identical ADAPT/VQE/HF energies (pinned by `test/test_two_qubit_reduction.py`); on Kingston the circuit shrinks from 17 CZ / depth 63 to a handful of gates — this is the configuration of `25_ADAPTVQE_H2_IBM.py`.
- **Dynamic parametrization** `quenching` (default `True`). `True` re-optimizes **all** parameters each iteration (standard ADAPT-VQE — this is what reaches FCI). `False` optimizes only the newly appended parameter and freezes every earlier one at its prior optimum (a 1-D line search per growth step: far cheaper, variationally weaker). Implemented once on the base as `_optimize_grown` (used by `ADAPTVQE.run`, `_grow_deflated` and `SubspaceADAPTVQE._subspace_optimize`) and `_optimize_all` (used by `VQE.run`/`_deflated_ground`/`SubspaceVQE`, where `quenching=False` means a one-parameter-at-a-time sweep over the fixed ansatz).

**No `vacuum` argument anywhere (removed 2026-09-15).** The real-space box is **always the geometry's `atoms.cell`**: `Mandacaru` lost `vacuum` (its frozen force grid is now `grid_from_cell(atoms, h)` — the same grid a single-point energy uses, centered on the molecule, no padding), `BlochCalculator` lost `vacuum` (the band-structure grid is the nuclei window `(2·n_images+1)` cells along each periodic axis × the primitive cell along the open axes, via `Grid(cell=window[:, None] * cell)`; `supercell(kmesh)` is plain `atoms.repeat(kmesh)` with the repeated cell and **no extra padding** — the primitive cell is what the user sizes; a zero-length lattice vector raises), and the CLI lost `--vacuum` (a geometry file must carry a cell — extxyz `Lattice`, CIF, POSCAR — and a bare g2 name needs an explicit **`--cell L | Lx Ly Lz | 9 components`**, `cli.parse_cell`, which centers the molecule; without either `load_geometry` exits with a clear message). A geometry without a cell raises `ValueError(missing_cell_message(h))` (`_hamiltonian_from_atoms.missing_cell_message`) telling the user to define the cell in the geometry (`atoms.center(vacuum=3.0)` on the ASE side is geometry, not calculator, and stays the idiom in tests/docs). Pinned by `test/test_dry_run.py` (`--cell`, the no-cell exit), `test/test_forces.py` (frozen grid from the cell), `test/test_bloch.py`. **Documentation style rule (2026-09-15):** in every documentation page (`docs/source/**`, README, `docs/experimental/*.md`, the website's `content.py` snippets) and every example script, `Mandacaru(...)` and `BlochCalculator(...)` constructor calls are written one argument per line, continuation lines aligned with the first argument, `method=` first (`calc = Mandacaru(method="adapt-vqe",\n                 basis={"name": "PAW", "size": "DZP"},\n                 h=0.20,\n                 pool="fermionic")`); single-argument calls may stay on one line; tests may keep compact calls. The reflow was done mechanically (a script splitting top-level arguments, inserting `method="adapt-vqe"` where a multi-argument call omitted it) — keep new snippets in that shape.

**Pseudopotentials — part of the main API (graduated 2026-09-15).** The whole feature lives in `src/mandacaru/pseudopotentials/` (`generation.py`, `io.py`, `orbitals.py`, `families.py`, `oncv.py`, `paw.py`, `link_library.py`, the library in `library/ncpp/` plus the git-ignored `library/oncvpsp` and `library/paw` **symlinks**, re-created with `python -m mandacaru.pseudopotentials.link_library --oncvpsp DIR --paw DIR`; `io.library_root()` is the parent (env `MANDACARU_PSEUDO_PATH`), `default_library_path()` = `ncpp/`). Tests are `test/test_{pseudo_io,pseudopotential,pseudopotential_engine,ncpp_family,oncvpsp,paw,link_library}.py` (together ~340 tests / 50 s / 2.4 GB; the project-wide `test/conftest.py` times every test and reads its peak RSS into `test/.resource_report.txt` — budget: test < 3 min, suite < 10 min, RSS < 8 GB), examples `26_pseudopotential_generation.py` / `27_pseudopotential_calculations.py`, guide `docs/source/guide/pseudopotentials.md`. `mandacaru.experimental` holds only VASQE.

**The selector is the `basis` argument — there is no `pseudopotentials=` argument anywhere:** `basis="NCPP"` (aliases `"TM"`, `"NCPP-TM"`), `"ONCVPSP"` (alias `"ONCV"`), `"PAW"`, `"UPAW"`, or the dict form with the size hierarchy `{"name": "PAW", "size": "DZP", "split_norm": ..., "directory": ...}` (PAW/UPAW also take `projector_basis`), exactly like `"FAO"`/`"NAO"`/`"cc-pVTZ"`; the per-element form `{"O": {"name": "PAW", "size": "DZP"}, "H": "PAW"}` works with sizes per element within ONE family (mixing a pseudo family with an all-electron family, or two pseudo families, raises a clear `ValueError`). Plumbing: `_hamiltonian_from_atoms.pseudopotential_family(name)` -> `FamilySpec | None` via `families.lookup_family` (the registry is the single source of truth, so `register_family` makes a new family a basis name with no driver edit); `resolve_pseudo_basis(name, options, symbols)` handles the per-element case; `build_basis_hamiltonian(atoms, basis, grid, h, charge, n_electrons, spin, frozen_core, frozen_orbitals, kinetic)` dispatches to `_pseudopotential_hamiltonian(..., family, options, kinetic)`, which validates the option keys against `FamilySpec.options` (default `COMMON_OPTIONS` = size/split_norm/directory) — an unknown key raises at driver construction (`VariationalDriver._check_pseudo_basis`), as does `frozen_core` with a pseudo basis. `dry_run.count_basis_functions(atoms, basis)` / `estimate_qubits(..., basis=)` count the pseudo basis (label `"PAW (DZP, pseudopotentials)"`). The old `"PP"`/`"PSEUDO"` basis names are a **deprecation error** (`RETIRED_PSEUDO_BASIS_NAMES`, `_check_retired_basis_name`) pointing at the new spelling — no silent aliasing.

**The family registry** is `families.PSEUDO_FAMILIES`: `FamilySpec(name, description, generate, get, build, norm_conserving, aliases, options)` with `register_family`/`unregister_family`/`resolve_family`/`lookup_family`/`canonical_family_name`/`family_names`/`family_listing`; unknown names raise a `ValueError` listing the registry. `_pseudopotential_hamiltonian` is a thin dispatcher — `family.build(atoms, grid, h, charge, spin, options, kinetic)` returns the usual 5-tuple. `PseudoPotential.family` is written and read by `io.py` (`FORMAT_VERSION` 2; a v1 file without the field loads as `LEGACY_FAMILY`), and the canonical Troullier-Martins key is **`"ncpp"`** (aliases `("tm", "ncpp-tm")`, `FamilySpec.label` = `"NCPP"`) — the shipped library files still say `"tm"` and are canonicalized on load.

**NCPP (Troullier-Martins).** Norm-conserving TM pseudopotentials with **Kleinman-Bylander** projectors, generated from scratch by an LDA radial atomic solver (`basis/atomic_solver.py`). The nonlocal term is the general separable form `H_NL = C D C+`: `C = projections()` (M x P, cached, C kernel `kb_projections`, fills `kb_resolution_ratios`), `D = nonlocal_coupling_matrix()` block-diagonal over `(atom_index, l, m)` from `nonlocal_coupling` (`core.hamiltonian.projector_blocks`/`assemble_block_matrix`; `None` -> the projectors' `kb_energy` diagonal). `MolecularIntegrals.kb_nonlocal()` (alias `nonlocal_matrix`) evaluates it; `KBProjector` carries `atom_index`, `channel=(l,m)`, `index` (radial projector within the channel, 0 for KB), `block_key`, and accepts `radial=`/`kb_energy=` overrides, with `orbitals.kb_coupling_blocks(projectors)` giving the TM `[[E_KB]]` blocks. **Overlap hook:** `nonlocal_overlap` (PAW's `q_ij`; TM passes `None`) makes `overlap()` = `bare_overlap() + C Q C+`, which feeds `_lowdin_x` and hence every orthonormalized integral / RHF / UHF-NO path (`Q = 0` reproduces the plain Hamiltonian exactly). Pinned by `test/test_ncpp_family.py`: H2 RHF -1.061096 / FCI -1.075333 Ha, LiH RHF -0.729555 / FCI -0.740839 Ha (re-pinned by ~1e-8 Ha when the FFT self-energy became exact; the old values stay under `before_exact_self_energy`). H and Li have one (local) channel, so H2/LiH carry no TM projectors.

**ONCVPSP** (`oncv.py`, Hamann PRB 88, 085117; family `"oncvpsp"`, alias `"oncv"`). Construction: `bound_state` (Numerov outward/inward shooting; `generation_points(Z)` = max(6000, 1500 Z); `_origin_seed` is a **six-term power series** — the two-term one admixes the irregular solution) and `scattering_wave` at `eps_1 + energy_offset` -> `optimize_pseudo_waves` (8 spherical Bessel functions at the **interleaved zeros of j_l and j_l'** — the RRKJ log-derivative roots make the third-derivative row linearly dependent — constraints value + 3 derivatives from the AE radial equation (`matching_targets`) plus generalized norm conservation, residual kinetic energy beyond `q_cut` = 5 Bohr^-1 minimized **exactly** by null-space elimination and a 1-D Lagrange-multiplier root, `constrained_minimum`) -> `polynomial_local_potential` (even polynomial inside `r_cut_local` = 0.9 min r_c, optional `local_shift`) -> `assemble_channel` (analytic projectors, `B_ij = <phi~_i|chi_j>` asserted symmetric to `B_ASYMMETRY_TOLERANCE` 1e-6 — needs cubic-spline resampling and the ODE-based targets — `D = B^-1`) -> unscreen with the TM machinery. Records `ONCVPseudoPotential`/`ONCVChannel` (two projectors and a 2x2 coupling block per l, `v_local_screened`); `io.py` dispatches on the family (`oncv.to_payload`/`from_payload`, tables under `radial_tables`). Library `library/oncvpsp/` (`build_oncv_library`, `get_oncv`, `oncv_library_path`; `DEFAULT_CUTOFFS` H 1.30 / Li 2.60 / C 1.50 / N 1.45 / O 1.45 / F 1.40 Bohr — Li at 2.2 or 3.3 grows a ghost, 3.0 shifts LiH by 0.15 Ha). Molecule path `build_oncv` mirrors the TM one with `oncv_projectors` (two `KBProjector`s per (atom,l,m)) and `oncv_coupling_blocks`. Diagnostics: `check_oncv_channel`, `radial_spectrum` (3-point Laplacian + Richardson — a 5-point stencil breaks the Dirichlet origin for l=0), `log_derivative_ae`/`log_derivative_ps`, `report_oncv`, `diagonalized_projectors`. Validation (`test/test_oncvpsp.py`, 50 tests): eigenvalues <= 1e-7 Ha, log derivatives <= 1.7e-4 at the references; **H2 (h=0.25) RHF -1.044179 / ADAPT -1.058561, LiH (h=0.30) RHF -0.774343 / ADAPT -0.782341 Ha**. Known limits: no NLCC, no relativistic terms, no projectors above the valence l, |D| up to ~300 Ha (the two partial waves are nearly proportional in the core; harmless to first order). ONCVPSP still **grid-samples its projectors** — the exact on-site quadrature exists only in `PAWIntegrals` — which makes its O/C curves erratic at the +-3 eV level; prefer PAW there.

**PAW** (`paw.py`, Bloechl PRB 50, 17953; family `"paw"`, `norm_conserving=False`, extra option `projector_basis="raw"|"dual"`). Frozen-core, one-center-expansion form with the one-center terms **linearized** at the LDA reference (fixed `D^ion` per species plus the constant `one_center_energy`). `generate_paw` -> `PAWDataset`/`PAWChannel`: the ONCV Numerov pair (`DEFAULT_ENERGY_OFFSETS` H/Li 0.5 Ha, else 1) -> `smooth_partial_waves` = `oncv.optimize_pseudo_waves(..., norm_factor=1-s)` so the inner-norm matrix is scaled and `q = s <phi_i|phi_j>_rc` is **positive definite by construction** (`DEFAULT_NORM_DEFICITS` H 0.05 / Li 0.02 / C 0.10 / N,O,F 0.15; free waves gave an *indefinite* q and a singular `1 + sum |p~>q<p~|`, which `assemble_paw_channel` refuses via `OVERLAP_MINIMUM`) -> `polynomial_local_potential` with **`DEFAULT_LOCAL_SHIFTS`** C 12 / N 10 / O 6 / F 8 Ha (without them the continued potential binds a 1s-like ghost 0.6-1 Ha below eps_2s in the first-row s channel) -> `chi_i = (eps_i - T - v~) phi~_i`, `B_ij = <phi~_i|chi_j>`, dual projectors `p~_i = sum_k (B^-1)_ki chi_k` (duality asserted to `DUALITY_TOLERANCE` 1e-8, achieved 1e-14), `q`, `dT`, `dV`, `D^scr = B + eps_j q_ij` (= `dT + dV` to 1e-15, `consistency_error`) -> monopole compensation charge with `compensation_shape` `(1-r^2/r_g^2)^3`, `r_g = min r_c`, analytic `compensation_potential` -> unscreen `v~^ion` -> `D^ion` and `one_center_energy` (the Hartree/xc double-counting difference that makes the LDA reference atom exact). Molecule path `build_paw` -> **`PAWIntegrals(MolecularIntegrals)`** with `datasets=`: `paw_projectors`, `paw_coupling_blocks` / `paw_overlap_blocks` (via `PAWDataset.projector_set(l, basis)` — `"raw"` samples the smooth chi_k, `"dual"` the p~; identical energies, only the resolution ratio differs), **exact on-site projections** (`projections()` overrides same-center entries by radial quadrature — grid sampling gave 0.7-3x the exact value depending on the nucleus/node offset and collapsed LiH by 0.2-0.6 Ha), the **augmented two-body tensor** (`two_body_augmentation`: pair densities + `Q^A g_A`, `compensation_moments`, `compensation_potentials` W, `compensation_coulomb` U — exact 1/R for disjoint spheres, Gauss-Legendre when overlapping) and `one_body_augmentation` (see the compensation-charge section). **Sizes, library coverage and storage.** The basis dict's options are the size hierarchy: `{"name": "PAW", "size": "DZP", "split_norm": ...}` reaches `pseudo_basis(..., size=)`, which builds the split-valence zetas *from the pseudized orbital* (polarization split off the outermost channel); the first zeta must stay the pseudopotential's own orbital (the KB projectors were built from it), and `size` defaults to `"SZ"`. An all-electron family can never be paired with a pseudopotential — the family *is* the basis. The shipped library covers **every element with Z <= 92** (`LIBRARY_Z_MAX = 92`, regenerable with `build_library()`); the ONCVPSP (110 MB) and PAW (190 MB) libraries live in the sibling repositories `mandacaru-oncvpsp` / `mandacaru-paw` (flat `<Symbol>.parquet`) and are linked in, never committed (`link_library(family, source, root=, files=, force=)`, `status()`, per-file links with `--files`; pinned by `test/test_link_library.py`, whose real-loader test skips when the links are absent). Storage is **Parquet by default** with **JSON** retained (`PSEUDO_FORMATS`); `load_pseudopotential` **auto-detects** the format from the extension, falling back to magic bytes (`PAR1` vs `{`). `save_pseudopotential` is lossless and idempotent (`stride=1`); the `STRIDE=4` decimation applies only at `build_library()` time, where the fine generation grid exists — applying it per-write made load->save compound. **Beware the pandas/pyarrow/qiskit interaction:** pandas 3 defaults `future.infer_string` on, so even a *fastparquet* read builds its column index as a pyarrow string array, and after Qiskit's `transpile` has run in the same process that decode corrupts (`UnicodeDecodeError` / `ArrowException`). Every Parquet read therefore goes through `core.serialization.native_pandas_strings()` — keep new Parquet paths inside it. (Separately, importing pandas *after* qiskit's transpile segfaults at interpreter shutdown; importing it first is fine.)

**PAW / ONCVPSP forces, particle-number sectors, real orbitals (2026-09-15).** `atoms.get_forces()` with a pseudopotential basis goes through `algorithms/pseudo_forces.pseudo_nuclear_gradient`: the energy `E = sum D h^MO + 1/2 sum Gamma g^MO + E_ion + E_1c` with `h^MO = A+ h A`, `A = S^-1/2 V` is differentiated with the spin-summed RDMs (`spatial_rdms`) and the MOs `V` (`MolecularIntegrals.mo_coefficients`, set by `molecular_hamiltonian`) held fixed — exact for an orbital-stationary state, with `details["orbital_gradient"]` measuring the residual. Hellmann-Feynman = operators move (local potential, projectors in `C D C+` and `S = S~ + C q C+`, compensation `W`/`U`, ion-ion); Pulay = basis functions move (`S~`, `T`, `V_loc`, `C`, grid ERI, `W`). Matrix derivatives come from displaced sampling on the frozen grid, contracted as a central-difference directional derivative of `AlgebraicEnergy(S, h, g)` (complex-safe, no energy-weighted density matrices). The calculator refuses a force whose rebuilt energy differs from the solver's by more than `ENERGY_CHECK_TOLERANCE` (1e-6 Ha). Validated analytic vs central difference of the fixed-state energy at **8.6e-5 eV/Angstrom** (H2 PAW-DZP, h = 0.25).

**Three fixes are load-bearing and must stay.** (1) **`PAWIntegrals.projections()` are atom-centered spherical quadratures** (`atom_centered_projections`, 64x24x48 points over each projector sphere; `atom_centered_projection_gradients` gives `G = <dphi/dR|p>`, Pulay `+G`, HF `-G`; `exact_projections = True`) — grid-sampled projections put a 3.9 eV nonlocal egg-box on H2 at h = 0.25 and 2 eV/Angstrom force errors; the remaining egg-box (kinetic/local/Hartree) is 18/13/5 meV at h = 0.25/0.20/0.15. (2) **`PAWDataset.local_potential` is a cubic spline** (C2, `_local_spline`, cached by id) — `np.interp` kinks made derivatives step-dependent at 2e-2 eV/Angstrom. (3) **Conjugation-real MOs** (`core.hamiltonian.conjugation_real_orbitals`, `MolecularIntegrals.conjugation_matrix`/`real_orbitals`, applied in `molecular_hamiltonian` for RHF and UHF-NO, rotating only within the occupied/virtual blocks): complex `Y_lm` orbitals leave the SCF with arbitrary phases and mixed degenerate pairs, the MO ERIs pick up imaginary parts (5.7e-2 Ha on H2 DZP), and every real pool then **stalls** (ADAPT 62 meV above FCI with every optimizer, 0.05 eV/Angstrom force error); with real MOs ADAPT reaches the sector FCI to 1e-9 eV. This affected every l > 0 basis, not just PAW.

**Particle-number sector** (`core/sector.py`): `ParticleSector(n_qubits, (n_alpha, n_beta), mapping, two_qubit_reduction)` with `restrict`, `positions`, `basis_vector`, `embed`, `project`, `apply_pauli_sum`. `restrict(PauliSum, max_entries=None)` builds the CSR on the sector by bit masks, **folded in batches of `RESTRICT_BATCH_ENTRIES = 8_000_000` staged entries**: every Pauli term contributes one entry per sector state, so holding them all before de-duplicating costs `len(terms) x dim` (OH in PAW-DZ — 14,707 terms, dim 25,200 — staged 3.7e8 entries, about 12 GB, for a 16.5M-nonzero result and died climbing past 2.35 GB). Folding batch by batch is exact (the sum is linear in the terms; pinned bit-identical down to `max_entries=1`) and brings that case to 33.5 s / 2.74 GB peak. `ADAPTVQE(sector="auto")` materializes H and the pool on the sector for `n_qubits >= SECTOR_AUTO_QUBITS = 16` (no circuit provider, not the subspace solvers) — H2/LiH PAW-DZP are 20 qubits but 100 states; `AdaptAnsatz(sector=)` and `rdm.one_rdm/two_rdm(..., sector=)` follow (not with two-qubit reduction). Also: **`Fermion.map_to_qubits` accumulates in place** — `result = result + op` copied the whole sum per term and took 22 s of a 24 s H2 DZP run.

**Two radial on-node bugs, both fixed and both still load-bearing.** (1) `multizeta.TabulatedOrbital.radial` and `nao.NumericalAtomicOrbital.radial` evaluated their `CubicSpline(extrapolate=False)` below the first table point, got NaN and returned 0, so every s function vanished within ~0.005 Bohr of its own center and a nucleus sitting **exactly on a grid node** (a symmetric molecule centered in its cell) lost the orbital's peak sample: LiH PAW-DZP -18.31 instead of -21.28 eV, H2 -29.76 instead of -31.72 eV. Both now continue as `R(r0)(r/r0)^l` below `r0`, and the rigid-shift ripple is back to 23 meV (LiH) / 14 meV (H2) at h = 0.20. (2) `pseudo_basis` built the polarization shell from the outermost channel's radial function *itself*, so `R_p(0) != 0` and the p function was discontinuous at its own nucleus; its displaced-sampling derivative exploded on-node (analytic -8.12 vs finite-difference -5.11 eV/Angstrom). The shell is now `r^k R_outer(r)` normalized (k = 1 for the first polarization shell) — same range, vanishing as `r^l`. Both changed every pseudo-family DZP/TZP energy.

**Forces / geometry optimization (rewritten 2026-09-16; the old "known-broken for the all-electron path" claim is retired).** `Mandacaru` has **two** gradient implementations, selected by **`force_method`** (`calculator.py`): **`"rdm"` is the default for every basis** — the complex-safe reduced-density-matrix gradient of `algorithms/pseudo_forces.py`, generalized from the PP families to all-electron bases by `_atom_potentials(integrals)` (a dataset's `local_potential` for a pseudopotential family, else a softened `-Z/max(r, floor)` closure); `"scf-response"` is the legacy differentiated-SCF path (`algorithms/forces.py` + `_jax_energy.py`), kept for cross-checking and still restricted to real closed-shell RHF (`_check_force_support` holds the open-shell / complex-orbital / spectral-kinetic gates, which are now *legacy-only*). A **frozen core** is refilled before the RDMs are contracted (`rdm.expand_frozen_core(gamma, gamma2, frozen, n_spatial_orbitals)`; core-core `δ_pr δ_qs − δ_ps δ_qr` and core-active `δ_pr γ^act_qs − δ_ps γ^act_qr` blocks, verified *exactly* against an explicit determinant). The state is not orbital-stationary in general, so the neglected orbital-response term is **measured, not assumed**: `ForceResult.details["orbital_gradient"]` carries it and the calculator warns above `ORBITAL_RESPONSE_TOLERANCE = 1e-3` Ha. Validated against central differences of the *same* energy on the *same* frozen grid: **H2 FAO 3.6e-3 eV/Å** (largest force 9.4), **LiH FAO frozen-core 4.6e-3** on 151.1 (3e-5 rel.), **H2O FAO frozen-core 0.146** on 1186.7 (1.2e-4 rel., p orbitals + complex MOs), **H2O PAW 18.2258 analytic vs 18.2267 finite-difference** eV/Å. Pinned by `test/test_all_electron_forces.py`. **What is still true:** (a) **egg-box** — rigidly translating a molecule on a frozen grid changes E (~160 eV/Å for H2O, 23 meV for LiH at h=0.20), and the net force faithfully differentiates that non-translation-invariant discretized energy; (b) **H2O still will not relax**, but the cause is now diagnosed and is *not* the gradient: the H2O **energy surface has no bound minimum** in this model — scanning both O–H at h=0.25 gives −461.20 / −468.82 / −470.68 / −472.37 eV at 0.97 / 1.40 / 2.00 / 2.40 Å, monotonically downhill, and refining to h=0.15 (which silences the projector-resolution warning) does not change it. Fixed earlier and still load-bearing: `nuclear_gradient` used to reach past `integrals.external_potential()` to the bare `-Z/r` and omit `kb_nonlocal()`, so on the PP path (`softening=0`) it built the *wrong* h_ao and diverged at grid nodes; and `_jax_energy._scf` unrolled a fixed 40 iterations whose derivative is only valid **if the SCF converged** — H2O sat on a metastable plateau ~19 iters then escaped, and differentiating the mid-transient unroll gave ~1e8 Ha/Bohr gradients that *looked* fine. `scf_iterations_required` (plain-NumPy probe, runs untraced) now sizes the unroll via `_resolve_scf_iterations`; the caller's `scf_iterations` is a **floor**, and genuine non-convergence raises. **`mandacaru --link-paw DIR` / `--link-oncvpsp DIR` / `--pseudo-status` (2026-09-18)** — the ONCVPSP and PAW datasets are too large to ship, so setting them up is the first thing a user does after cloning, and it should not require knowing `python -m mandacaru.pseudopotentials.link_library` exists. `cli.link_library_command` wraps `link_library(family, source, force=True)` (no geometry required, like `--build-backend`): the CLI passes `force=True` because naming a path *is* the request to use it, so an existing **link** is replaced (the data repository can be moved freely) while a real non-empty `library/paw/` directory is still refused with its message and never deleted. **Dry run** (`algorithms/dry_run.py`, `cli.py`, `__main__.py`): `estimate_qubits(atoms | load_hamiltonian= | hamiltonian=)` → `QubitEstimate` (`n_qubits = 2·(basis functions − frozen)`, plus `num_particles`, per-atom function counts, the device capacity from `Device.qubits` in `backends/hardware.py`, and the state-vector memory) — it *instantiates* the basis family to count functions but never samples a grid. The **`mandacaru` console script** (`[project.scripts]`, also `python -m mandacaru`) wraps `Mandacaru`: `mandacaru H2O --frozen-core --dry-run`, `--json`, `--device-qubits N`, `--load-hamiltonian`; without `--dry-run` it runs the full calculation. **NAO-AE basis** (`basis/nao_ae.py`, `NAOAEBasisSet` in `factory.py`, `BasisSet.build("NAO-AE", tier=1, onset=3.0, width=1.0, scale=1.0, extra=None, linear_dependence_tol=1e-4, tail_norm=1e-4)`): all-electron numerical atomic orbitals, generated from scratch. The minimal basis is every occupied shell (core included) of the self-consistent LDA atom (`atomic_solver.solve_atom`, which now takes a `confinement=` potential applied only in the orbital solves) re-solved in `v_free + v_cut`, where `v_cut = s·exp(−w/(r−r₀))/(r₀+w−r)²` is a smooth exponential wall (zero below the onset `r₀`, capped at `WALL_CAP` beyond `r₀+w`; `onset`/`width` are user-facing Å). Tiers add hydrogen-like states of `−z/r + v_cut` whose `z` is **derived from the atom** via `⟨r⟩ = [3n²−l(l+1)]/(2z)` (`effective_charge_for_radius`; `TIER_RADIUS_RATIOS`: polarization 1×, diffuse 2×, contracted 0.6× the valence ⟨r⟩): tier 1 = polarization at `l_max+1` + one diffuse (n+1) function per valence channel; tier 2 adds `l_max+2`, a noded `l_max+1` and a contracted function per channel (H: 1/5/14 functions, O: 5/14/30). Tier functions are shortened by `tail_norm` (wall re-centred, re-solved); each `l` channel is Gram–Schmidt orthonormalized (`orthonormalize`, minimal first, rejection below `linear_dependence_tol`, a rejected minimal function raises). Output is `RadialTable` → `TabulatedOrbital` (`r_c` at the wall). Cannot be mixed with a pseudopotential family in a per-element basis (all-electron by definition; `resolve_pseudo_basis` raises). On H₂ tier 0 (LDA 1s, more diffuse than the exact 1s) sits *above* FAO and tier 1 well below; core functions are as sharp as FAO's, so use `frozen_core` beyond the first row. Pinned by `test/test_nao_ae.py`; guide in `docs/source/guide/nao_ae.md`; example `examples/23_NAO_AE_basis.py`.

**Per-element basis** (`_hamiltonian_from_atoms.is_per_element_basis`/`per_element_basis`/`PER_ELEMENT`, `basis/factory.PerElementBasisSet`): `basis={"O": {...}, "H": "6-31G", "*": "FAO"}` — a dict keyed by chemical symbols (plus `"*"` default) is detected by the *absence* of a `"name"` key; `resolve_basis` returns `(PER_ELEMENT, mapping)`, callers validate with `per_element_basis(mapping, symbols)` (missing element without `"*"` → error; PW and nesting refused) and then `BasisSet.build(mapping)`; works in `build_basis_hamiltonian`, the dry run, `BlochCalculator`, and on the PP path as a per-element `size` (`pseudo_basis(size={symbol: size})`). **Interaction energies** (`algorithms/interaction.py`: `interaction_energy(atoms, fragments, charges, charge=, method=, basis=, h=, grid=, **solver_kwargs)` → `InteractionEnergy`, also `Mandacaru.interaction_energy`): builds ONE grid from the complex (`grid_from_cell`) and evaluates complex + fragments (`atoms[indices]`, same cell/coordinates) on it — re-centring a fragment changes its grid sampling and, for a sharp core, its energy by eV (Na⁺ at h=0.3: +226 eV); `method="rhf"` is the circuit-free mean-field path (`_rhf_energy`, UHF-NO for odd fragments, 0 for a bare proton). Pinned by `test/test_interaction.py`; guide `docs/source/guide/interaction_energy.md`. ## FAO virtual orbitals (2026-09-17)

`basis={"name": "FAO", "virtual_orbitals": k}` (default **0** = the historical minimal basis, byte-identical) appends the `k` lowest **unoccupied** subshells of each atom to the FAO basis, in aufbau order and with the same bare `Z` as the occupied orbitals. `_config.unoccupied_subshells(atomic_number, count)` is the single source: it returns the `_AUFBAU_ORDER` entries the ground-state filling never reached, so H -> 2s, Li -> 2p, C/O -> 3s, Fe -> 4p. **A partially filled subshell counts as occupied** (carbon's `2p^2` is already a basis shell, so its first virtual level is `3s`), and the helper raises when `count` exceeds the levels left below the end of the filling table. `FAOBasisSet(virtual_orbitals=)` gains `subshells(element)` (occupied in the historical `(n,l)`-sorted order, then the virtuals appended — never interleaved, so the occupied functions keep their indices) and `function_count(element)`; the constructor refuses negatives, non-integers and `bool`.

**`virtual_orbitals` counts levels, not functions** — one virtual `p` level is 3 functions. Deliberate: half a shell would break the atom's spherical symmetry and make the energy orientation-dependent, and "one orbital per subshell" is already the FAO family's own language. H2 costs 4 -> 8 -> 20 -> 24 qubits for k = 0/1/2/3. The option reaches every path for free (`resolve_basis` -> `BasisSet.build(name, **options)` in `build_basis_hamiltonian`, `dry_run` and `bloch`), including the per-element form; the dry-run label becomes `FAO {"virtual_orbitals": 1}`. Electron counts are untouched — only `n_spatial_orbitals` grows.

Validated (H2, 0.74 Angstrom, 8 Angstrom cell, h = 0.30, ADAPT-VQE/fermionic to basis FCI): **-28.161879 eV (k=0, 4 qubits) -> -28.300907 (k=1, 8 q) -> -28.338413 (k=2, 20 q)**, monotone as a strict basis superset requires. **Caveat:** a virtual hydrogenic orbital is diffuse (H 2s has <r> = 6 a0 ~ 3.2 Angstrom), so the cell must contain it or the grid clips the tail. Pinned by `test/test_fao_virtual_orbitals.py` (32 tests); guide `docs/source/guide/basis_sets.md`.

## PAW and p-valence binding: the compensation-charge fix (2026-09-17)

**Symptom.** PAW's energy surface had no bound minimum for O/C-containing molecules: exact sector ground states of OH, CH and H2O were monotonically downhill out to dissociation in every `size` and at every `h` (OH/SZ sat +7.50 eV above dissociation at the experimental r_e, DZ +7.09), while s-valence systems were bound and accurate — LiH (1.69 Angstrom) was the positive control that validated the rest of the pipeline. The relaxations still *converged*, cleanly, to the wrong answer: a converged relaxation is **not** evidence that the model binds, so check with an energy scan before trusting a geometry.

**Root cause.** `MolecularIntegrals._compute_one_body` builds `T + V + C D C+`, where the external potential `V` is the grid integral of `v^ion` against the **smooth pair density** `phi~* phi~`. PAW's compensation charge is an *extra* density on top of that, so the grid integral could not see it — while `two_body_augmentation` gave it its full Hartree repulsion. The compensation charge therefore repelled every electron and was attracted to no nucleus. It scales with the augmentation charge (O carries 0.64 e against Li's 0.009 and H's 0.021), which is why the failure tracked the heavy atom's valence angular momentum exactly: the augmentation term is **+102 eV for OH** against +0.55 eV for LiH, and grows by **+8.7 eV** between 4.0 and 0.97 Angstrom — exactly the binding deficit.

**The fix.** A new hook `MolecularIntegrals.one_body_augmentation()` (returns `None` by default, so every non-PAW basis is untouched), added to `one` in `_compute_one_body` and to the force's energy rebuild in `pseudo_forces`. `PAWIntegrals.one_body_augmentation` returns `sum_{A,LM} Q^{A,LM}_pr V^{A,LM}` with `V^{A,LM} = integral g^_{A,LM} sum_{B != A} v^ion_B` from `compensation_ionic_at(centres)` — an **atom-centred spherical quadrature**, not the grid (the shape spans ~4 grid points at h = 0.20 Angstrom, so a grid sum would be inaccurate and would inject an egg-box into the force), converged to 1e-9 at the default order. The on-site `B = A` term is excluded: it is already inside the dataset, which is calibrated to the reference atom. Taking `centres` as an argument is what lets the force difference it (`pseudo_forces._ionic_shift`).

**Results** (exact sector ground states, PAW-SZ, h = 0.20, 12 Angstrom cell): OH unbound (+7.50 eV at r_e) -> **bound, 1.05 Angstrom, 3.46 eV** (experiment 0.9697, 4.6 eV); CH unbound -> **1.25 Angstrom, 1.77 eV** (1.1199, 3.47 eV); LiH 1.69 Angstrom, 1.44 -> 1.65 eV. PAW-DZ moves OH's minimum to ~0.90 Angstrom, bracketing experiment from the other side. Relaxations agree with the surface: CH converges to 1.3103 and 1.3105 Angstrom from opposite sides, OH from 1.15 to 1.0399 Angstrom.

**Test pins moved with it — do not restore the old ones.** Every PAW energy dropped by an amount that scales with the augmentation charge (see the pinned `test_paw.PAW` values above; the old table is kept beside them as `PAW_BEFORE_COMPENSATION_ATTRACTION`). **H2 PAW-DZP `d_eq` moved 0.807 -> 0.712 Angstrom** (h = 0.25; experiment 0.741, VASP-PBE 0.750 — absolute error improved from +0.066 to -0.029), so `test_paw_forces` changed too: 0.75 Angstrom is now *outside* the minimum (`bond_force > 1.0`, it read `< -1.0`), and `test_h2_force_curve_follows_vasp` compares only *signs* where |VASP force| > 2 eV/Angstrom, because the two methods' minima are 0.04 Angstrom apart. The gradient itself was never in question. Also re-pinned in the **Y_LM convention**: `compensation_moments()` / `compensation_coulomb()` are keyed by multipole channel `(atom, L, M)` and the monopole carries `1/sqrt(4 pi)` with the Coulomb matrix carrying `4 pi` — every product, and so every energy, is unchanged to 1e-16.

**Two hypotheses built, measured and REFUTED** — both are correct machinery, neither was the cause; do not "re-fix" these. (1) **Multipole compensation** (`pseudopotentials/multipoles.py`, ~330 lines): `shape_function`/`shape_potential` for any L, `gaunt` by quadrature (no Wigner dependency), `radial_moments`, `multipole_coulomb_matrix` (vectorized; the force needs *directional* derivatives, unlike the monopole), `paw_multipole_blocks` + `PAWDataset.multipole_moments`, and `PAWIntegrals` keyed by `(atom, L, M)` throughout. `L = 0` reduces to the old monopole to 3e-16 and uses the *stored* `q_ij` rather than the reconstruction (the raw basis's large `B^-1` amplifies a 1e-8 reconstruction error to 1e-4). O gains 9 channels (L = 0,1,2), H keeps 1. Effect on OH binding: 0.5 eV. Kept, because the electron-ion fix sums over the same channels. (2) **One-centre two-body term** (`pseudopotentials/onecenter.py`): `radial_coulomb` (validated against a uniform sphere), `angular_coupling`, `one_centre_coulomb`, `reference_density_matrix` — the linearization's missing piece `1/2 (D-D0)^2 dW`, **measured at 0.08-0.33 eV for oxygen** and ~0 for Li/H. **Not wired into the Hamiltonian**: validated machinery plus the measurement that ruled the hypothesis out.

**Cost note.** SZP is impractical for relaxation, measured: OH/PAW-SZP is 13 orbitals -> 26 qubits, **127,948 Pauli terms**, sector dim **204,490** (2.6e10 term-state products against DZ's 3.7e8). Memory is fine (~2.1 GB, the batched `restrict` holds) but one geometry's Hamiltonian takes **~40 min**, so a relaxation is an overnight job; `ParticleSector.restrict`'s per-term Python loop is the thing to optimize if SZP is wanted. **DZ is the practical improvement over SZ.**

## The compensation potentials are not Hermitian (2026-09-17)

**Root cause of the p-valence *force* error** (the binding failure was a different bug, fixed earlier the same day). `PAWIntegrals.compensation_potentials()` returns `W^{A,LM}_qs = integral phi~*_q phi~_s v_L(r_A) Y_LM(r^_A)`. **The weight is complex whenever M != 0**, so `W` is Hermitian only for the M = 0 channels — measured on water, `|W - W^H|` is 1e-16 for every `(A,L,0)` channel and *as large as `|W|` itself* for every M != 0 one. The Pulay branch of `pseudo_forces` nevertheless wrote the product rule as `dW[channel] = cross_w + cross_w.conj().T` with `cross_w = ((dpsi.conj() * v_comp[channel]) @ psi.T) * dV`, and `cross^H` puts **`conj(v)`** in the second half instead of `v`. Both halves are now written out explicitly. One line; nothing else in the force path was wrong.

**Why it hid for two days.** The compensation channels come from the *pseudopotential's* angular channels, so an s-valence atom has only `(A,0,0)` with a real weight: **H and Li never exercise the bug** (H2 4.4e-5, LiH 1.6e-4 against OH 4.2e-2), and all 76 `test_paw*.py` tests passed before and after the fix. It also explains the *shape* of the error: on C2v water with the bonds along y and z, z is carried by the real `M = 0` harmonic and y by the complex `M = +-1` pair, so the analytic oxygen force came out **2.2496 along y against 2.7841 along z** for a geometry whose y-z symmetry is exact.

**How it was found** (worth repeating for the next one): monkeypatch `AlgebraicEnergy.directional` to capture every `(dS, dh, dg)` it contracts, rebuild the integrals at displaced geometries **on the same frozen grid**, and compare each matrix derivative with its own central difference. Result: `dS` 2e-6, `dh` 6e-6, **`dg` 1.4e-1** — the two-body augmentation, and only for oxygen. Then `dU` was cleared at 1e-5 against a finite difference of `compensation_coulomb()`, and `dQ`/`dC` were cleared by `dS`/`dh` already being exact, leaving `dW`. **Watch the units in that audit: the analytic derivatives are per Bohr and an ASE displacement is in Angstrom, a factor 0.5292 that looks exactly like a physics bug.**

**Results** (water, PAW-SZ, h = 0.20): analytic vs finite difference of the calculator's own energy **0.575 -> 0.0032 eV/Angstrom**, `dg` 1.4e-1 -> 9e-6, and the C2v symmetry is restored (O: 2.82747 vs 2.82755 along y and z). **The reported net force got *larger*, 0.869 -> 1.158 eV/Angstrom, and that is correct**: the rigid-translation finite difference gives dE/dt = -0.8162 eV/Angstrom per axis against the fixed -0.8188, so the gradient now agrees with its energy and the old cancellation was accidental.

**What remains is a real egg-box, and it converges.** Net force / largest force for that water: **1.85 / 0.86 / 0.41 / 0.099 / 0.025 at h = 0.30 / 0.25 / 0.20 / 0.16 / 0.13** (27-49 s per geometry, 12 qubits). Oxygen needs **h <= 0.16 for geometry**, finer than the h <= 0.25 that suffices for energies.

**H2O in PAW-SZ binds** — the older "H2O has no bound minimum, BFGS is walking correctly down a wrong surface" note was the **all-electron FAO** path and predates the compensation-attraction fix. Symmetric O-H scan at h = 0.16, angle 104.5 degrees: -480.799 / -481.924 / -482.201 / **-482.291** / -482.205 / -481.634 / -480.335 / -477.730 / -475.204 / -474.657 eV at 0.85 / 0.92 / 0.96 / **1.00** / 1.05 / 1.15 / 1.30 / 1.60 / 2.20 / 3.20 Angstrom — monotonic out to dissociation, so **7.63 eV for the two bonds** (3.8 each against 4.8 experimental), with the bond force crossing zero at 1.00 Angstrom. A relaxation from 90 degrees / 1.0 Angstrom at h = 0.16 with `project_translation=True` reaches 0.9921 Angstrom / 117.29 degrees in 3 BFGS steps: the bond length is good (+3.6 %) and the 13 degrees on the angle is the minimal valence s+p shell, not the gradient (PAW-DZ on water would be 24 qubits / sector dim 245,025 — the SZP-class cost documented above).

Pinned by `test/test_paw_forces.py`: `test_compensation_potentials_are_hermitian_only_for_m_zero` (the structural invariant, no solver), `test_forces_respect_the_c2v_symmetry` and `test_p_valence_force_is_the_derivative_of_the_energy` (both **verified to fail on the pre-fix code**), and `test_translation_projection_zeroes_the_net_force`.

## One `output.txt` per relaxation, with the forces in it (2026-09-18)

**`Mandacaru.calculate` builds a fresh solver for every geometry**, so a relaxation created one `AdaptOutputLogger` per BFGS step and each opened the path with mode `"w"`: the file that came out of a twelve-step run held **one** step's iterations, and the forces — the thing a relaxation is actually judged on — were never in it at all. Four changes, all in `utils/logging.py` plus one call site:

- **The banner is the file's, not the block's.** `utils/banner.lines()` is the single source of the banner text (`show()` writes exactly those lines to stdout), and `AdaptOutputLogger` writes them into a **freshly opened** log — the test is `self._fh.tell() == 0`, so appending never repeats it while an explicit `append=True` to a not-yet-existing file still gets it. `banner=False` opts out; the stdout banner is unchanged (once per process via `base._BANNER_SHOWN`).
- **Later steps append.** `_LOG_STEPS` maps each log's **absolute path** to the number of blocks written to it in this process: the first logger truncates, every later one appends (`append=True|False` overrides). `logger.step` is the 1-based block index, written as a `step:` line and in the block title. `log_steps(path)` reads the counter and `reset_log(path=None)` forgets it — a fresh process starts empty, so only a long-lived one needs it. **Consequence to expect:** a *scan* that reuses one `output=` path across several `Mandacaru` objects in one process now concatenates instead of overwriting; give each geometry its own path if you want separate files.
- **Forces are logged.** `append_forces(path, symbols, forces, hellmann_feynman=, pulay=, units=, extra=, step=)` appends a `[FORCES]` block: three per-atom tables — `forces` is what ASE consumes (-dE/dR), `hellmann_feynman` and `pulay` are the gradient components (+dE/dR), as `ForceResult` defines them, and the block says so in a `convention:` line — then `max_force` / `rms_force` / `net_force`. `Mandacaru._log_forces` calls it after `_forces` (the solver's own logger is closed by then, which is why this is a module function and not a logger method), adding `force_method`, `include_pulay`, `pulay_fraction`, `n_electrons` and the two residuals that say whether the gradient is usable at all: `orbital_gradient` and `translational_residual` (plus `translation_projected` when the mean force was removed). It is skipped when the solver has no `output` (only `ADAPTVQE` has one).
- **The blocks are indented 4 spaces** (user directive; `utils.logging.INDENT`, `_indent(lines, level)`, `AdaptOutputLogger._emit_body(..., level=1)`). Section markers, the `====` rules and the banner stay at column 0; a block's keyed lines take one level and what a keyed line *contains* — the atoms under `geometry:`, the lattice vectors under `cell_vectors:`, the iteration table's heading/rule/rows, each force table — one more. Blank separators stay truly empty, and a block appended under an earlier one is preceded by a blank line. **Indentation is invisible to the reader code** — `parse_output` strips every line, which is why the format change needed no parser change and old logs still read back.

Two more user directives of the same day: **no `operator_sequence` in the summary** (the iterations table already names the operator every step selected, *in order*, and `result.operators` is the same list as data — on a wide register that one line was longer than the table it duplicated), and the log's `ITERATION_COLUMNS` run **`1q` / `cnot` / `depth`** (cheapest gate first); the stdout trace keeps its own order (`cnot, 1q, depth`, `_ITERATION_COLUMNS` in `adapt_vqe.py`).

`parse_output` is **step-aware**: `result["steps"]` is the list of blocks in order and the top-level `metadata` / `system` / `setup` / `iterations` / `summary` / `forces` keys describe the **last** step, so reading a single-point log is unchanged. `[FORCES]` parses into `symbols` plus the three `(N,3)` lists and its scalars, and a file need not open with a system block (a forces block alone is still a step; `_SECTIONS` drives the dispatch). Pinned by `test/test_noncubic_and_output.py` (`TestLogAppendsAcrossSteps`, `TestForcesBlock`, `TestRelaxationLog`, `TestBlockIndentation`).

**What the forces in the log immediately showed: the final step's `fmax` is often the egg-box.** In the h = 0.10 water relaxation all three atoms' forces pointed the same way at convergence and `net_force` (0.0222) exceeded `max_force` (0.0131), with `net_force` sitting at 0.016-0.022 through the whole run — so an `fmax` of 0.02 at that grid is a translation, not a deformation. Use `project_translation=True` for this kind of run, or stop at `fmax` 0.03-0.05.

## `[PERFORMANCE]`, and stdout becomes the ASE table (2026-09-18)

Two user directives, the second of which reverses the "the run trace is always printed" decision above.

**1. The `[PERFORMANCE]` block** (`utils.logging.append_performance` / `_performance_block_lines`): one per evaluation, closing the step *after* `[FORCES]`. It lists every timed stage with a rule and the sum, then `untimed_s` (`wall_time_s` minus the stages: Hamiltonian construction, the mapping, materialization — work no stage wraps), `wall_time_s`, and the machine: `integration_backend`, `openmp_threads` (what the C kernels used) against `cpu_count` (what the machine has), `mpi: not used (single process, shared-memory OpenMP)` — stated because the word invites the assumption — `peak_memory_MiB` (the process high-water mark, so monotonic across a relaxation) and `resident_memory_MiB` (current RSS, so the two together show a stage that allocated and released; needs psutil, else `n/a`). `Timings.resources()` builds that table, with `profiling.cpu_count()` / `current_memory_mb()` as the new helpers.

**`Mandacaru` writes the block, not the solver**, and that is the whole point of its position: on a real relaxation **the nuclear gradient is the largest single stage** — water/PAW-SZ at h = 0.10 spends **62 % of its 325 s on forces against 19 % on the variational optimization** — so a block closed when `run()` returned would account for the smaller part of the step. `Mandacaru.calculate` times the gradient (`"nuclear gradient (forces)"`) and any provider measurement (`"measurement (provider)"`), merges them into a `Timings` seeded from `result.timings`, and appends the block; `VariationalDriver.defer_performance` (set by `Mandacaru`) tells the solver to skip its own, so a **direct** `ADAPTVQE(...).run()` still writes one with its own stages. `VariationalDriver.write_performance` / `qpu_accounting` are the hooks.

**QPU accounting** (`backends.providers.qpu_usage(provider, wall_time_s)`): `qpu_device`/`qpu_shots`/`qpu_wall_time_s` always, plus `qpu_jobs`/`qpu_job_ids`/`qpu_seconds`/`qpu_billed_seconds` from `job.metrics()["usage"]` when the provider reports them (Qiskit Runtime, real device only). `qpu_seconds` is the metered time that counts against the open plan's monthly quota. Every read is defensive — a job object that raises still leaves a usable block — and nothing is invented: a local simulator contributes the wall clock and the device name, and a run with `shots = 0` emits **no** `qpu_*` keys at all.

**2. stdout is now ASE's table.** Measured first, as asked: the water relaxation printed **552 lines for 6 steps** — per step a 35-line configuration header, a 33-line iteration table and a 13-line timings block — of which the **7 lines** of ASE's `Step Time Energy fmax` table were what the user wanted to watch, and all 552 duplicated, in a second format, what `output.txt` now holds structurally. So `output=` decides the split, exactly as GPAW's `txt=` does: **with a log file the solver's trace is off and stdout carries only ASE's evolution of energies and forces; without one the trace is printed** (it is then the only report there is). `Mandacaru(trace=True|False|None)` overrides — `None` is the automatic choice — and `verbose=` is refused with a message pointing at `trace=`.

**ASE does not flush `Optimizer.log`** (verified in `ase.optimize.optimize`), and its line is ~60 bytes: a redirected `python run.py > run.log` would have shown nothing for minutes and a running relaxation would have looked hung. `calculator._watchable_stdout()` therefore reconfigures a **non-tty** stdout to line-buffered, once per process and defensively (a replaced `sys.stdout` may not support it), and `calculate` flushes at the end as a fallback. A tty is line-buffered already, so this changes only the redirected case.

Pinned by `test/test_noncubic_and_output.py` (`TestPerformanceBlock`, `TestQPUAccounting`, `TestStandardOutputIsTheASETable`). Guide: `docs/source/guide/run_output.md` opens with a "What goes where" table.

## The orbital-response warning: what it means, and the pool fix (2026-09-18)

The user asked why `atoms.get_forces()` on H2O/PAW-SZ warns `the state is not stationary with respect to orbital rotations (max |dE/dkappa| = 8.5e-03 Ha)`, and **the message's advice was wrong**, so it is rewritten.

**What the residual is.** `AlgebraicEnergy.orbital_gradient` is `max |dE/dkappa|` over orbital rotations with the RDMs frozen. It vanishes at *both* ends of the correlation range — RHF is orbital-stationary, and a full CI in an orbital space is invariant under rotating those orbitals, so the frozen-orbital gradient is the *whole* derivative there. Measured at the relaxed water geometry (h = 0.25, 6 orbitals, sector dim 225): **HF determinant 1.2e-9 Ha, exact sector FCI 1.8e-9 Ha, ADAPT (30 `ceo` operators, 5.4e-4 Ha above FCI) 1.0e-2 Ha.** So a nonzero residual does **not** report an unconverged optimizer — it reports an ansatz that stopped short of its space's FCI.

**Why tightening the tolerance does nothing.** The energy is *second* order in the state error, this residual *first* order: `gradient_tolerance` 1e-3 -> 1e-4 with `max_iterations` 50 -> 100 grew 30 -> 41 operators and moved the screening gradient 1.8e-4 -> 7.6e-5, the energy by **1e-6 eV** and the residual by **0.6 %**. Pinned as a scaling law by `test_all_electron_forces.py::TestOrbitalResponseResidual` (contaminate the exact state by epsilon: residual proportional to epsilon, energy error to epsilon^2; the two zeros are pinned there too). **The test system is a scalene H3+ triangle on purpose:** H2 in a minimal basis has two orbitals of opposite g/u parity, so its energy is *even* in the rotation angle and the residual is identically zero however bad the state is — the test would pass for the wrong reason.

**The lever is the pool.** Same geometry, same h = 0.25, `gradient_tolerance=1e-4`, `max_iterations=100`:

| pool | size | ops | max grad | E-E_FCI (Ha) | dE/dkappa (Ha) | fmax (eV/Ang) | CNOTs |
|---|---|---|---|---|---|---|---|
| `ceo` | 92 | 37 | 9.1e-5 | 5.44e-4 | **1.00e-2** | 2.6257 | 1456 |
| `fermionic` | 92 | 85 | 9.4e-5 | 4.06e-4 | **2.91e-5** | 2.5696 | 8138 |
| `qubit` | 640 | 100 | 1.9e-4 | 4.05e-4 | **6.36e-5** | 2.5698 | 1226 |

`fermionic` and `qubit` cut the residual **~300x** (below `ORBITAL_RESPONSE_TOLERANCE`, so no warning) while improving the energy only 25 % — exactly the first-order/second-order asymmetry. And the forces follow the residual, not the energy: the exact-FCI state gives fmax 2.5441, the two low-residual pools land within 0.026 of it and agree with each other to 0.0002, while `ceo` is 0.082 off. **`pool="qubit"` is the recommendation for this system** — smallest residual-to-cost ratio and *fewer* CNOTs than `ceo` (1226 vs 1456), at the price of 100 operators and a 640-operator screening. (`ceo` is `qeb` in this codebase, so it is not the varied pool its name suggests.) **Consequence for the user's relaxation:** the ADAPT-vs-FCI force error is **0.085 eV/Angstrom** at that geometry, ~6x the `fmax = 0.0131` the run converged to — a second error source above the threshold, alongside the 0.022 eV/Angstrom grid egg-box.

## `project_translation="auto"` is the default (2026-09-18)

The user asked when `project_translation` makes sense and whether it can decide for itself. It can, and the argument is a theorem rather than a heuristic: **the exact force of a free molecule sums to zero, so subtracting the mean is the orthogonal projection onto a subspace that *contains* the true answer, and an orthogonal projection can never increase the distance to a point already in the subspace.** The reported force is therefore never made worse by projecting and is usually made better, whatever the grid error happens to be. Pinned by `test_paw_forces.py::test_projection_cannot_increase_the_error_against_a_zero_sum_force`.

**What it gives up** is the identity `forces == -dE/dR` of the *discretized* energy, which genuinely is not translation invariant. That is a property of the approximation, not of the physics — but it is the property most of the force tests exist to check, so the raw array is kept: **`ForceResult.unprojected`** (backed by `details["forces_unprojected"]`, equal to `forces` when nothing was projected), alongside `details["translational_residual"]` (always the *unprojected* residual, since `_check_translational_invariance` runs first and still warns) and `details["translation_removed"]`.

`DEFAULT_PROJECT_TRANSLATION = "auto"`, `PROJECT_TRANSLATION_CHOICES = (True, False, "auto")`. `Mandacaru._projection_applies(result)` is the gate: **at least 2 atoms** (a single atom's grid re-centers on it, so its residual is zero by construction and says nothing) and **not periodic** (the sum over a cell's atoms is not the free-molecule identity; an explicit `project_translation=True` there emits a `RuntimeWarning` saying it is ignored rather than doing nothing silently). Validation is by *type* — `1 in (True, False, "auto")` is `True` in Python, so an int is refused as the typo it is.

**Consequence for recorded numbers:** every force quoted in this file before 2026-09-18 is the *unprojected* one, reproducible with `project_translation=False`; the differences are the egg-box residuals documented per system. Flipping the default failed 8 tests, every one asserting a property of the raw gradient (finite-difference checks in `test_fao_forces`/`test_all_electron_forces`/`test_paw_forces`, the LiH egg-box measurements, the Hellmann-Feynman + Pulay identity); all now read `force_result.unprojected` with a comment saying why, so the trade-off is visible at each assertion instead of hidden in a default. Policy tests: `test_fao_forces.TestTranslationProjectionPolicy`.

**When to turn it off:** validating a gradient against a finite difference, comparing against the driver's raw output, or measuring the egg-box itself. For relaxation and dynamics — where the artifact is systematic and integrates into a centre-of-mass drift — leave it on. ASE's plain `BFGS`/`FIRE` use forces only, never the energy, so projection introduces no inconsistency into the optimizer; `BFGSLineSearch`/`QuasiNewton` do use the energy, and there the projected force and the unprojected energy are mildly inconsistent by exactly the residual.

## `[GEOMETRY OPTIMIZATION SUMMARY]` and the relaxation footer (2026-09-18)

User directive: a relaxation needs a final summary of the relaxed geometry, the per-step `[SUMMARY]` becomes **`[QUANTUM VARIATIONAL SUMMARY]`** (it summarizes one geometry's variational run, not the relaxation), and a small footer says the relaxation finished.

**The hard part is *when*, not *what*: ASE never tells a calculator that a relaxation is over** — the optimizer just stops calling it, and there is no hook. So there are two paths, both ending in the same block written once:

- **`Mandacaru.write_optimization_summary(atoms=None, fmax=None, optimizer=None, force=False)`** — explicit, returns whether it wrote. Passing `optimizer=opt` is the *only* way the footer can state a verdict: it asks the optimizer's own `converged()`, which accounts for constraints and filters. Without it the footer reports the final force and says the run `finished`, because the threshold is the optimizer's and the log does not guess it.
- **an `atexit` hook**, armed the first time a geometry step with forces is logged (`_arm_exit_hook`), so an unmodified script gets the blocks with no edit. `_write_summary_at_exit` swallows every exception on purpose — the calculation finished long before, and a log that cannot be closed (interpreter shutdown, a deleted temp directory, a read-only file) must not look like a failed run — and its status says completion was **not signaled**, naming the call that signals it.

`_summary_written` is set **after** a successful write, so a failed write can be retried, and an empty trajectory returns `False` instead of raising. Nothing is written for a **single** geometry (no trajectory to summarize) unless `force=True`. `Mandacaru.trajectory` accumulates one entry per force evaluation (energy, `max_force`, `net_force`, wall time, centre of mass, positions, symbols); **`net_force` is always the *unprojected* residual**, so the convergence table shows the grid artifact even though `project_translation="auto"` removed it from the reported forces.

`utils.logging.append_optimization_summary(path, history, symbols=, positions=, fmax=, ...)` writes both blocks: the scalars, a `convergence:` table (`step energy max_force net_force`), the `relaxed_geometry:` table (via `_geometry_rows`, factored out of `write_system` so a geometry reads the same everywhere in the file), then `[RELAXATION COMPLETE]` with a one-line `status:`. `center_of_mass_drift` is included because a free molecule cannot translate under its own forces — whatever is there is the egg-box. **Parsing:** `_SUMMARY_MARKERS = ("[QUANTUM VARIATIONAL SUMMARY]", "[SUMMARY]")` — the old marker still reads — and the two closing blocks land at the **top level** of `parse_output` (`result["optimization"]`, `result["completion"]`) rather than inside a step, because that is what they describe; `convergence` comes back as a list of `{step, energy, max_force, net_force}` and `relaxed_geometry` as `[symbol, x, y, z]` rows. Pinned by `TestGeometryOptimizationSummary` (8 tests). Examples 28 and 29 end with `atoms.calc.write_optimization_summary(optimizer=opt)` — note it is `atoms.calc`, as both assign the calculator inline.

## UPAW: an option, not the default (2026-09-18)

`~/Dropbox/UPAW.pdf` = Ivanov *et al.*, *Quantum Computation of Electronic Structure with PAW and Plane Waves* (arXiv:2408.03159v2, Riverlane). Its **unitary PAW** picks pseudo partial waves with `O_ij = <phi_i|phi_j> - <phi~_i|phi~_j> = 0`, so `T+T = I` and the pseudo states stay orthonormal — needed because qubitized QPE on a non-orthogonal basis is a generalized eigenproblem.

**Mandacaru already had the knob.** `q = pw.norms - pw.achieved` with `norm_factor = 1 - s`, so `q = s norms` and **`norm_deficit=0` *is* UPAW**. Datasets for H, Li, C, O build cleanly that way (`|q| <= 3e-14`, overlap minimum exactly 1.0000, eigenvalues to <= 1.4e-7 Ha, duality 1e-14, no ghosts, same generation time; `|S - S~| = 9.8e-14` at the molecular level). **It is not the default, for three measured reasons:**

1. **We do not need it.** Mandacaru Loewdin-orthogonalizes the augmented overlap (`_lowdin_x` on `S = S~ + C q C+`) *before* building the second-quantized Hamiltonian, and `eig(S^-1/2 H S^-1/2)` is exactly the generalized problem's spectrum — the many-body basis is already orthonormal. The paper's problem is specific to a plane-wave basis that cannot be cheaply orthogonalized against the augmentation.
2. **It does not remove the augmentation machinery.** The constraint fixes only the *norm*, i.e. the **L = 0** moment. Water at h = 0.25, oxygen: `|Q^{L=0}|` 3.2e-2 -> **7.7e-15**, but `|Q^{L=1}|` 1.5e-2 -> 6.9e-3 and `|Q^{L=2}|` 1.4e-3 -> **2.2e-2 (16x larger)**. `W`, `U`, `one_body_augmentation`, `two_body_augmentation` and their force derivatives all remain — including the complex M != 0 channels that carried the Hermiticity bug.
3. **The waves are harder, and it lands on the forces.** Water's net force (the egg-box) is **5x larger**: 0.380 -> 1.918 eV/Angstrom at h = 0.25 and 0.0415 -> 0.2227 at h = 0.20. Energy converges ~19 % more slowly in `h` — the same ordering the paper concedes (PAW converged at 400 eV, UPAW at 600). The guess that a smaller monopole would *reduce* the artifact is refuted: hardness dominates.

Physics agrees where it should, so this is a cost judgement and not a correctness one: **LiH d_eq 1.6782 (PAW) vs 1.6802 Angstrom (UPAW)** and binding 3.2389 vs 3.1413 eV. The LCU one-norm lambda is unchanged (H2 1.3563 -> 1.3579 Ha), so it buys nothing on the quantum-resource side either — the paper's lambda reduction is against *all-electron plane waves*, while PAW and UPAW share the same localized basis size here.

**Worth taking from the paper instead** (neither implemented): **down-sampling** (Sec 3.2.1, `E_ds(n+1) = E_ds(n) + E(n+1, n_b) - E(n, n_b)` — reach the converged-basis energy through *differences* computed with fewer orbitals; it maps directly onto `BlochCalculator.total_energy(kmesh)`, already a BvK supercell series, and onto the SZ->DZ->DZP hierarchy), and **lambda and Gamma as dry-run outputs** (the paper's cost model is Toffoli ~ O(sqrt(Gamma) lambda / eps); lambda = sum |c_P| is one sum over a `PauliSum` we already build and would let a user rank basis/mapping choices by *fault-tolerant* cost rather than qubit count alone). Their two-body **rank reduction / double factorization** is a real project (Mandacaru has no DF/THC), not a quick win.

**Shipped as the family `"upaw"`** (user directive). `basis="UPAW"` (alias `"unitary-paw"`) is a registered `FamilySpec` like any other, so it reaches the driver, the per-element form and the dry run (`"UPAW (DZP, pseudopotentials)"`) with no driver edit. In `pseudopotentials/paw.py`: `UPAW_FAMILY`/`UPAW_LIBRARY_SUBDIR`, `generate_upaw(symbol, **options)` = `generate_paw(norm_deficit=0.0, ...)` tagged `family="upaw"` via `dataclasses.replace` (an explicit `norm_deficit=` is a `TypeError` — it *is* the family's definition), `upaw_library_path`, `get_upaw`, `build_upaw_library`, `build_upaw`, and `build_paw(..., loader=None)` so the molecular path is shared verbatim. Exported from `mandacaru.pseudopotentials`.

**No library is shipped, so `get_upaw` generates on demand** — it looks in `library/upaw/`, finds nothing, generates, caches in `_CACHE` and warns once (0.4-2.2 s per element; H2 end to end 0.6 s first call, 0.2 s cached). An *explicit* `directory=` is a statement that the library is there, so a missing element raises with the `build_upaw_library` recipe instead. That asymmetry is deliberate: generating is cheap enough to be invisible in the default case and wrong to do silently when the user named a path. **One serialization fix was needed:** `io.save_pseudopotential` wrote the *layout* family into the `family` field, so a UPAW dataset came back as `"paw"`; `TABLE_FAMILIES` now maps **family -> codec** (`"upaw": ".paw"`, i.e. not invertible), the writer stores the record's own family when it shares the layout, the loader hands the canonical name down in the payload, and `paw.from_payload` reads `payload["family"]`. A PAW file is refused as UPAW and vice versa.

Pinned by `test/test_upaw.py` (17 tests, 8 s): `q = 0` and `overlap_minimum == 1.0` exactly, the molecular `S == bare_overlap()`, the PAW contrast, no ghost / duality / eigenvalue in a generated dataset, name and alias resolution, `generate_upaw` refusing `norm_deficit`, a PAW file refused as UPAW, the on-demand-vs-named-directory asymmetry, `basis="UPAW"` end to end, the dry-run label, family mixing refused, a built library used without the generation warning, **and the two measurements that keep it from being promoted** (`L = 0` gone while `L = 1, 2` are not, and `basis="PAW"` still resolving to `paw`). Guide: the "UPAW: a unitary transformation" section of `docs/source/guide/pseudopotentials.md`. `test_upaw.py` reads Parquet, so it joins the files that must not share a process with a Qiskit-transpiling one.
