# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Carcará** is a framework for fermionic quantum simulation based on variational quantum algorithms (VQAs), targeting real NISQ-era quantum hardware (IBM Quantum via Qiskit). The intended end-to-end pipeline is: fermionic system → second-quantized Hamiltonian → qubit (Pauli) Hamiltonian → parameterized ansatz → VQA optimization → QPU/simulator execution → error mitigation. See `plan/roadmap.md` for the full phased design and its flagship algorithm, **ADAPT-VQE** with pluggable operator pools (fermionic / qubit / QEB / CEO), plus its **excited-state** extensions (deflation / subspace-search).

**Important:** the project is mid-build. Implemented end-to-end: localized bases (FAO / NAO / STO-nG / 6-31G(d)), **a periodic plane-wave basis** and the **pseudopotential families NCPP / ONCVPSP / PAW** (selected as a basis name, `basis="PAW"`; package `carcara.pseudopotentials`, stable since 2026-09-15) → real-space (and reciprocal-space, for PW) integral engine → second-quantized `Fermion` Hamiltonian → fermion-to-qubit mappings → **UCCSD ansatz → VQE** and **ADAPT-VQE** (both exact state-vector solvers, validated on H₂), with **RHF/UHF** for the molecular-orbital basis. Also implemented: **excited states** (`energy_levels` via variational deflation, and `SubspaceVQE`/`SubspaceADAPTVQE` subspace-search), and the periodic-system **`BlochCalculator`** (band structure + BvK total energy, `method="adapt-vqe"|"vqe"`). All solvers share a common **`VariationalDriver`** base (`algorithms/base.py`) with the excited-state methods as composable mixins. **The single user-facing entry point is `Carcara(method=..., ...)`** (`algorithms/calculator.py`; renamed on 2026-09-09, the old name is gone without alias — also `from carcara import Carcara`) — an ASE calculator selecting the solver by the `method` string (`"adapt-vqe"` is **the default everywhere**, also for `BlochCalculator`; `STABLE_METHODS` = `"vqe"`, `"adapt-vqe"`, `"subspace-vqe"`, `"subspace-adapt-vqe"`; anything else must be added with `register_method(name, cls)` — the `carcara.experimental` package registers its own solvers when *explicitly* imported, and the stable code, docs, README, examples and website never name them; a repository sweep under `test/experimental/` enforces that), forwarding all solver options, and exposing the run result uniformly on `.result` (plus `.solver`/`.hamiltonian`/`.n_qubits`/`.num_particles`, direct-mode `run()`, and `energy_levels()`); the solver classes remain the internal layer. The `backends/hardware.py` device registry is written and every entry is runnable (`AER_simulator`, IBM Quantum via Qiskit Runtime, Amazon Braket); **still an empty stub: error mitigation** (`backends/mitigation.py`). Before building on a module, check whether it actually has code (`wc -l`), because `plan/roadmap.md` mostly describes intended design and its later phase (mitigation) is not yet written. `pyproject.toml` is the source of truth for the build (currently Python ≥ 3.11).

## Current state of the code

Implemented:
- `src/carcara/basis/` — localized single-particle basis functions (`BasisFunction` ABC) and three concrete families: `FullAtomicOrbital` (analytic, with Slater charges), `NumericalAtomicOrbital` (confined Sankey/SIESTA-type, `nao.py`), `GaussianOrbital` (contracted GTOs, `gaussian.py`). **All families are generated natively from scratch — no tabulated/external basis-set data.** The `BasisSet` factory (`factory.py`) builds `"FAO"` (Full Atomic Orbitals; one analytic orbital per occupied subshell, carrying the **actual atomic number Z** as the orbital's nuclear charge — the bare hydrogenic orbital, no Slater screening; **`{"name": "FAO", "virtual_orbitals": k}`** appends the `k` lowest *unoccupied* subshells per atom, see below), `"STO-3G"`, `"NAO"`, `"GTO"` and `"6-31G"`/`"6-31G(d)"` bases. The GTO family is a minimal **STO-nG** basis generated in `sto_ng.py` by least-squares fitting `n_gaussians` primitives to the Slater-type orbital of each occupied subshell (Slater's-rules ζ = (Z−S)/n\*), with the reference fit done once at ζ=1 (cached, `_fit_reference`) and exponents rescaled by ζ². `BasisSet.build(method="GTO", n_gaussians=3)` → STO-3G-like; the fit reproduces published STO-nG exponents closely (H 1s → 2.22766/0.40577/0.10982). The **Pople split-valence** family (`pople.py`) reuses that fit to build 6-31G(d): 6-primitive cores, 3+1 split valence, and a native (Slater-heuristic) `d` polarization shell on non-H atoms. Shared aufbau config in `_config.py`, angular helpers in `_angular.py`. `_config.valence_subshells` returns the highest-`n` occupied subshells **plus the semicore `(n-1)d` / `(n-2)f`** when occupied, so Fe is `3d⁶4s²` (8 valence electrons) rather than a 2-electron `4s²` atom — this feeds both the basis and pseudopotential generation.
- `src/carcara/basis/gaussian_families.py` — **named Gaussian families** (`BasisSet.build("cc-pVTZ" | "6-311+G(2df,2p)" | "def2-TZVP" | "STO-4G" ...)` → `GaussianBasisSet`): `parse_basis_name` turns a name into a `GaussianRecipe` (core/valence contraction *patterns*, heavy/H polarization `(l,count)` tuples, diffuse lists or `diffuse_present`, tight functions, `polarization_min_z`=11 for Pople's `3-21G*`), and `gaussian_shells(Z, recipe)` generates `(l, exps, coeffs)` natively: each `(n,l)` shell is one `_fit_reference` Slater fit of `sum(pattern)` Gaussians partitioned tightest-first (`(3,1)` = 6-31G split, `(3,1,1)` = 6-311G), polarization `f_l·ζ_val²` (`HEAVY_/HYDROGEN_POLARIZATION_FACTOR`, ratio 3 spread — `6-31G*` reproduces `pople_631g_shells` exactly), diffuse = most diffuse exponent of that `l` / `DIFFUSE_RATIO` 3.5, tight = tightest valence × 3. Function counts match the published shell notation (`cc-pVTZ` C `[4s3p2d1f]`, `def2-QZVP` C `[7s4p3d2f1g]`, spherical shells); exponents are Carcará's own. `MAX_CONTRACTION = 10`: the Slater fit is numerically singular past ~10 primitives, so `sto_ng._projected_overlap` now rejects ill-conditioned trials (cond > 1e12, overlap > 1) and `_fit_reference` raises instead of returning garbage — keep contractions ≤ 10. `NAMED_BASIS_SETS` lists the 40 validated names; pinned by `test/test_gaussian_families.py` (structure table + H₂ RHF/Hamiltonian integration per family). `6-31G`/`6-31G(d)`/`6-31G*`/`STO-nG` still route to the dedicated `Pople631GBasisSet`/`GTOBasisSet`.
- `src/carcara/basis/multizeta.py` — **multiple-zeta and polarized NAOs**, selected by `BasisSet.build("NAO", size=...)` or `basis={"name":"NAO","size":"DZP","energy_shift":0.03}` (all `NAOBasisSet` options — `size`, `energy_shift`, `r_c`, `n_grid`, `split_norm` — pass through the dict). `ZETA_NAMES` covers `SZ`/`SZP`/`DZ`/`DZP`/`DZ2P`/`TZ`/`TZP`/`TZ2P`/`QZ`/`QZP`/`QZ2P` (or an explicit `(n_zeta, n_polarization)` pair); **the default is `DEFAULT_NAO_SIZE = "DZP"`** — `size="SZ"` is opt-in and keeps the original `NumericalAtomicOrbital` path byte-for-byte. Extra zetas use the **SIESTA split-valence** construction (`split_radius`/`split_valence_tail`): pick `r_s` leaving `split_norm` (0.15) of the norm outside, replace the inside by `r^l(a−b r²)` matched in value *and* slope at `r_s`, keep the difference — each zeta is strictly shorter-ranged than the last (H 1s: 3.99 → 2.09 → 1.22 → 0.81 a₀). Polarization adds a whole `l_max+1` shell solved in the same confining sphere (3 functions for s-valence, 5 for p, 7 for d). All orbitals become `TabulatedOrbital` (`R(r)·Y_lm` off a spline), so the integral engine sees them identically. **Caveat worth knowing:** high zetas are short-ranged by construction and the real-space grid must resolve them — the 3rd H zeta spans 0.65 Å ≈ 3 points at `h=0.20 Å` and contributes ~1e-6 Ha (3.6e-5 at `h=0.12`). DZP is the practical sweet spot; TZ/QZ need a fine grid to be worth anything.
- `src/carcara/integrals/` — real-space one- and two-body integral engine, grid, FFT Poisson solver, C backend binding
- `src/carcara/core/` — the second-quantized layer. `mapping.py`: `Fermion` (fermionic ladder operators with full algebra and a `from_integrals` builder for `H = Σ h_pq a†_p a_q + ½ Σ ⟨pq|rs⟩ a†_p a†_q a_s a_r`), `PauliSum` (the qubit-operator output type, with `to_sparse_pauli_op`), and the three fermion-to-qubit mappings — **Jordan-Wigner** (default), **parity** (with optional two-qubit reduction) and **Bravyi-Kitaev** — via a shared encoding-matrix construction (`map_to_qubits(method=...)`). `hamiltonian.py`: `MolecularIntegrals` drives the integral engine to build the spin-orbital molecular Hamiltonian as a `Fermion`. `planewave.py`: `PlaneWaveIntegrals` — a **periodic plane-wave basis** (`{"name":"PW","energy_cutoff":300}`; eV, default 300) computing the reciprocal-space one-/two-body integrals with PBC (diagonal kinetic `½|G|²`, structure-factor external potential, momentum-conserving `4π/Ω/|G_p−G_r|²` electron repulsion, G=0 removed by jellium), mirroring the `MolecularIntegrals` interface (`molecular_hamiltonian`, `hartree_fock`, `integration_profile`). It guards against an intractable O(N⁴) tensor via `max_plane_waves` (default 60) — a realistic cutoff on a molecule-sized cell yields far too many plane waves for exact state-vector VQE, so use a small cell/cutoff.
- `src/carcara/circuits/` — `base.py` (the **`Ansatz` protocol** — `num_parameters`/`n_qubits`/`reference_state`/`state(θ)`/`evolve(θ, references)` — that every ansatz conforms to structurally, so a new ansatz drops in with no driver change), `gates.py` (anti-Hermitian single/double fermionic excitation generators), `ansatz.py` (`UCCSD`, a state-vector ansatz `|ψ(θ)⟩ = exp(Σ θ_k (T_k − T_k†))|HF⟩`; default is the exact UCC exponential, `trotter=True` gives the circuit-faithful first-order product), `adapt_ansatz.py` (the growable `AdaptAnsatz`), `pools.py` (ADAPT-VQE operator pools — **fermionic**, **qubit** (qubit-ADAPT), **QEB** (Z-strings dropped) and **CEO** (coupled exchange, OVP) — behind a common `OperatorPool`/`PoolOperator` interface with a `build_pool` registry), and `profiling.py` (`CircuitMetrics`/`profile_ansatz` — compile `|HF⟩`+∏exp(A_k) to a native `{cx,u}` gate set for CNOT/depth). `AdaptAnsatz`/`profile_ansatz`/`CircuitMetrics`/`Ansatz`/`UCCSD` are imported from `carcara.circuits` (their canonical home — not re-exported through `carcara.algorithms`). The `evolve(θ, references)` method applies one shared unitary to a `(2ⁿ,k)` stack of reference states (used by the subspace-search solvers).
- `src/carcara/optimizers/optim.py` — `Optimizer`, a classical-optimizer wrapper with cost-history tracking. Six named methods (`NAMED_OPTIMIZERS`): **SPSA**, **COBYLA** (default), **Nelder-Mead**, **SLSQP**, **Adam**, **L-BFGS-B**. COBYLA/Nelder-Mead/SLSQP/L-BFGS-B dispatch to `scipy.optimize.minimize`; **SPSA** and **Adam** are implemented natively (SPSA = two-eval Spall stochastic gradient; Adam = finite-difference-gradient adaptive moments).
- `src/carcara/algorithms/base.py` — **`VariationalDriver`**, the shared ASE-`Calculator` base every variational driver subclasses. It owns the common **problem-setup surface** (`basis`/`grid`/`h`/`kpts`/`spin`/`initial_state`/`charge`/`n_electrons`/`frozen_core`/`frozen_orbitals`/`hamiltonian_builder`/`optimizer`/`device`/`run_options`/`sparse`), the ASE `calculate()` hook (geometry→Hamiltonian each call in calculator mode; reused in direct mode), the **state-vector backend** (`_materialize_hamiltonian` dense/sparse-Hermitize, `_as_pauli_sum`, `_resolve_sparse`, the canonical **`energy(psi)`** — a state vector in, uniformly), the Γ-point k-guard (`_check_kpts`/`_kpts_label`), timings/banner scaffolding (`_make_timings`/`_finalize_timings`/`_show_banner`) and `format_pauli_sum`. Subclasses implement just `_configure(hamiltonian, num_particles, n_orbitals)` (build the ansatz/pool + materialize) and `run()`. Excited-state **methods are mixins** over the base: **`DeflationMixin`** (`algorithms/deflation.py`) supplies `energy_levels(...)` once (the state-by-state VQD outer loop + `EnergyLevels`), with each driver providing the per-state `_deflated_ground` hook; **`SubspaceMixin`** (`algorithms/subspace.py`) supplies the SSVQE `run()` scaffolding, with each driver providing `_reference_occupied`/`_subspace_optimize`/`_make_subspace_result` (the run result always lands on the driver's `.result` — there is no per-class result attribute). So `VQE(DeflationMixin, VariationalDriver)`, `ADAPTVQE(DeflationMixin, VariationalDriver)`, `SubspaceVQE(SubspaceMixin, VQE)`, `SubspaceADAPTVQE(SubspaceMixin, ADAPTVQE)` — and a new method plugs in as a mixin/subclass without re-implementing setup. (`VQE.energy_at(θ)` is the parameter-space cost; the base `energy(psi)` is the state-vector expectation.)
- `src/carcara/algorithms/vqe.py` — `VQE`, an exact state-vector eigensolver (`⟨ψ(θ)|H|ψ(θ)⟩` minimized over ansatz params); validated on H₂ against exact diagonalization to ~1e-9 Ha. `VQE`/`VQEResult` mirror `ADAPTVQE`/`ADAPTVQEResult`: `optimizer` accepts a method-name string (`"SPSA"` / `"COBYLA"` default / `"Nelder-Mead"` / `"SLSQP"` / `"Adam"` / `"L-BFGS-B"`) or an `Optimizer`, `verbose=True` prints the qubit Hamiltonian as Pauli strings + a timing/resources summary on `run()`, and `VQEResult` exposes `num_parameters`/`energy_history`/`correlation_energy`. Both `VQE` and `ADAPTVQE` also have an **`energy_levels(num_states=2, ...)`** method computing molecular **excited states** via variational quantum deflation (VQD): each level minimizes `⟨H⟩ + β·Σⱼ|⟨ψⱼ|ψ⟩|²` over the previously found states (auto `β` from the Hamiltonian's coefficient 1-norm; the shared `DeflationMixin`/`EnergyLevels` live in `algorithms/deflation.py`), returning an `EnergyLevels` (ascending Hartree energies + `excitation_energies`/`in_units("eV")`/stored state vectors; ADAPT re-grows a fresh deflated ansatz per level and records `num_operators`). Reported energies are the bare `⟨H⟩` (penalty vanishes at the eigenstate) — every returned level is a true eigenvalue of H, limited to the sector the ansatz can reach from its HF reference (ADAPT's greedy screening hits Brillouin's zero-gradient wall for singles, so on H₂ it reaches the seniority-zero partner, while UCCSD-VQE also reaches a singly-excited level). `algorithms/subspace.py` adds **`SubspaceVQE`** and **`SubspaceADAPTVQE`** (via `SubspaceMixin` over `VQE`/`ADAPTVQE`) — **subspace-search VQE (SSVQE)**, which computes the ground + first few excited states **simultaneously** in one optimization: `num_states` orthogonal reference determinants (auto-generated as the lowest of the HF particle-number sector, `subspace_determinants`/`reference_matrix`) are sent through one shared unitary `U(θ)` and the weighted energy `Σⱼ wⱼ⟨φⱼ|U†HU|φⱼ⟩` (strictly-decreasing `weights`, default `(k,k-1,…,1)`) is minimized (`SubspaceADAPTVQE` grows one shared ansatz whose pool-screening gradient is the weighted per-reference sum). This needed the ansatz method **`evolve(θ, references)`** (added to `UCCSD` and `AdaptAnsatz`; applies the same unitary to a `(2ⁿ,k)` stack of references). Returns `SubspaceVQEResult`/`SubspaceADAPTVQEResult` (ascending Hartree `energies`, orthonormal `states`, `weights`, `optimal_energy`=ground, `excitation_energies`, `in_units("eV")`, `.levels` → `EnergyLevels`; both are ASE calculators exposing the spectrum on `.result`, ASE energy = ground). Levels are variational **upper bounds** (Hylleraas–Undheim `Eᵢ ≥ λᵢ`); the ground is exact from the default HF start, excited-state tightness tracks ansatz expressivity. **`VQE` is also an ASE calculator**, but the recommended user-facing form is `atoms.calc = Carcara(method="vqe", basis="FAO", optimizer=..., h=...)`; `atoms.get_total_energy()` builds the Hamiltonian + a default UCCSD ansatz from the geometry and runs, returning eV, with the run result on `atoms.calc.result`. The geometry→Hamiltonian building (grid-from-cell + basis integrals) is shared by both drivers in `algorithms/_hamiltonian_from_atoms.py`; the shared `resolve_optimizer` helper lives in `optimizers/optim.py`.
- **Profiling** (`utils/profiling.py`) — `Timings` accumulates named stage wall-times plus the OpenMP core count and peak process RSS (`peak_memory_mb`, via `resource.getrusage`). The C backend reports its thread count through `carcara_num_threads()` → `_backend.num_threads()`. `IntegralEngine` times its one-/two-body stages (`engine.integration_profile()` → `MolecularIntegrals.integration_profile()`); `VQE.run`/`ADAPTVQE.run` time optimization / gradient-screening / etc. and print a "Timings / Resources" block in the verbose summary (also on `result.timings` / `result.integration_profile`).
- `src/carcara/algorithms/adapt_vqe.py` — `ADAPTVQE`, the adaptive grow-then-reoptimize loop (gradient `⟨ψ|[H,A_i]|ψ⟩` over a pool, warm-started inner VQE) on the exact state-vector backend, using the growable `AdaptAnsatz` (`circuits/adapt_ansatz.py`; dense eigendecomposition backend, or a **sparse closed-form** backend for large active spaces) and Qiskit-based circuit profiling (`circuits/profiling.py`: `profile_ansatz` → CNOT count + depth in a native `{cx, u}` gate set). Both drivers subclass `VariationalDriver` (see `base.py`) so setup/materialization/`energy(psi)`/timings are shared. All four pools reach FCI on H₂. See `examples/01_ADAPTVQE_H2.py` … `examples/06_ADAPTVQE_O2_triplet.py`. Operator selection is the single pluggable hook **`_select_operator(grads, iteration)`** (default `argmax|g|`), used by `run()`, the deflation grow (`_grow_deflated`) and the subspace grow — so a subclass changes *which* operator grows the ansatz without touching convergence (`max|g| < tol`, computed independently of selection).
- `src/carcara/algorithms/hartree_fock.py` — `RHF` (closed-shell SCF; supplies the **molecular-orbital basis** so ADAPT's HF reference is stationary and singles have zero gradient) and `UHF` (`run()` → energy, for the isolated-atom references; `solve()` → `UHFResult` with both spin-orbital sets, the **natural orbitals** of `D_α+D_β` (`natural_orbitals`, occupation-ordered) and `h_mo`/`eri_mo` in that basis, plus `reference_energy` of the NO determinant and `spin_contamination`). **Open shells (2026-09-09):** `MolecularIntegrals.molecular_hamiltonian(mo_basis=True, n_electrons, num_particles=(nα,nβ), open_shell=None)` uses RHF for even counts and the **UHF natural-orbital basis** for odd counts (or `open_shell=True`), one spatial basis for both spins so the α/β-block spin-orbital form and everything downstream (pools, ansätze, mappings, frozen core, dry run) are unchanged; the NO reference is not stationary, so ADAPT also selects singles (fine). `resolve_num_unpaired` makes an odd count a doublet by default (`spin` is now only a compatibility flag; magmoms select quartets etc.), `_num_particles` checks parity instead of refusing odd counts, `resolve_frozen_core(..., n_doubly=n_beta)` freezes only doubly occupied NOs; the **PW** basis still refuses odd counts (RHF-only). `VQE` now stores `num_particles`/`n_spatial_orbitals` like ADAPT; `adapt_vqe._max_abs` treats an **empty pool** (H atom: 1 electron, 1 orbital) as converged instead of crashing on `max([])`. Pinned by `test/test_open_shell.py` (H, H₃ doublet/quartet, Li frozen core, H₂⁺, OH dry run; ADAPT/VQE reach the sector FCI computed by `_sector_ground_state`).
- `src/carcara/algorithms/bloch.py` — the **general (1-/2-/3-D) periodic-system driver `BlochCalculator`** — a single class whose variational solver is selected by `method="adapt-vqe"` (default) / `"vqe"`, mirroring `Carcara`. Takes an ASE `Atoms` *primitive cell* (`atoms.cell`/`atoms.pbc` define the lattice and periodic directions). `bands(kpts)`/`band_structure(path)` solve the single-particle **Bloch Hamiltonian** `H(k)c = ε(k)S(k)c` at each k-point — the cell-to-cell overlap/one-body blocks `S^{(R)}`,`h^{(R)}` are built from the FAO real-space integrals over a lattice window, the Bloch phase is the dimension-general `exp(2πi k·n)` over integer translations, and (being single-particle) the bands are **identical across the three methods**. `total_energy(kmesh, **solver_kwargs)` gives the **total energy per cell using all k-points** via the **Born–von Kármán equivalence** (an `(n1,n2,n3)` mesh ≡ Γ-point on the `(n1,n2,n3)` supercell): it builds the supercell with `atoms.repeat`, runs it through a molecular `Carcara(method=self.method, ...)`, and returns `(E(supercell)/n_cells, result)` where `result` is the method's `VQEResult`/`ADAPTVQEResult` (read from `calc.result`; a finite-supercell estimate exact in the infinite-mesh limit; k-points come from ASE `monkhorst_pack`). `band_structure` returns `BandStructure` (x/energies/xticks/labels/kpts). See `examples/07_ADAPTVQE_H_chain_bands.py` and `examples/11_Bloch_crystals.py`.
- `src/carcara/algorithms/expressivity.py` — PQC **expressibility** (Sim *et al.* 2019): random-parameter state fidelities vs the Haar distribution scored by KL divergence (`compute_expressibility`, `calculate_kl_divergence`, `calculate_haar_distribution`). The Haar reference dimension is the *number-conserving sector* `d = C(M,nα)·C(M,nβ)` (`active_space_dimension`) or the empirical span rank (`estimate_effective_dimension`), **not** `2^N` — the fermionic ansätze never leave their symmetry sector. `ADAPTExpressivityTracker` / `track_adapt_expressivity` hook `ADAPTVQE.run(callback=...)` to log expressibility as the ansatz grows.

Recently implemented: `backends/hardware.py` (device registry — `AER_simulator` ideal simulator, IBM Quantum and Amazon Braket devices) and `utils/logging.py` (the ADAPT `output.txt` protocol, `AdaptOutputLogger`/`parse_output`). `ADAPTVQE` (`algorithms/adapt_vqe.py`) is also an **ASE calculator** — driven in user code via `atoms.calc = Carcara(method="adapt-vqe", pool=..., basis="FAO", mapping=..., optimizer=..., gradient=..., device=...)`; `atoms.get_total_energy()` builds the Hamiltonian from the geometry and runs the loop, returning eV (result on `atoms.calc.result`) with selectable `optimizer` (`"SPSA"` / `"COBYLA"` default / `"Nelder-Mead"` / `"SLSQP"` / `"Adam"` / `"L-BFGS-B"`, or an `Optimizer` instance) and `gradient` (`"finite_difference"` / `"parameter-shift"`). The run trace goes to stdout only when no `output=` log is given (`Carcara` has `trace=`, not `verbose=`; the solver classes keep their own `verbose` — see "`[PERFORMANCE]`, and stdout becomes the ASE table" below). `run()` prints of the quantum simulation — the qubit Hamiltonian's **term count only** (its Pauli expansion is no longer dumped), then a **column-aligned iteration table** (one single line per grown operator: `iter | |grad| | E (eV) | dE | expr | cnot | 1q | depth | type | operator` — see "Run output" below; the selected operator's Pauli-string expansion is *not* printed, and neither is the pool: they live on `result.operators` and, with `verbose_operators=True`, in `pool.json`). `run()` takes no required arguments: `max_iterations` / `gradient_tolerance` / `output` all default to the constructor values. The class is `ADAPTVQE` and its result dataclass `ADAPTVQEResult` (no `AdaptVQE`/`AdaptVQEResult` aliases). Both drivers also accept `kpts` (Monkhorst-Pack mesh via ASE; a `(n1,n2,n3)` triple or the ASE dict `{"size":(...),"gamma":True}` — the engine is Γ-point/molecular so a denser mesh is generated + exposed on `.kpoints` but rejected at run with `NotImplementedError`), `spin` (bool, default False — spin-polarized/high-spin reference; open-shell odd-electron builds raise `NotImplementedError`, RHF-only), `initial_state` (default `"hartree-fock"`, the HF-determinant reference; validated), and the **frozen-core approximation** `frozen_core`/`frozen_orbitals` (`frozen_core=True`/`"auto"` freezes the chemical noble-gas core, an int freezes that many lowest MOs, or `frozen_orbitals=[...]` names exact spatial-MO indices; core orbitals are removed from the active space via `core.hamiltonian.freeze_core_integrals` — a constant core energy + effective one-body potential — so the ansatz/pool/qubit-count shrink. Resolved by `core_electrons`/`resolve_frozen_core` in `_hamiltonian_from_atoms.py`; PW rejects it with `NotImplementedError`). The **initial spin state** is read primarily from the ASE geometry's initial magnetic moments (`Atoms(..., magmoms=...)`): their rounded total is the number of unpaired electrons (`resolve_num_unpaired`), so a triplet is `magmoms=[1,1]` → reference `(n_alpha, n_beta)` with `n_alpha-n_beta=2` (the `spin` bool is the fallback when no magmoms are set). ADAPTVQE also takes **`sparse`** (default `"auto"` → sparse pool for `n_qubits ≥ 12`): the sparse path keeps the Hamiltonian + pool generators as scipy-sparse matrices (`PauliSum.to_sparse_matrix`), screens with the exact analytic gradient, and applies `exp(θA)` in `AdaptAnsatz` via the closed form `I + sinθ·A + (1−cosθ)·A²` valid because the excitation generators satisfy `A³=−A` (a `scipy.sparse.linalg.expm_multiply` fallback otherwise) — so only the few *selected* operators are ever densified, making 12+-qubit active spaces (e.g. frozen-core H₂O) tractable. The **ASE-calculator path softens the −Z/r cusp to half a grid step** (`MolecularIntegrals(..., softening=)`) so a nucleus landing on a grid node no longer produces a ~1e12 garbage core integral (needed since FAO now uses the bare Z). `run()` first writes the **start-up banner**, once per process, (`utils/banner.py` — `lines()` renders it and `show()` writes those lines to stdout via `_write`, not `print`) *before* anything is written to `output.txt`; the same `lines()` go once into the top of `output.txt` itself (see "One `output.txt` per relaxation" below). `MolecularIntegrals.hartree_fock_hamiltonian(n_electrons)` reduces the full Hamiltonian to the mean-field (diagonal orbital-energy) HF `Fermion` whose ground state is the HF determinant at the RHF total energy. The calculator-mode grid is centered on the molecule (minimum-image via ASE `find_mic`), so the molecule's placement in the cell is irrelevant. The `basis` argument accepts a name **or** a `{"name": ..., <options>}` dict (`resolve_basis` in `_hamiltonian_from_atoms.py`): `{"name":"FAO"}`, `{"name":"NAO","energy_shift":0.03}`, `{"name":"NAO-AE","tier":1}`, `{"name":"GTO","n_gaussians":3}`, `{"name":"6-31G(d)"}`, or the periodic `{"name":"PW","energy_cutoff":300}` (routes to `PlaneWaveIntegrals`; requires `atoms.cell`).

- **F01 — anisotropic / skewed FFT Coulomb.** `PoissonFFTSolver(shape, spacing=None, self_const=None, workers=-1, step=None)` builds its kernel distances from the **3x3 step matrix**, not `grid.dx`, so per-axis resolution *and* non-orthogonal cells are exact. ## FAO virtual orbitals (2026-09-17)

`basis={"name": "FAO", "virtual_orbitals": k}` (default **0** = the historical minimal basis, byte-identical) appends the `k` lowest **unoccupied** subshells of each atom to the FAO basis, in aufbau order and with the same bare `Z` as the occupied orbitals. `_config.unoccupied_subshells(atomic_number, count)` is the single source: it returns the `_AUFBAU_ORDER` entries the ground-state filling never reached, so H → 2s, Li → 2p, C/O → 3s, Fe → 4p. **A partially filled subshell counts as occupied** (carbon's `2p²` is already a basis shell, so its first virtual level is `3s`), and the helper raises when `count` exceeds the levels left below the end of the filling table (U has only 2). `FAOBasisSet(virtual_orbitals=)` gains `subshells(element)` (occupied in the historical `(n,l)`-sorted order, then the virtuals in aufbau order — appended, never interleaved, so the occupied functions keep their indices) and `function_count(element)`; the constructor refuses negatives, non-integers and `bool`.

**`virtual_orbitals` counts levels, not functions** — one virtual `p` level is 3 functions. Deliberate: half a shell would break the atom's spherical symmetry and make the energy orientation-dependent, and "one orbital per subshell" is already the FAO family's own language. H₂ costs 4 → 8 → 20 → 24 qubits for k = 0/1/2/3. The option reaches every path for free (`resolve_basis` → `BasisSet.build(name, **options)` in `build_basis_hamiltonian`, `dry_run` and `bloch`), including the per-element form `{"O": {"name": "FAO", "virtual_orbitals": 1}, "H": "FAO"}`; the dry-run label becomes `FAO {"virtual_orbitals": 1}`. Electron counts are untouched — only `n_spatial_orbitals` grows.

Validated (H₂, 0.74 Å, 8 Å cell, h = 0.30, ADAPT-VQE/fermionic to basis FCI): **−28.161879 eV (k=0, 4 qubits) → −28.300907 (k=1, 8 q, −0.139) → −28.338413 (k=2, 20 q, −0.177)**, monotone as a strict basis superset requires; the same ordering holds at 12 Å/h=0.30 and 16 Å/h=0.35. **Caveat:** a virtual hydrogenic orbital is diffuse (H 2s has ⟨r⟩ = 6 a₀ ≈ 3.2 Å), so the cell must contain it or the grid clips the tail — the absolute FAO energies move with the box as they always have. Pinned by `test/test_fao_virtual_orbitals.py` (32 tests: the aufbau levels per element, complete-shell/spherical-symmetry, the occupied prefix unchanged, validation, the dict/per-element/dry-run paths, and the variational gain). Guide: `docs/source/guide/basis_sets.md` ("Virtual levels for the FAO basis").

## The compensation charge had no electron-ion attraction (2026-09-17)

**Root cause of the p-valence binding failure.** `MolecularIntegrals._compute_one_body` builds `T + V + C D C†`, where the external potential `V` is the grid integral of `v^ion` against the **smooth pair density** `φ̃*φ̃`. PAW's compensation charge `n̂` is an *extra* density on top of that, so the grid integral cannot see it — while `two_body_augmentation` *did* give it its full Hartree repulsion. The compensation charge therefore repelled every electron and was attracted to no nucleus. It scales with the augmentation charge, which is why it tracked s-vs-p valence: **O carries 0.64 e against Li's 0.009 and H's 0.021**, so LiH/H2 were never visibly wrong while O/C bonds could not form at all. Measured: the augmentation term is **+102 eV for OH** (vs +0.55 eV for LiH) and grows by **+8.7 eV** between 4.0 and 0.97 Å — exactly the binding deficit.

**The fix.** A new hook `MolecularIntegrals.one_body_augmentation()` (returns `None` by default, so every non-PAW basis is untouched), added to `one` in `_compute_one_body` and to the force's energy rebuild in `pseudo_forces`. `PAWIntegrals.one_body_augmentation` returns `Σ_{A,LM} Q^{A,LM}_pr · V^{A,LM}` with `V^{A,LM} = ∫ ĝ_{A,LM} Σ_{B≠A} v^ion_B` from `compensation_ionic_at(centres)` — an **atom-centred spherical quadrature**, not the grid (the shape spans ~4 grid points at h = 0.20 Å; a grid sum would be inaccurate and would inject an egg-box into the force). The on-site term `B = A` is excluded: it is already inside the dataset, which is calibrated to the reference atom. Taking `centres` as an argument is what lets the force difference it (`pseudo_forces._ionic_shift`). The quadrature is **converged to 1e-9** at the default order (checked to 384x64x128).

## The compensation potentials are not Hermitian (2026-09-17)

**Root cause of the p-valence *force* error** (the binding failure was a different bug, fixed earlier the same day). Reported by the user as: an H2O relaxation in PAW-SZ whose forces did not sum to zero and which displaced the molecule.

`PAWIntegrals.compensation_potentials()` returns `W^{A,LM}_qs = ∫ φ̃*_q φ̃_s v_L(r_A) Y_LM(r̂_A)`. **The weight is complex whenever M ≠ 0**, so `W` is Hermitian only for the M = 0 channels — measured on water: `|W − W^H|` is 1e-16 for every `(A,0,0)` and `(A,L,0)` channel and *as large as `|W|` itself* (0.74 against 0.74) for every M ≠ 0 one. The Pulay branch of `pseudo_forces` nevertheless wrote the product rule as

```python
cross_w = ((dpsi.conj() * v_comp[channel]) @ psi.T) * dV
dW[channel] = cross_w + cross_w.conj().T        # WRONG for complex v
```

and `cross^H` puts **`conj(v)`** in the second half instead of `v`. Both halves are now written out explicitly. One line; nothing else in the force path was wrong.

**Why it hid for two days.** The compensation channels come from the *pseudopotential's* angular channels, so an s-valence atom has only `(A,0,0)` with a real weight: **H and Li never exercise the bug**. That is exactly the validation table — H2 4.4e-5, LiH 1.6e-4 (both clean) against OH 4.2e-2 — and why all 76 `test_paw*.py` tests passed before and after the fix. It also explains the *shape* of the error: on C2v water with the bonds along y and z, z is carried by the real `M = 0` harmonic and y by the complex `M = ±1` pair, so the analytic oxygen force came out **2.2496 along y against 2.7841 along z** for a geometry whose y↔z symmetry is exact.

**How it was found** (the audit the previous entry asked for, worth repeating for the next one): monkeypatch `AlgebraicEnergy.directional` to capture every `(dS, dh, dg)` it contracts, rebuild the integrals at displaced geometries **on the same frozen grid**, and compare each matrix derivative with its own central difference. Result: `dS` 2e-6, `dh` 6e-6, **`dg` 1.4e-1** — the two-body augmentation, and only for oxygen. Then `dU` was cleared at 1e-5 against a finite difference of `compensation_coulomb()`, and `dQ`/`dC` were cleared by `dS`/`dh` already being exact, leaving `dW`. **Watch the units in that audit: the analytic derivatives are per Bohr and an ASE displacement is in Ångström, a factor 0.5292 that looks exactly like a physics bug.**

**Results** (user's `water_unrelax.xyz`, PAW-SZ, h = 0.20): analytic vs finite difference of the calculator's own energy **0.575 → 0.0032 eV/Å**, `dg` 1.4e-1 → 9e-6, and the C2v symmetry is restored (O: 2.82747 vs 2.82755 along y and z; H1_y = 0.43219 vs H2_z = 0.43211). **The reported net force got *larger*, 0.869 → 1.158 eV/Å, and that is correct**: the rigid-translation finite difference gives dE/dt = −0.8162 eV/Å per axis against the fixed −0.8188, so the gradient now agrees with its energy and the old cancellation was accidental.

**What remains is a real egg-box, and it converges.** Net force / largest force for that water: **1.85 / 0.86 / 0.41 / 0.099 / 0.025 at h = 0.30 / 0.25 / 0.20 / 0.16 / 0.13** (27–49 s per geometry, 12 qubits). Oxygen needs **h ≤ 0.16 for geometry**, finer than the h ≤ 0.25 that suffices for energies.

**`Carcara(project_translation=True)`** (new, default `False`, `calculator.py`) subtracts the mean force so the forces sum to zero. A free molecule's exact forces *do* sum to zero, so this enforces a symmetry rather than hiding an error — but it removes only the *translational* component of the egg-box, so it stops a relaxation drifting across the grid without making a coarse grid trustworthy. Refused for periodic systems; the unprojected residual stays on `details["translational_residual"]`, with `details["translation_projected"]` / `["translation_removed"]` recording what was done.

**H2O in PAW-SZ now binds** — the "H2O has no bound minimum, BFGS is walking correctly down a wrong surface" note in the forces section was the **all-electron FAO** path and predates the compensation-attraction fix. Symmetric O–H scan at h = 0.16, angle 104.5°: −480.799 / −481.924 / −482.201 / **−482.291** / −482.205 / −481.634 / −480.335 / −477.730 / −475.204 / −474.657 eV at 0.85 / 0.92 / 0.96 / **1.00** / 1.05 / 1.15 / 1.30 / 1.60 / 2.20 / 3.20 Å — monotonic out to dissociation, so **7.63 eV for the two bonds (3.8 eV each against 4.8 eV experimental)**, with the bond force crossing zero at 1.00 Å (+0.177 → −1.655). **Relaxation from the user's 90°, 1.0 Å geometry: 3 BFGS steps, 123 s, h = 0.16, `project_translation=True` → d = 0.9921 Å, angle 117.29°, fmax 0.036 eV/Å, COM drift 0.106 Å.** Experiment is 0.9572 Å / 104.52°: the bond length is good (+3.6 %) and the 13° on the angle is the minimal valence s+p shell, not the gradient (PAW-DZ on water would be 24 qubits / sector dim 245,025 — the SZP-class cost documented above).

## One `output.txt` per relaxation, with the forces in it (2026-09-18)

**`Carcara.calculate` builds a fresh solver for every geometry**, so a relaxation created one `AdaptOutputLogger` per BFGS step and each opened the path with mode `"w"`: the file that came out of a twelve-step run held **one** step's iterations (the last), and the forces — the thing a relaxation is actually judged on — were never in it at all. Three changes, all in `utils/logging.py` plus one call site:

- **The banner is the file's, not the block's.** `utils/banner.lines()` is now the single source of the banner text (`show()` writes exactly those lines to stdout, verified byte-identical), and `AdaptOutputLogger` writes them into a **freshly opened** log — the test is `self._fh.tell() == 0`, so appending never repeats it and an explicit `append=True` to a not-yet-existing file still gets it. `banner=False` opts out. The stdout banner is unchanged (still once per process via `base._BANNER_SHOWN`).
- **Later steps append.** `_LOG_STEPS` maps each log's **absolute path** to the number of blocks written to it in this process: the first logger truncates, every later one appends (`append=True|False` overrides). `logger.step` is the 1-based block index; `write_metadata` writes it as a `step:` line and titles blocks after the first `ADAPT-VQE (CEOPool, 12 qubits) -- geometry step 2`. `log_steps(path)` reads the counter and `reset_log(path=None)` forgets it — a fresh process starts empty, so only a long-lived one (a notebook cell re-run) needs it. **Consequence to expect:** a *scan* that reuses one `output=` path across several `Carcara` objects in one process now concatenates instead of overwriting. That is deliberate and the same reasoning as the relaxation; give each geometry its own path if you want separate files.
- **Forces are logged.** `append_forces(path, symbols, forces, hellmann_feynman=, pulay=, units=, extra=, step=)` (with `_force_block_lines` / `_force_table`) appends a `[FORCES]` block: three per-atom tables — `forces` is what ASE consumes (−dE/dR), `hellmann_feynman` and `pulay` are the gradient components (+dE/dR), as `ForceResult` defines them, and the block says so in a `convention:` line — then `max_force` / `rms_force` / `net_force`. `Carcara._log_forces` calls it after `_forces` (the solver's own logger is closed by then, which is why this is a module function and not a logger method), adding `force_method`, `include_pulay`, `pulay_fraction`, `n_electrons` and the two residuals that say whether the gradient is usable at all: `orbital_gradient` and `translational_residual` (plus `translation_projected` when the mean force was removed). It is skipped when the solver has no `output` (only `ADAPTVQE` has one; `VQE` writes no log).

- **The blocks are indented 4 spaces** (user directive, same day; `utils.logging.INDENT = "    "`, `_indent(lines, level)`, `AdaptOutputLogger._emit_body(..., level=1)`). Section markers (`[METADATA]`, `[ITERATIONS]`, ...), the `====` rules and the banner stay at column 0; a block's keyed lines take one level and what a keyed line *contains* — the atoms under `geometry:`, the lattice vectors under `cell_vectors:`, the iteration table's heading/rule/rows, each force table — one more (the force tables' own 2-space prefix is gone; `_force_table` returns plain rows and the caller indents). The title line went from one space to four. Blank separators stay truly empty (no trailing whitespace), and a block appended under an earlier one is preceded by a blank line instead of stacking its `====` against the previous block's. **Indentation is invisible to the reader code** — `parse_output` strips every line, which is why the format change needed no parser change and old logs still read back.

- **No `operator_sequence` in `[SUMMARY]`, and the circuit columns run `1q` / `cnot` / `depth`** (user directives, same day). The sequence line is gone from `write_summary` (parameter included) and from `ADAPTVQE.run`'s call: the `[ITERATIONS]` table already names the operator every step selected, *in order*, and `result.operators` is the same list as data — on a wide register that one line was longer than the table it duplicated (H₂O/`ceo`: 30 operators on one line). Pinned by `test_summary_reports_final_parameterization`, which now asserts the key is absent *and* that the table's `operator` column reproduces `result.operators`. The log's `ITERATION_COLUMNS` reordered from `cnot, depth, 1q` to **`1q, cnot, depth`** (cheapest gate first, then the depth they compile to). Note the stdout trace keeps its own order (`cnot, 1q, depth`, `_ITERATION_COLUMNS` in `adapt_vqe.py`) — the two tables were already ordered differently before this, and only the log's order was asked about.

`parse_output` is **step-aware**: `result["steps"]` is the list of blocks in order and the top-level `metadata` / `setup` / `iterations` / `summary` / `forces` keys describe the **last** step, so reading a single-point log is unchanged. `[FORCES]` parses into `symbols` + the three `(N,3)` lists + its scalars, and a file need not open with `[METADATA]` (a forces block alone is still a step; `_SECTIONS` drives the dispatch).

Validated on `~/Simulations/carcara/local/water/run_carcara.py` (water, PAW-SZ, 12 qubits, `ceo`, h = 0.10, `fmax` 0.02, from 90° / 1.00 Å) and on an H₂/FAO BFGS run: one banner, one `[METADATA]`+`[ITERATIONS]`+`[SUMMARY]`+`[FORCES]` block per geometry, and the block's `max_force` equal to the `fmax` ASE printed for that step (H₂ 7.4468 → 0.6853 → 0.4107). **That water run is also the first h = 0.10 relaxation:** 6 BFGS steps, E −477.4590 → −477.6169 → −477.7904 → −477.7978 → −477.7983 → **−477.7982 eV** with fmax 2.550 → 1.552 → 0.535 → 0.175 → 0.0277 → **0.0131**, ending at **d = 1.0132 Å, angle 110.14°** (COM drift 0.0705 Å, no `project_translation`). The h = 0.16 run recorded above ended at 0.9921 Å / 117.29° **with** `project_translation=True`, so the two differ in *both* h and the projection and are not a clean h series — take them as two independent data points against experiment (0.9572 Å / 104.52°), both with the bond ~4–6 % long and the angle 6–13° wide (the minimal valence s+p shell). What is clean, and visible in the log the moment the forces are in it: **the final step's `fmax` *is* the egg-box.** At step 6 all three atoms' forces point the same way (O −0.0092/−0.0093, H −0.0067/−0.0063, H −0.0063/−0.0066 eV/Å) and `net_force` is 0.0222 against `max_force` 0.0131 — `net_force` sat at 0.016–0.022 through the whole run, so an `fmax` of 0.02 at h = 0.10 is a translation, not a deformation. Use `project_translation=True` for this kind of run (it removes exactly that component) or stop at `fmax` 0.03–0.05. Pinned by `test/test_noncubic_and_output.py`: `TestLogAppendsAcrossSteps` (one banner, numbered blocks, nothing erased, `reset_log`, the `append=` override), `TestForcesBlock` (round trip of the vectors and the breakdown, the norms, the block landing under its own step, an optional breakdown) `TestRelaxationLog` (a real two-step relaxation: one block per force evaluation, the logged force *is* `atoms.get_forces()`, the energies go downhill) and `TestBlockIndentation` (markers at column 0, keys at 4, nested rows at 8, the iteration rule still the heading's width, no trailing whitespace).

## `[PERFORMANCE]`, and stdout becomes the ASE table (2026-09-18)

Two user directives, the second of which reverses the "the run trace is always printed" decision above.

**1. The `[PERFORMANCE]` block** (`utils.logging.append_performance` / `_performance_block_lines`): one per evaluation, closing the step *after* `[FORCES]`. It lists every timed stage with a rule and the sum, then `untimed_s` (`wall_time_s` − the stages: Hamiltonian construction, the mapping, materialization — work no stage wraps), `wall_time_s`, and the machine: `integration_backend`, `openmp_threads` (what the C kernels used) against `cpu_count` (what the machine has), `mpi: not used (single process, shared-memory OpenMP)` — stated because the word invites the assumption — `peak_memory_MiB` (the process high-water mark, so monotonic across a relaxation) and `resident_memory_MiB` (current RSS, so the two together show a stage that allocated and released; needs psutil, else `n/a`). `Timings.resources()` builds that table, with `profiling.cpu_count()` / `current_memory_mb()` as the new helpers.

**`Carcara` writes the block, not the solver**, and that is the whole point of its position: on a real relaxation **the nuclear gradient is the largest single stage** — water/PAW-SZ at h = 0.10 spends **62 % of its 325 s on forces against 19 % on the variational optimization** (32–38 s vs 17–26 s per step, from the block itself on an otherwise idle machine; an earlier reading of 70–110 s vs 33–55 s came from a run competing with the test suite and is *not* the clean figure), so a block closed when `run()` returned would account for the smaller part of the step. `Carcara.calculate` times the gradient (`"nuclear gradient (forces)"`) and any provider measurement (`"measurement (provider)"`), merges them into a `Timings` seeded from `result.timings`, and appends the block; `VariationalDriver.defer_performance` (set by `Carcara`) tells the solver to skip its own, so a **direct** `ADAPTVQE(...).run()` still writes one (its stages only). `VariationalDriver.write_performance` / `qpu_accounting` are the hooks.

**QPU accounting** (`backends.providers.qpu_usage(provider, wall_time_s)`): `qpu_device`/`qpu_shots`/`qpu_wall_time_s` always, plus `qpu_jobs`/`qpu_job_ids`/`qpu_seconds`/`qpu_billed_seconds` from `job.metrics()["usage"]` when the provider reports them (Qiskit Runtime, real device only). `qpu_seconds` is the metered time that counts against the open plan's 10 min/month. Every read is defensive — a job object that raises (service unreachable) still leaves a usable block, pinned by `test_a_job_that_cannot_answer_does_not_break_the_log`. Nothing is invented: a local simulator contributes the wall clock and the device name, and a run with `shots = 0` emits **no** `qpu_*` keys at all.

**2. stdout is now ASE's table.** Measured first, as asked: the water relaxation printed **552 lines for 6 steps** — per step a 35-line configuration header, a 33-line iteration table and a 13-line timings block — of which the **7 lines** of ASE's `Step Time Energy fmax` table were what the user wanted to watch (1.3 % signal), and all 552 duplicated, in a second format, what `output.txt` now holds structurally. So `output=` decides the split, exactly as GPAW's `txt=` does: **with a log file the solver's trace is off and stdout carries only ASE's evolution of energies and forces; without one the trace is printed** (it is then the only report there is). `Carcara(trace=True|False|None)` overrides — `None` is the automatic choice above — and `verbose=` is still refused, now with a message pointing at `trace=`. `Carcara._show_trace()` passes `verbose=` to the solver it builds.

**ASE does not flush `Optimizer.log`** (verified in `ase.optimize.optimize`), and its line is ~60 bytes: a redirected `python run.py > run.log` would have shown *nothing* for minutes and a running relaxation would have looked hung — the same trap the old `verbose` TypeError guarded against. `calculator._watchable_stdout()` therefore reconfigures a **non-tty** stdout to line-buffered, once per process and defensively (a replaced `sys.stdout` may not support it), and `calculate` flushes at the end as a fallback. A tty is line-buffered already, so this changes only the redirected case.

Pinned by `test/test_noncubic_and_output.py`: `TestPerformanceBlock` (one block per step, after the forces; the gradient among the stages; `total_s`/`untimed_s` adding up; the resources; **no** `qpu_*` without a processor; a direct run writing its own), `TestQPUAccounting` (the metered seconds, a local provider, no provider, a hostile job) and `TestStandardOutputIsTheASETable` (a log file silences the trace, no log file prints it, `trace=` overrides, `trace="yes"` and `verbose=` refused, and the log still has everything). Guide: `docs/source/guide/run_output.md` opens with a "What goes where" table.
